# WB 中国跨境 FBS 计价资料

本目录用于独立的 WB 利润计算器、定价工具及订单明细中的情景预估，不参与 Ozon 或历史订单利润重算。

## 官方物流来源

- 原表：https://static-basket-02.wbbasket.ru/vol20/China/warehouse_and_tarrifs/1026.pdf
- 生效日：2026-11-11；核对日：2026-11-12。
- 完整原件：`public/reference/wb-logistics-2026-11-11.pdf`。
- 结构化数据：`logistics-2026-11-11.json`，记录原件 SHA-256，包含全部 73 个唯一仓库编号。
- 提取中文表，并逐项交叉核对英文表中的 73 个仓库编号与四个费用字段。物流产品使用官方英文名称 WB Standard / WB Express，保留中文名称、WB Plus 标记、运输方式、承运货物、时效和仓库位置。
- 一个仓库编号是一条报价入口，不等于一家独立承运商。新版原表没有为所有仓库列出独立承运商名称，不推测承运商。默认合肥 382855 按用户确认显示 DPX，费率和限制仍以此仓编号的最新行计算。

计费重 = ceil(包裹实际克重 / 100) × 100。运费 = 计费公斤 × 当前档公斤费 + 每票费。此官方中国跨境表按实重计费，不套用 Ozon 体积重或计抛公式。计费重不超过 300g 时使用轻小件档，从 400g 使用另一档。尺寸限制逐仓匹配；多数仓限重 25kg，357322 单独限重 20kg。带电商品容量限制为 100Wh，具体是否承运还需依原表渠道名称、禁运目录及仓库要求核对。

常见费率：

| 入口 | ≤300g：元/kg + 元/票 | ≥400g：元/kg + 元/票 |
| --- | --- | --- |
| WB Standard（包括合肥 382855） | 58 + 2 | 43 + 8 |
| WB Plus 珲春 50072222、东莞 50131977 等 | 48 + 9 | 48 + 9 |
| 香港 325994 等 | 89 + 17 | 89 + 17 |
| 东莞 357322 | 122 + 19 | 122 + 19 |
| WB Plus 成都 50239292 | 48 + 30 | 48 + 30 |

不能把上表汇总值覆盖到所有仓；完整 73 行才是计算来源。后续更新应下载新官方原件、核对生效日及全表，新增版本并更新引用，保留旧原件。此任务不建立未经用户要求的定时同步任务。

中文轻小件栏另印有“限重1.9公斤”，与该栏 0.1–0.3kg 范围不一致；英文对应标题无此句。没有据此覆盖正文明确的总限重，保留原件供核对。

## 官方佣金来源

https://dev.wildberries.cn/docs/openapi/rates

通过当前企业内已核对身份的正式 WB 店铺，调用 `GET https://common-api.wildberries.cn/api/v1/tariffs/commission?locale=zh`，仅使用 `kgvpChina`，不使用俄罗斯本土或其他销售模式字段。结果按企业、店铺和授权摘要隔离，合并并发读取并缓存 12 分钟以遵守接口限频；读取前仍验证店铺所有权和有效授权。不返回 Token。缺少官方中国费率时不填入 Ozon 费率，提示按卖家后台手动填写。

## 公共费用约定

按本次用户要求，广告、退货率、每次退货损失、其他费、国内运费及贴单、尾程和提现沿用现有工具逻辑。尾程 2.5% 和既有提现公式是用户指定的共同测算约定，不代表本次核实了 WB 合同中另收这些费用。WB 中国卖家售价以人民币输入和输出，卢布仅供汇率参考。


## 平台隔离与版本登记（2026-11-12）

- WB 版本注册表为 `src/shared/wb-logistics-catalog.js`。保留 2026-09-01（42 仓）及 2026-11-11（73 仓）两份官方原件和对应哈希；生效时点采用北京时间，历史版本可显式选择用于复核。新版本只追加，旧数据不覆盖。
- WB 报价必须携带 `platform=wb`、版本号及 `wb:<版本>:<仓库编号>`，否则计算器拒绝。结果保存当次版本、仓库、原件哈希、计费重量及费率快照。
- Ozon 继续使用数据库中原有的版本组、生效期和规则 ID。工具报价增加 `ozon:<版本组>:<规则ID>` 标识并在结果保留快照，不修改历史订单利润公式或订单保存的版本。
- 物流设置明确分开两平台目录。WB 官方版本为只读资料：发布新版本需核对原件、生效日、全部行及哈希后随发布流程登记；不能用 Ozon 的新增／编辑规则入口录入 WB 报价。Ozon 写接口拒绝显式 WB 平台、WB 仓库字段及 DPX/WB 服务商。

## WB 订单明细预估（2026-11-28）

订单明细使用独立模型 `wb-order-estimate-v2`。参数预览不写订单；点击“重算并保存利润”或订单列表的重算入口后，由服务端保存正式预估及计算记录，不改写真实账单、库存成本或 Ozon 公式。报价仍按订单日期匹配上面的官方物流版本；模型版本与物流报价版本分开记录。原始账单结算继续使用既有独立结算逻辑。

- 揽收仓通过个人偏好接口保存：偏好 key 必须包含当前企业编号，不与 WB 卖家库存仓绑定混用。首次使用显式配置，默认推荐合肥 DPX 仓 `382855`；保存后自动用于同一用户在该企业的后续 WB 订单。跨境运费由选择的仓库、实重、长宽高自动校验及报价，不根据尺寸猜测所在地。
- 采购成本、国内运费及贴单来自本地绑定库存，包裹资料优先取已同步的 WB 商品卡，不足时逐项回退库存资料。千克转换为克；多件订单不能用单件包裹尺寸假算整单运费，需补充整包数据。国内运费和贴单独立校验，缺失保持未知，不依赖采购成本是否填写。
- 委托派送费沿用工具的售价 × 2.5%；提现费沿用既有工具约定 `max(0, 售价 - 跨境运费 - 委托派送费 - 售价 × 20%) × 1.2%`。其中固定 20% 为既有测算基数约定，不替代当前填写的类目佣金率，也不代表核实了 WB 合同费率。
- 支付手续费按明确配置的费率 × 售价单独预估，费率按店铺保存在当前企业的个人偏好中。未配置时不猜测费率，标注“暂未计入”，利润为待补充的预估。明确配置 0 与未知不同。中国区官方财务 API 有 `acquiringFee` 和 `acquiringPercent`，但文档样例不是通用费率，不能把样例数值当作默认值：[WB 官方财务接口](https://dev.wildberries.cn/docs/openapi/documents-and-accounting)。真实账单净额已包含平台佣金和支付费，不再次扣减。
- 自动单次退货损失 = 采购货值 + 国内运费及贴单 + 跨境运费 + 平台佣金 + 委托派送费。预估退货损失 = 单次退货损失 × 退货率。允许手工覆盖单次损失（包括明确填 0），清除覆盖后恢复自动计算；默认退货率为 0，不把单次损失默认锁成 0。
- 广告、其他费用按填写费率计算，默认 0。罚款、仓储、入仓及其他账单调整暂不猜测，保留真实账单明细供核对。必需成本、佣金、日期报价或包裹资料不完整时明确列出缺失项，不把未知金额伪装为 0。

## WB 订单重算与持久化

- 列表提供逐单“重算利润”，顶部提供“重算本页利润”／“重算已选利润”；有勾选时只处理勾选记录，无勾选时只处理当前页 WB 记录。混选其他平台时拒绝，单次最多 100 单，不隐式计算其他页或所有企业订单。明细的“重算并保存利润”使用本次明确确认的参数。
- `POST /api/wb/orders/recalculate-profit` 需要 `orders.manage`，请求为 `{order_ids, overrides?, command_id?}`。企业和操作成员来自重新校验的会话，服务端先检查整组订单的企业、平台和有效店铺，再逐单在事务中保存。既有单单重算接口按平台分发，WB 不进入 Ozon 公式、财务、库存或出库流程。
- 前后端复用 `src/shared/wb-order-profit.js`，算法未更改。销售额、店铺、订单日期和数量始终取服务端原始资料；请求只允许采购、包裹、费用费率及揽收仓参数，不能提交最终利润或覆盖销售额。
- 自动重算读取最新商品资料、当前用户在该企业的仓库／本店支付配置及官方类目佣金。明确保存的手工参数单独记为 `manual_overrides`，优先于自动资料；上次完整计算输入只是审计快照，不能把旧的自动成本永久当作手工参数。旧手工空值回退当前资料，明确填写 0 保留为 0。明细重开按手工参数和当前商品资料恢复。
- `wb-order-estimate-v2` 单独登记为仅支持预估的公式。使用既有 `order_profit_calc_state` 和 `order_profit_calc_revisions`：已确认属于 WB、且没有其他公式正式结果的旧 V1 基线，在保留旧金额、真实利润和锁定信息后显式切换至 WB 版本；已有其他固定版本或正式计算记录时停止并提示核对。不会重写旧修订。
- 每笔计算先锁订单商品，再读取最新手工参数和配置；修订、当前指针及有效的 `order_items.estimated_profit` 投影在同一事务提交。重复命令不会把旧结果重新投影到较新修订上。正式账单金额、真实利润、出库成本及其锁定状态不参与此次预估写入。
- 不完整的计算也明确记录缺失项，修订输出中的利润为 `null`，不把它写成数字 0。列表通过当前 WB 修订读取结果，覆盖旧数字投影，区分“未重算”“待补齐参数”和真实的 0 利润。支付费率未知但其他必需参数齐全时允许保存带提示的暂估。
- 明细返回 `saved_profit`（输入、输出、手工参数、修订编号及计算时间），列表返回 `wb_profit` 的精简摘要。保存后同时失效服务端订单缓存并强制刷新前端列表；查看、刷新和同步账单不会静默触发利润重算。计算时间按北京时间显示。

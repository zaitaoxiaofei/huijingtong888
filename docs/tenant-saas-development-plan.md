# 多租户订阅与套餐开发计划

## 业务目标

系统由软件服务方提供给个人或团队使用。每个个人/团队对应一个独立工作空间；同一空间中的负责人和员工协作使用该空间的数据。团队之间不能读取或修改对方的企业/店铺、采集、商品、库存、采购、人员、订单、分析、AI 任务及素材、财务和任务数据。

前期用户规模较小，采用同一 MySQL 数据库、共享业务表并以 `tenant_id` 标记空间归属。隔离必须在服务端按当前会话的工作空间限定查询和写入，不信任请求参数中的租户 ID；SQL 使用绑定参数。后续可按性能和运维需要给个别高增长表拆分或独立存储。店铺级员工可见范围属于后续增强，不替代当前团队级隔离。

平台超级管理员负责创建和管理工作空间、套餐、授权和激活码，以及平台共用规则、自动任务、监控、AI 提供商和提示词库。普通企业负责人只能管理自身空间，不拥有平台管理权限。

## 平台与企业身份边界（2026-10-21 补充）

- `people` 保存全局登录身份及历史业务引用；平台超级管理员必须具有 `platform_grants` 中明确启用的 `super_admin` 授权。旧 `admin` / `technical` 岗位、姓名及开发账号名称均不产生平台权限。
- 企业角色保存在 `tenant_members.role`，业务岗位保存在该关系的 `business_roles_json`。同一人可以具有平台身份、企业身份或经过明确分配的双身份；平台专用账号无需默认企业成员关系。
- 服务启动不新增任何企业成员或平台授权，包括平台超级管理员。历史会话仅可通过该人员已有的有效成员关系补绑定；缺少企业关系时，企业业务请求拒绝访问。
- 企业店铺、企业人员和店铺矩阵配置归入企业管理。矩阵的固定风格、生成方案和公共字典共用，店铺规则、企业通用尾图及店铺模板按当前会话企业隔离。
- 汇率、利润规则、物流与取消规则、自动任务、监控、AI 配置和提示词管理归入平台管理。业务功能消费共用规则的权限与修改平台规则的权限分别控制。
- 本地代码已接入身份和菜单拆分、企业人员管理及矩阵配置切片。实际账号与成员清理须执行[明确清单迁移](platform-enterprise-identity-migration.md)，当前进度不代表实际数据库已迁移或生产版本已发布。

## 套餐口径

- 套餐期限以天配置。1 个月按 30 天、1 个季度按 90 天、1 年按 365 天计算。
- 套餐账号总数包含 1 个主负责人账号；套餐额度中的“子账号上限”是总账号数减去一个主账号。
- 主账号以外的成员账号（包括企业管理员角色）均占子账号名额。套餐店铺额度单独计算。
- 账号或店铺额度留空表示不限；调低已生效企业额度时，不自动删除既有账号或店铺，但会阻止继续新增。
- 停用套餐只阻止后续开通/重新授权，保留历史企业对套餐的引用。编辑套餐不静默修改现有企业额度；对已有企业的变更应通过明确的重新授权或管理员手动调整完成。
- 不在本阶段推断或收取价格；支付、订单、自动续费须单独确认业务口径后开发。

## Scrum 切片与验收

### 切片 1：套餐目录与企业按套餐开通（已完成，待用户验收）

- 保存预置套餐和自定义套餐；平台管理员可以新增、编辑、启用、停用。
- 创建企业时选择套餐；系统按套餐写入期限、总账号数和店铺额度。
- 对已有企业重新授权时同步套餐期限和额度，并在操作前明确提示。
- 回归账号/店铺额度服务端校验、平台管理员权限与旧企业数据兼容。
- 验收：逐个检查 6 个预置套餐；新建体验版和团队版测试企业；验证 1 账号套餐不能新增子账号、3 账号套餐最多增加 2 个非负责人账号、店铺数分别受套餐限制；编辑套餐后确认旧企业未被静默改额，重新授权后才更新。

### 切片 2A：后台发码、查看与作废（已完成，待用户验收）

- 创建企业/套餐时在同一数据库事务中生成高随机性激活码，只保存 SHA-256 哈希和尾号提示；明文只在创建/重发响应中展示一次。
- 平台管理员可查看尾号与状态、复制创建/重发时的明文码、作废或重发；重发会在事务中先作废旧码再创建新码。码的有效期与创建时套餐期限一致。
- 浏览器插件令牌与客户激活码使用独立表、接口和 UI，不能互相替代。
- 当前仅完成后台发码管理；注册认领端点尚未开放，现有激活码暂不能用于客户自助登录。
- 已验证：代码层结构检查确认明文不落库、接口不查询完整码、普通空间管理员不能调用平台发码接口；数据库实测、认领、过期/重复码并发测试待切片 2B/3。

### 切片 2B：激活码认领与空间绑定（待开发）

- 激活码绑定目标空间、有效期与一次性认领状态；认领时使用事务锁定激活码，保证并发下至多一个请求成功。
- 验收：有效码认领成功；错误、过期、作废和已使用的码失败；并发提交只能有一个成功；日志和接口不泄露密码或完整激活码。

### 切片 3：邮箱注册与绑定

- 新用户提交邮箱、验证码、姓名和密码，完成邮箱验证后使用激活码加入对应空间并创建主账号。
- 邮箱唯一性、验证码有效期、失败次数限制、密码哈希和注册限流均在服务端校验。
- 验收：新邮箱注册、验证、绑定及登录闭环；验证码过期/错误、邮箱重复、弱/空密码、激活码无效均被拒绝。

### 切片 4：管理员续费与额度调整

- 管理员可以查看套餐、剩余时间、激活码状态和账号/店铺用量；按需要手动延长时长、调整账号与店铺上限。
- 记录操作者、变更前后值、原因和时间；不因调整额度自动删除既有数据。
- 验收：分别调整期限、账号、店铺额度；确认剩余时间、并发名额校验和变更记录一致。

### 切片 5：租户隔离回归与页面逐步接入

- 身份基础：明确平台授权与企业角色/岗位，启动不自动入组。企业人员创建及成员修改仅影响当前企业；保留最后一位启用负责人及账号额度校验。迁移使用逐个审查的人员 ID 与完整目标企业关系清单。
- 配置接入：企业店铺、人员、矩阵配置已形成独立本地切片。矩阵仅放行配置读取、规则保存、尾图上传与受控读取，生成、后台任务、导入和发布继续保留隔离闸门。
- 按业务模块盘点仍使用默认空间或全局数据的接口，逐模块改为服务端租户范围查询。
- 先覆盖核心写入/列表，再覆盖导出、统计、AI、后台任务和缓存；保留平台管理员明确授权的跨租户管理入口。
- 每个模块均使用 A/B 两个测试空间验证列表、详情、修改、删除、导出和后台任务互不可见。

### 切片 6：店铺级权限（后续）

- 在空间隔离已稳定后，才为成员增加可访问店铺范围，并逐个接入订单、库存、采购和分析等数据域。
- 验收：受限员工无法通过 URL、过滤器、导出或直接 API 访问未授权店铺；管理员权限行为与页面可见性一致。

# 草稿箱同类目批量编辑规范

## 目标

草稿箱选中的多个同类目草稿复用“商品上架”页面的多变体表格进行编辑。编辑器中的一行对应一个原草稿，保存后仍分别覆盖原草稿，不创建合并草稿。

## 入口与加载

草稿箱通过 `draftIds` 路由参数传递选中的草稿 ID。商品上架页必须逐个读取草稿详情，并按以下规则聚合：

1. 使用 `description_category_id + type_id` 作为类目一致性键。
2. 类目键缺失或存在多个类目键时拒绝进入批量编辑。
3. 一个草稿只映射为一行，行内保存不可编辑的草稿 ID、模板 ID 和加载时版本。
4. 行图片使用后端返回的 `effective_images`；该字段是 URL 字符串数组，前端图片标准化必须同时兼容字符串和媒体对象。不存在时才按草稿模板的可编辑图片链路降级。
5. 批量模式不允许新增、复制或删除行，避免草稿和行失去一一对应关系。

## 保存契约

前端调用 `POST /api/listing/drafts/batch-update`：

```json
{
  "items": [
    {
      "id": 2004,
      "updated_at": "2026-07-31T00:00:00.000Z",
      "template_id": 15817,
      "product_name": "商品标题",
      "source_images": ["https://example.com/1.jpg"],
      "template_payload": {
        "editable_payload": {
          "description_category_id": 123,
          "type_id": 456,
          "variants": []
        }
      }
    }
  ]
}
```

后端必须：

- 拒绝无效或重复草稿 ID，单次最多 100 条。
- 对每条草稿执行访问权限、模板、媒体和必填字段校验。
- 再次校验所有草稿属于同一 `description_category_id + type_id`。
- 使用 `updated_at` 做并发冲突检查；有草稿已被其他用户修改时返回 409。
- 在一个 MySQL 事务中更新全部草稿；任意一条失败时整体回滚。
- 每个草稿的 `template_payload.editable_payload.variants` 只保存该草稿对应的一行。

## 图片权威规则

批量编辑不得把第一行图片、模板默认图片或采集箱历史图片复制到其他行。每行图片独立保存，并标记为当前草稿的手工图片选择。图片解析的总体优先级继续遵守 `LISTING_DRAFT_MEDIA_SOURCE_RULES.md`。

## 回归检查

- 混选不同类目会被阻止。
- 选中 N 个草稿会显示 N 行，保存后仍是原 N 个草稿 ID。
- 修改其中一行标题、价格或图片，只改变该草稿。
- 任一草稿产生并发冲突时，其他草稿也不落库。
- 普通单草稿编辑、上架记录编辑和采集箱进入上架页的行为不变。

# 汇率工具

## 入口和读取范围

- 全局右上角，简易计算器旁的“汇率工具”。
- 经营首页，AI 消耗右侧的“每日汇率”卡片。显示北京今日已归档参考汇率，点击打开同一弹框。
- 不新增侧栏菜单、路由或工作区标签。首次打开默认近一年，可以切换近一月、近一季度或选择日期；最多 400 日。
- 曲线为每日俄罗斯央行参考价，方向为 1 人民币可兑多少卢布。今日没有日档时明确待更新，最近历史值另外注明，不冒充今日。
- 按用户最新要求，弹框只保留月/季/年、日期区间、刷新、右上今日参考率和曲线。鼠标悬停、触摸和方向键可查看具体日期及日汇率；缺日断线，不插值伪造分时价格。
- 每日明细、来源生效日和存档编号保存在数据库及后台 API；工具不再显示明细表、可追溯说明卡或经营影响面板。

## 经营影响（后台能力，当前工具不展示）

费用核算规则和官方参考汇率是平台公用数据；订单、销售收入及汇差只属于当前企业。有效企业成员可读公共行情，只有当前企业具备财务权限的成员可读企业经营影响。无企业上下文的平台账号只读公共行情。

已结算项目只统计本北京月签收、使用 V2、已有完整实际结算并锁定签收汇率的商品，读取当前实际修订的汇率波动损益，不累计多条历史修订。旧 V1 或版本依据不明的订单分别注明未纳入；没有适用订单时显示说明，缺依据时显示待核对。

待签收项目按当前有效 V2 订单的冻结原始单价和当前待签收数量计算，包含跨月存量。已确认的 RUB 销售价使用原币金额；用户于 2026-10-26 明确确认：CNY 标价先乘冻结下单日汇率，作为参考卢布收入，再按今日汇率折回，与原人民币销售额比较。该值是销售收入的参考测算，不含佣金、物流或其他费用，不预测未来汇率，也不改写订单原币证据或正式利润。

综合预计收入汇差与已确认 RUB、参考 CNY 分项分别保留。页面标明参考项目数和已确认项目数；金额有已知部分时说明覆盖情况，缺单价、数量或冻结汇率的项目不按零处理。该估算与本月已结算真实汇差不合并成净损益。

## API

- `GET /api/exchange-rates/tool?range=year|quarter|month&from=&to=`：只读公共曲线、今日/最近参考价及覆盖情况；服务端重新验证成员及财务权限后，才附带当前企业的 `month_impact`。客户端不能通过企业或店铺参数改变归属。
- `GET /api/exchange-rates/tool/today`：首页轻量读取，仅一条公共档案查询，不读取企业订单。
- 原 `GET /api/exchange-rates/daily-archive` 仍为平台管理员审计入口，权限没有放宽。
- 页面 GET 不取外部报价、不补档、不触发订单重算。切换账户或企业会关闭弹框、取消在途请求并丢弃旧响应。

`open.estimated_sales_income_fx_cny` 是综合参考测算；`known_rub_revenue_impact_cny` 仅包含有明确 RUB 原价的部分。`reference_cny_items`、`reference_cny_impact_cny` 和 `reference_rub_revenue` 标明 CNY 参考部分。显式缺失的综合金额不能回退成已知子集冒充完整结果。

## 官方历史补档

俄罗斯央行 [XML 接口说明](https://www.cbr.ru/development/SXML/) Example 2 定义 `XML_dynamic.asp?date_req1=&date_req2=&VAL_NM_RQ=`；[动态报价 XSD](https://www.cbr.ru/StaticHtml/File/92172/ValCurs_dynamics.xsd) 定义日期范围、币种、Record 日期及名义数量/报价。CNY 标识为 `R01375`。

一次窗口先用首日 daily 响应验证 CNY 身份和真实前序报价，再用一次 dynamic 批量请求补全年。实际官方全年验证得到 247 条生效报价；日历中的休市日按真实前序记录沿用。两个请求足以提供一年曲线，不逐日请求 365 次。

复用不可变的 `order_profit_daily_fx_rates`，不新增冗余表。既有日档的 ID、数值、来源和时间保持原值；新增历史档案保存真实批量 URL、生效日期、原始精度和 XML 原始字节 SHA-256。XML 按声明严格支持 UTF-8/Windows-1251，不以有损解码文本代替原始摘要。

服务主进程和候选均部署支持批量来源 URL 的版本后，执行：

```bash
node scripts/backfill-exchange-rate-history.mjs --database=目标库 --mysql-admin-socket=/var/run/mysqld/mysqld.sock --from=2025-10-27 --to=2026-10-26
```

默认仅检查数据库，不访问央行、不写入。明确加 `--apply` 才补缺少的参考日档；不创建表、不修改旧汇率设置、不改订单或利润。范围依实际北京日期滚动确定。补档可幂等重跑；先完成全部供应商响应校验，再逐日保存已验证的日档。

补档后回滚版本必须继续支持读取真实批量来源 URL，不能将已有批量档案伪装成逐日抓取或删除它们以迁就旧读取器。

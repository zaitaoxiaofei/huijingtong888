# 采集类目回写与草稿恢复

基线：远端 release/2026.10.21-task-brand，c56ad6b8af51a84b0f18e5aa9870b95e0937a8db。
插件版本：1.4.35；安装包：ozon-baodan-erp-plugin-1.4.35.zip。

## 问题与修复

“加入采集箱”入口先保存完整详情，再异步补采卖家类目；旧逻辑关闭回写，稍后返回的 ID 没有入库。修复后复用同一请求，在初次保存成功后附加回写，保留原企业请求上下文，避免重拉与跨企业串写。回写失败不更新本地成功缓存，成功重试会清除失败状态。采集阶段随商品载荷保存，界面区分详情已保存、类目补采和回写失败。

后端统一采集入库与模板生成的类目缓存解析：优先验证完整官方 ID，接纳独立 type_id、单个末级 ID 和旧版组合键；末级 ID 仅在缓存唯一时补全上级，歧义明确提示人工选择。旧 category2/3 推断不覆盖明确官方或手动选择。名称匹配使用完整路径或唯一精确名称，不按模糊名称任取最新记录。

SKU 兜底选择当前企业内实际包含该 SKU 的店铺，保留模板调用的企业会话；不再默认只查最新配置的店铺。未知类目仍保持未知，不生成伪造 ID 或凭空填写必填属性。

图片归档另做每商品范围的共享请求去重与全局 3 并发限制：模板、编辑数据、原始来源中同一 URL 只读取一次；保留所有图片，失败仍明确报错，不绕过 OSS、租户或来源 URL 安全校验。

## 指定商品的实测情况

用户提供公开 SKU 1634801230。Chrome 商品页显示类型为“汽车防盗器遥控器套”，采集插件已加载，Seller 页面已登录；采集箱详情实际缺 description_category_id/type_id。

共享缓存中唯一同名完整类目为 17028749:97381（汽车用品 / 汽车配件 / 汽车防盗器遥控器套），已有 32 个属性定义、3 个必填项。

通过现有授权应用 API 尝试带入该类目创建模板时，图片归档链路返回 502 / operation aborted，尚未创建目标草稿。没有覆盖旧草稿、模板或删除图片。程序直接读取部分公开来源图出现连接失败；ECS 的来源图限 1 KiB 对照请求已实测 HTTP 200，证明不能将归档超时等同于地址失效。当前现网重试仍超时；修复部署后应继续以原地址验证完整图片归档与草稿保存，无需把用户手工下载作为长期路径。该故障与类目回写缺口分开记录，不能将模板创建失败全部归因于类目。

## 操作步骤

1. 更新到 1.4.35 后，刷新 Ozon 商品页与已登录的 seller.ozon.ru 页面；保留插件企业配置。
2. 重新采集指定商品，等“类目补采已回传”后在 ERP 采集箱核对完整类目。若 ID 有歧义，在商品上架页选择完整分类。
3. 继续使用采集原地址归档图片；新版本对重复地址去重并限制并发。若来源连接仍失败，保留全部原地址与图片数量并明确提示；浏览器下载后上传只作为可选的人工兜底，不保存缺图草稿。
4. 打开编辑页，核对类目属性、尺寸重量和必填项后保存草稿。本次恢复不自动提交 Ozon。

新功能 ECS 部署仍需用户对具体验证版本批准，且必须从最终合并 release 提交构建；部署后应检查下载包版本、更新状态及实际生产下载包 manifest 均为 1.4.35。

# FBP 补货、安全目标与图标流程

基线：远端 `release/2026.10.21-task-brand`，`780a49ebc6365130868300b33f1bff2e531be844`。

## 数量与业务口径

- 本地仓：采购到货验收增加实物；FBS订单、安全保障和已审核FBP锁定沿用既有分配。实际发往FBP时才扣本地实物。
- FBP：申请 → 审核锁定 → 发往FBP/在途 → 签收入库 → 官方可用 → 平台订单占用与平台仓销售发货。发仓记录与销售履约是不同流程。
- 官方可用已经排除平台占用，不再次扣减订单；签收记录仅用于核对，不直接累加到官方可用。缺少任一绑定SKU快照时保持未知。
- 各店铺、SKU分别按FBP/OGR近14个完整北京时间自然日销量计算安全目标，不能用另一店铺的富余抵消短缺；本地保障口径不变。
- 补货净需求先扣同SKU在途与已审核待发，同SKU预测和待审核申请取较大值，跨SKU累加；草稿不产生正式需求。本地可用与剩余采购在途优先覆盖，剩余缺口才建议采购。
- 已核实的官方安全缺口可手动提交采购申请，无须为了采购先制造一张备货申请；已被在途覆盖则阻止基于安全目标的重复申请。保留原有成员权限、事务、幂等和通知校验。
- 全局预警使用批量本地快照和聚合销量，40个商品共5次查询；不逐商品调用远程API。首屏local-only路径跳过该投影，FBP读取完成后异步补充。

## 交互

采购、本地仓、FBP使用三条图标流程，点击展开原有数量证据、SKU或对应单据。真实在途才显示轻微运输动效，真实缺口才显示预警动效。浅色、深色、窄屏和系统减少动态效果均覆盖；未知数量显示待核对。

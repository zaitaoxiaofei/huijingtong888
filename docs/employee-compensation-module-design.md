# 员工工资模块设计方案

## 1. 目标

在现有员工、店铺、利润账单和运营任务数据之上，增加一套可配置、可试算、可审核、可追溯的工资核算模块。

核心目标：

- 不再由财务手工汇总每位员工工资。
- 支持按岗位、员工、店铺和生效时间配置不同工资策略。
- 支持底薪、营业额提成、利润提成、绩效、满勤、五险一金、季度奖、年终奖及人工调整。
- 每一项金额都能展开查看公式、原始指标、计算过程和调整记录。
- 已审核工资自动进入现有月度账单的工资费用，避免重复录入或重复扣减。

## 2. 产品入口与页面

建议在“财务中心”下增加“员工工资”，路由为 `/finance/payroll`，包含五个页签。

### 2.1 工资总览

- 月份、公司、店铺、员工、部门/岗位筛选。
- 应发工资、员工扣款、实发工资、公司承担五险一金、公司总用工成本。
- 本月与上月对比，按店铺和工资项目拆分。
- 待配置、待取数、待确认、待审核、已锁定、已发放等异常提醒。

### 2.2 工资单

一行一名员工，默认显示：

- 员工、岗位、归属店铺。
- 底薪、营业额提成、利润提成、绩效奖金、满勤奖、其他奖金。
- 员工五险一金、个税、其他扣款。
- 应发、应扣、实发、公司承担金额、公司总成本。
- 数据完整度、工资单状态、审核人、发放状态。

点击员工后展示工资明细和逐项计算证据。

### 2.3 工资策略

- 策略模板：例如运营、店长、采购、仓库、客服。
- 员工可以继承模板，并覆盖单独项目。
- 策略有版本和生效日期，修改下月策略不会改变历史工资单。
- 提供“复制策略”“停用”“模拟计算”和“批量分配员工”。

### 2.4 绩效指标

- 指标库、数据来源、负责人、目标值、完成值、得分规则。
- 自动指标和人工指标分开标识。
- 支持员工确认，主管复核，争议备注和附件。

### 2.5 社保奖金与设置

- 五险一金基数和比例。
- 参保公司、参保城市和城市缴费方案。
- 考勤数据或人工录入。
- 季度奖、年终奖规则。
- 个税先支持人工录入，后续再增加专项附加扣除和税务计算器。

### 2.6 外部工资表导出

- 内部工资单保持完整明细，外部 Excel 只接收最终汇总结果。
- 按公司和城市维护不同导出模板，例如“上海汇境通工资表”“合肥公司工资表”。
- 导出时选择工资月份和公司，系统复制对应模板并填入员工数据，不改变原模板版式。
- 导出记录保存模板版本、工资批次、导出人和导出时间，支持重复下载但不能重复生成费用。

## 3. 工资计算模型

### 3.1 统一公式

```text
固定收入 = 底薪 + 岗位津贴 + 固定补贴
业务提成 = 营业额提成 + 利润提成 + 订单/商品提成
绩效收入 = 绩效奖金 + 满勤奖 + 季度奖 + 年终奖
应发工资 = 固定收入 + 业务提成 + 绩效收入 + 其他加项
员工扣款 = 员工承担五险一金 + 个税 + 考勤扣款 + 其他减项
实发工资 = 应发工资 - 员工扣款
公司总成本 = 应发工资 + 公司承担五险一金 + 公司福利及其他雇主成本
```

“员工实发”和“公司用工成本”必须同时展示，不能把公司承担的社保、公积金算进员工实发。

### 3.2 DIY 组件类型

策略不是让用户编写代码公式，而是由可组合的安全组件构成：

| 组件 | 配置方式 | 示例 |
| --- | --- | --- |
| 固定金额 | 月金额，可按入离职天数折算 | 底薪 6,000 元 |
| 百分比提成 | 指标 × 比例 | 店铺营业额 × 0.3% |
| 阶梯提成 | 不同区间使用不同费率 | 利润 0～5 万 2%，超出部分 4% |
| 达标奖金 | 满足条件发固定金额 | 上新满 40 个奖励 800 元 |
| 分段评分 | 完成率映射为得分或金额 | 完成率 90% 对应 80 分 |
| 封顶/保底 | 限制某项目或整单金额 | 提成最高 10,000 元 |
| 人工录入 | 需备注、凭证和审批 | 临时奖励、处罚、补发 |
| 周期奖金 | 按季度或年度累计指标 | 季度利润达标奖 |

所有金额组件都支持：适用范围、指标周期、计算顺序、四舍五入方式、最低值、最高值、是否允许负数和备注。

### 3.3 营业额与利润提成口径

营业额提供可选口径，但策略保存后必须锁定一种：

- 有效营业额：排除取消，退货按最终确认结果冲减。建议作为默认值。
- 结算营业额：仅使用已到账/已结算金额，准确但时间滞后。
- 下单营业额：波动快，不建议作为正式发薪依据。

利润提成默认使用：

```text
提成基数 = 店铺经营利润（扣除平台费、广告、采购、物流和人工杂费，但不扣本次工资）
利润提成 = max(0, 提成基数 - 利润门槛) × 提成比例
```

必须使用“扣工资前利润”，否则工资影响利润、利润又影响工资，会产生循环计算。若利润为负，默认提成为 0；是否允许负向追扣应作为显式高级选项。

### 3.4 多店铺和多人分摊

新增员工店铺归属关系，包含生效日期和权重。例如员工负责 A 店 60%、B 店 40%。

- 店铺指标提成：分别按店铺计算，再按员工权重分配。
- 公司级固定工资：可按权重分摊到店铺，供利润账单核算。
- 多人共同负责一个店铺时，员工分配权重之和允许小于 100%，但不能超过 100%。
- 中途调店按生效日期切段，不直接覆盖整月归属。

## 4. 绩效考核设计

### 4.1 首批自动指标

优先使用当前系统已有明确责任人和时间记录的数据：

- 新增选品数。
- 新建或完成上新草稿数。
- 成功发布商品数。
- 产品开发任务完成数、完成率和质量分。
- 采购任务完成数。
- 负责人名下商品产生的有效营业额、利润或订单数。

“运营动作”不能只按点击次数计薪，避免刷操作。建议用有业务结果的事件，例如“成功发布”“审核通过”“任务完成”，并保留对象 ID 去重。

### 4.2 指标得分

推荐每个岗位使用 100 分绩效卡：

| 指标 | 权重 | 示例目标 | 示例计分 |
| --- | ---: | ---: | --- |
| 成功上新数 | 30% | 40 个 | 完成率封顶 120% |
| 选品通过数 | 20% | 15 个 | 按通过数量计分 |
| 店铺利润目标 | 30% | 50,000 元 | 低于 60% 不得分 |
| 运营任务质量 | 20% | 90 分 | 使用主管确认质量分 |

```text
指标得分 = min(完成值 / 目标值, 指标封顶比例) × 指标权重
绩效奖金 = 绩效奖金基数 × 绩效系数
```

绩效系数可配置为：低于 60 分为 0，60～79 分为 0.6，80～89 分为 0.8，90～99 分为 1.0，100 分以上为 1.2。

### 4.3 数据可信度

每个自动指标保存：来源表/业务对象、统计口径、时间范围、负责人字段、生成时间和明细快照。无法自动取数时状态应为“待补录”，不能静默按 0 计算。

## 5. 五险一金、考勤和奖金

### 5.1 五险一金

- 按参保城市/方案维护养老、医疗、失业、工伤、生育、公积金比例。
- 首批建立“上海最低基数方案”和“合肥最低基数方案”，每个方案分别保存社保最低基数、公积金最低基数、单位比例、个人比例和生效日期。
- 默认缴费基数取员工参保城市在该月份有效的最低缴费基数；如果以后需要为个别员工提高基数，可以在员工档案单独覆盖。
- 区分员工承担与公司承担。
- 参数按生效日期版本化，历史月份不回滚。
- 首版支持手工覆盖最终金额，覆盖必须填写原因。
- 城市最低基数和缴费比例属于年度政策参数，不允许写死在代码或工资策略中；每次政策调整新增版本，并保留政策来源和核验日期。

### 5.1.1 参保归属与店铺归属分离

员工需要增加以下工资档案字段：

- 用工/发薪公司。
- 参保城市：上海或合肥。
- 社保方案。
- 公积金方案。
- 参保开始和结束日期。

参保城市由员工挂靠的用工公司决定，不跟随员工负责的店铺变化。例如员工负责上海店铺，但劳动关系挂在合肥公司，仍按合肥方案缴纳和导出到合肥公司工资表。

### 5.1.2 月度计算口径

```text
社保缴费基数 = 当月有效城市方案的社保最低缴费基数
公积金缴费基数 = 当月有效城市方案的公积金最低缴费基数
单位某险种金额 = 对应缴费基数 × 单位比例
个人某险种金额 = 对应缴费基数 × 个人比例
```

金额按城市申报要求进行舍入。新入职、离职、补缴、断缴和跨城市转移不能按普通整月静默计算，应标记为人工确认。

### 5.2 考勤

- 满勤奖应依赖应出勤天数、实际出勤、迟到、早退、事假、病假、旷工。
- 暂无考勤系统时，首版按月人工录入并由主管确认。
- 后续可导入 CSV/Excel 或接考勤系统，数据来源保持可追溯。

### 5.3 季度奖和年终奖

- 规则仍复用工资组件，但核算周期为季度或年度。
- 支持按季度/月度平均绩效、累计利润、在职月数和发放条件计算。
- 奖金归属期与实际发放月分开保存。

## 6. 核算流程与状态

```text
草稿 → 取数完成 → 员工/主管确认 → 财务审核 → 锁定 → 已发放
```

1. 每月创建核算批次，冻结员工、策略版本、店铺归属和指标时间范围。
2. 系统拉取店铺经营指标和员工运营指标，生成试算工资单。
3. 主管补充考勤、质量分和人工奖惩，员工可查看但不能修改金额。
4. 财务检查异常、审核并锁定。
5. 锁定后生成工资费用，按店铺分摊写入月度账单。
6. 发薪后记录发放日期、流水号和凭证。

锁定后禁止直接编辑。需要改动时生成“调整单”，可以在本期补发/追扣，也可以撤销审核后重新核算；两种操作都必须留审计记录。

## 7. 数据结构建议

不要把所有规则塞进 `people` 表，也不要把最终工资只保存成一个总数。建议新增：

| 表 | 用途 |
| --- | --- |
| `payroll_profiles` | 员工薪酬档案、岗位、入离职日期、社保方案 |
| `payroll_legal_entities` | 用工/发薪公司及其城市、工资表模板 |
| `payroll_contribution_schemes` | 上海、合肥等城市的社保公积金基数、比例和生效版本 |
| `payroll_shop_assignments` | 员工与店铺的有效期、职责和分摊权重 |
| `payroll_policy_templates` | 策略模板及版本、生效时间 |
| `payroll_policy_components` | 策略中的底薪、提成、绩效、奖金和扣款组件 |
| `payroll_employee_policies` | 员工绑定策略及个性化覆盖 |
| `payroll_metric_definitions` | 指标口径、数据源、周期和计分规则 |
| `payroll_periods` | 月/季/年核算批次和状态 |
| `payroll_statements` | 每位员工每个周期的工资单汇总 |
| `payroll_statement_items` | 每个工资项目的输入、公式、结果和快照 |
| `payroll_metric_snapshots` | 指标值及可追溯业务对象快照 |
| `payroll_attendance` | 月度考勤数据 |
| `payroll_adjustments` | 补发、追扣和人工奖惩 |
| `payroll_audit_logs` | 配置、计算、审核、锁定和发放日志 |

关键金额使用 `DECIMAL`，比例和金额规则保存结构化 JSON，同时把规则名称、版本和计算结果展开保存，确保未来策略变化后仍能解释历史工资。

## 8. 与现有系统的衔接

- 员工直接复用 `people.id`，不重复创建员工档案。
- 店铺直接复用 `shops.id`；现有 `shops.user_id` 可作为默认负责人，但工资使用新的多店铺归属关系，不能只依赖单一负责人字段。
- 营业额和利润优先读取 `analytics_shop_daily`，并保存核算快照。
- 产品开发与运营绩效可读取现有负责人字段和团队任务数据。
- 已审核工资生成或关联一笔 `finance_expenses.category = 'salary'` 的费用记录，并带唯一工资批次来源标识；禁止人工费用和工资批次重复扣减。
- 月度账单继续读取工资费用，但可下钻到工资批次、员工和工资项目。
- 员工负责的店铺决定经营指标和工资成本分摊；员工挂靠的用工公司决定社保城市和外部工资表，两种关系不能混用。

建议为 `finance_expenses` 增加 `source_type`、`source_id` 和唯一约束，使自动生成的工资费用可幂等更新，避免重复写入。

## 8.1 上海现有工资表映射

已确认当前《上海汇境通员工工资明细表1.xlsx》包含 3 月至 6 月四个工作表，主体范围为 A:S。导出时保留现有标题、合并单元格、边框、签字栏和公式结构。

| Excel 列 | 模板字段 | 内部工资字段 |
| --- | --- | --- |
| A | 序号 | 导出序号 |
| B | 部门 | 员工部门/岗位 |
| C | 姓名 | 员工姓名 |
| D | 基本工资 | 内部工资单“应发工资”汇总值 |
| E:I | 单位养老、医疗、附加医疗、失业、工伤 | 城市方案的单位缴费明细 |
| J | 单位公积金 | 城市方案的单位公积金 |
| K | 单位缴费小计 | E:J 合计 |
| L:N | 个人养老、医疗、失业 | 城市方案的个人缴费明细 |
| O | 个人公积金 | 城市方案的个人公积金 |
| P | 个人缴费小计 | L:O 合计 |
| Q | 当月应缴个人税 | 内部工资单个税 |
| R | 实发工资 | D - P - Q |
| S | 确认签字 | 保留空白供签字 |

模板的 D 列名称虽然是“基本工资”，为了满足“内部明细计算、外部只填最终工资”的要求，导出时默认映射内部“应发工资合计”，即已经包含底薪、提成、绩效、奖金和其他应发项目。该映射必须作为模板配置显示，避免使用者误以为 D 列只含底薪。

合肥员工使用独立模板和合肥城市方案；即使两份模板列结构相同，也分别保存模板版本，不能直接覆盖上海模板。

## 9. 权限和隐私

- 管理员：策略、全员工资、审核、锁定和撤销。
- 财务：全员工资、调整、审核、发放和导出。
- 主管：仅查看和确认自己负责团队的绩效、考勤和非敏感明细。
- 员工：仅查看自己的工资单和计算依据。
- 店铺利润、其他员工工资、身份证号、银行卡号等敏感数据默认不可见。
- 工资导出、查看详情和修改都写审计日志。

## 10. 异常与校验

以下情况阻止审核，并明确提示缺什么、去哪里修复：

- 员工没有有效工资策略。
- 策略引用的店铺、指标或社保方案失效。
- 多人店铺分配权重超过 100%。
- 自动指标取数失败或账单快照未生成。
- 公式出现循环依赖、除零、非法负数或超出封顶值。
- 同一员工同一周期存在重复工资单。
- 本月工资费用已经回写，试图再次生成。

非阻塞警告包括：环比波动超过阈值、提成远高于底薪、利润为负但仍有奖金、人工调整金额过大。

## 11. 推荐分期

### 第一期：先替代人工工资汇总

- 员工薪酬档案和店铺归属。
- 底薪、固定补贴、营业额/利润提成、满勤、手工奖惩。
- 月度试算、审核锁定、明细解释。
- 审核后回写现有月度账单。

### 第二期：自动绩效与社保

- 上新、选品、任务、营业额和利润指标自动取数。
- 绩效卡和主管确认。
- 五险一金方案、考勤导入和工资导出。

### 第三期：奖金与员工自助

- 季度奖、年终奖、补发追扣。
- 员工工资单自助查看与确认。
- 银行发薪文件、个税计算和凭证闭环。

## 12. 首版验收标准

- 能为不同员工配置不同工资组合，并设置生效日期。
- 能按一个月、一个员工、多个店铺完成稳定试算。
- 任一工资项目都能解释“指标来源 × 规则 = 金额”。
- 修改策略不会改变已锁定历史工资单。
- 已审核工资只在月度账单扣减一次，并能下钻到员工明细。
- 缺少指标时不会默认为 0 后直接发薪。
- 所有用户界面日期按北京时间显示。

## 13. 建议的默认运营岗位模板

可先提供一个开箱即用但可修改的模板：

```text
底薪：6,000 元
店铺利润提成：扣工资前经营利润超过 30,000 元的部分 × 3%
店铺营业额提成：有效营业额 × 0.2%，单月封顶 3,000 元
绩效奖金基数：2,000 元，按 100 分绩效卡系数计算
满勤奖：300 元
员工五险一金：按员工档案基数和方案扣除
季度奖：季度平均绩效不低于 90 且季度利润达标时发放
年终奖：年度累计绩效、公司利润和在职月数共同决定
```

该模板只作为新建策略的示例，不能硬编码为全公司统一规则。

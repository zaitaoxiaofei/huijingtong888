# 订单同步策略

## 两种同步

### 历史回填

入口：我的订单 -> 选择店铺、开始日期、结束日期 -> 拉取当前范围。

用途：

- 第一次补齐老店铺历史订单。
- 例如 RuVibe Mart 从 2025-10-01 拉到 2026-05-06。
- 后端会按 31 天切片请求 Ozon，避免一次请求时间跨度太大。
- 每个切片内部按 Ozon `has_next` 分页拉完。

### 日常增量

入口：我的订单 -> 增量同步。

用途：

- 平时维护订单状态。
- 默认拉最近 7 天。
- 同时从本地数据库里找 `sync_state != final` 的老订单，按这些订单所在日期补查 Ozon。
- 已取消订单和超过 45 天的已签收订单会逐步归档为 `final`，后续增量同步不会反复查它们。
- 超过 60 天还没有完成的订单会标记为 `exception`，进入“同步异常”状态。

## 订单生命周期

- `open`：仍可能变化，增量同步会继续关注。
- `final`：已经归档，不再作为日常增量同步目标。
- `exception`：超过正常周期仍未完成，需要人工检查。

## 当前限制

- Ozon 返回什么字段，系统会尽量完整保存到 `ozon_orders_raw.raw_json`。
- 订单列表接口当前最多返回 10000 单，前端再分页筛选。
- 自动每 5 分钟后台同步还没有开启；建议等历史回填完成后再打开，避免回填期间和自动同步抢接口请求。

## 推荐操作顺序

1. 先对老店铺执行一次历史回填。
2. 回填完成后看“同步异常”和“待绑定 SKU”。
3. 老数据确认后，再开启定时增量同步。

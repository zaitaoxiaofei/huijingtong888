# 刊登、AI 与任务中心企业隔离验收

本文记录 `codex/saas-pilot-isolation` 的实现边界。测试使用独立、禁用 TCP 的临时 MySQL，每项测试创建并删除自己的随机数据库；没有读取业务数据库，也没有部署或重启服务。

## 企业与操作人

- 历史刊登/AI 数据使用字符串企业键 `admin`，对应数据库中 `slug = default` 的企业；新企业使用数字主键的字符串。核心库存、店铺、采购表继续使用数字企业主键。默认企业只能访问自身数字归属及被明确保留的历史 NULL 归属。
- `business-task-tenant.js` 从数据库重新检查企业、订阅期限、人员、有效企业成员及当前岗位。平台管理员身份不能替代后台业务任务的企业成员身份。
- 刊登发布记录、AI 生成任务、批次任务、矩阵任务和活动清理配置保存企业与操作人。后台执行恢复保存的身份，不能沿用调度线程的其他企业上下文。
- `team-task-tenant.js` 在任务中心 HTTP 入口检查当前 `team` 权限并建立独立上下文。任务自动刷新缓存按企业分开；无企业上下文的旧全局启动预热会跳过。

## AI 费用与文件

- `tenant_ai_limits`、`tenant_ai_usage` 按企业和北京时间月份计数。同一企业的并发请求通过事务锁统一预留额度；文本、视觉、图片调用均纳入总次数，失败的已提交尝试不退回次数，已有供应商任务轮询不重复计数。
- 新企业没有额度行时额度为 0；平台明确写入 NULL 才表示无限额度。默认历史企业没有额度行时保留原有无限策略。请求体不能指定计费企业或操作人。
- AI 默认业务上下文要求 `operations`；订单分析可以显式使用 `analytics`。预留额度时再次检查对应权限，分析上下文不能被其他运营业务当作运营授权复用。
- `ai_image_task_owners` 在写入新 AI/裁图任务文件之前保存企业与操作人。文件、下载和 ZIP 入口检查归属和路径边界；裁图处理在启动处理器之前完成检查。
- 原始 AI 输出保持私有 API 文件地址。素材被明确保存为刊登发布图片后，才进入 Ozon 可公开抓取的发布资产流程。`/uploads/listing-media` 是发布资产边界，不能用它代替原始任务文件授权。

## 数据与迁移

- `migrate-tenant-ai-background.mjs` 迁移 15 张既有 AI/后台表并建立 3 张额度、用量和文件归属表；AI 业务编号唯一键带企业维度。
- `migrate-tenant-team-tasks.mjs` 迁移 9 张团队任务/项目/候选/灵感/关联/热力图表。自动任务唯一键、固定负责人和热力图主键带企业维度。`team-task-schema.js` 提供全新数据库的完整建表定义。
- 两个迁移默认只读预览，执行需要明确数据库与管理员 socket。实际迁移使用数据库级 advisory lock，并在变更后验证列和主键/唯一键；历史归属仅保留默认企业，不推断其他企业成员。
- 团队任务人员引用检查当前企业成员；项目、候选、产品、草稿引用检查企业归属。运营统计的订单、采购、库存来源均在 SQL 中限定当前企业。
- 默认企业选品列表、分页、汇总和筛选使用一致的产品范围，供应商及人员关联同样收口；发布任务关联不能读取其他企业的任务，即使存在错误产品引用。

## 评价与活动

- 评价列表、总数、同步、回复和评论读取根据店铺企业归属授权；回复操作人取已授权会话。
- Ozon 活动的 7 个外部操作入口均在取店铺凭据和外部请求之前检查当前企业。
- 自动活动清理配置保存服务端确认的企业和操作人，恢复执行从数据库配置读取身份。旧配置缺少身份时拒绝执行，需要企业运营重新保存配置后启用；不会给旧全局任务推断管理员身份。
- 现有评价回复模板为共享预置文案；当前接口不提供企业自定义模板写入。

## 验证范围

### 2026-10-23 发布回执与视觉重试

上线后的普通运营验收补齐草稿列表的精确只读 `GET /api/listing/draft-bindings` 门禁。关联数据只从当前企业草稿、车型和任务返回；负责人姓名与头像还要求当前企业有效成员及有效账号，返回前重新核验当前运营权限。`POST draft-bindings`、`GET draft-binding-options` 及未验收的高级绑定写入继续关闭。默认企业的数字 ID 不假定为 1，测试使用实际 ID 7 验证旧 `admin` 键与成员归属一致。

记录级重试在每次 Ozon 请求及退避后的下一次尝试前，重新核对当前操作人的企业、岗位、成员、订阅和原店铺；请求体不能替换企业或店铺。已知任务编号先查询官方结果，只有明确失败才允许修正后再次提交。任务级重试的中央门禁保持不变。

直接发布和记录重试在外部提交前，用既有发布记录的 JSON 和状态保存独立尝试标记；返回任务编号后，先保存回执，再进行状态查询、变体关联、库存关联或质量查询。数据库瞬断只重存同一份回执，不重投 Ozon。持续保存失败、网络结果未知或未返回任务编号时保持 `resubmitting`，不会当作普通失败自动重投；界面错误提示先刷新并核对原店铺商品编号，无法确认时由管理员核对处理，不伪造任务编号或仅凭 HTTP 5xx 判断未提交。

最终结果、错误记录及变体状态更新限定原企业、原店铺和本次回执；旧任务迟到的响应不能覆盖后续已确认失败后重新提交的任务。后续关联与质量查询继续使用绑定回执的权限检查。

视觉请求重试在第二次请求前再次检查当前权限并预留一次额度；两次已提交尝试计两次，额度耗尽和撤权保留原有 409/403 错误。真实 MySQL 与网络替身回归覆盖退避撤权、回执写入失败、状态查询挂起、并发重试、旧结果迟到及逐次额度，未进行真实 Ozon 发布或付费 AI 调用。

### 2026-10-22 AI 裂变运营入口修复

普通运营人员原先已通过岗位鉴权，但识别、规划及图片生成接口遗漏于中央企业隔离清单，返回 `TENANT_ISOLATION_PENDING`；默认企业的平台管理员因维护入口绕过该清单而不受影响。这不是要求运营人员拥有平台权限。

补齐以下精确 POST 入口：`ai-variant-lab/analyze-image`、`ai-variant-lab/batch-plan`、`ai-variant-lab/batch-run-images`、`ai-variant-lab/batch-resume-images`、`listing/generate-offer-id`。默认企业普通成员和客户企业使用同一套规则，仍要求有效企业、成员、订阅及运营权限；不按模块前缀开放其他高级接口。

图片批次从数据库保存的企业与创建人恢复独立上下文；每行、通道重试、服务商轮询、结果保存及延时唤醒重新检查权限。失败记录和运行标识固定企业，不能沿用调度线程的其他企业身份。已有服务商任务继续拉取时不重复扣生成额度。请求体不能覆盖计费企业或任务创建人。

公开参考图读取复用 DNS 地址校验及连接固定，拒绝私网、元数据地址和重定向越界，下载限制 20 MB；私有 AI 文件仍验证任务归属，历史公开刊登素材只允许真实 `public/uploads/listing-media` 目录中的文件。

新增回归覆盖完整 HTTP 登录后的普通运营入口、A/B/default 同编号规划与任务、错误企业引用、并发额度、持久任务恢复、运行中撤岗/撤销成员/订阅过期、服务商内部连续轮询撤权、错误清理与唤醒，以及四类货号占用来源隔离。所有付费 AI 请求使用网络替身，生产只读验证不会代替真实付费生成结果验收。

### 2026-10-22 普通运营草稿批量上架

草稿箱批量上架先读取店铺素材配置，在浏览器准备素材，再提交后台批量任务。此前 `POST listing/drafts/batch-publish` 属于未验收而关闭的入口，普通运营虽有岗位权限仍被隔离门禁拒绝，默认企业的平台管理员可以通过维护入口执行。浏览器水印 `POST listing/media/watermark` 同样需要独立收口，不能按模块前缀整体放行。

本轮只验收并开放这两个精确 POST。水印核验当前企业与目标店铺，图片读取、合成和登记前后重新检查成员、订阅和运营权限；私有 AI/裁图素材继续通过原任务归属检查。发布媒体的远程请求使用校验并固定的公共地址，逐次核对重定向、超时和读取上限。客户企业的运营人员可以读取本企业的 bootstrap、尾图配置及文件用于发布，配置写入仍要求企业负责人或管理员。

批量任务保存服务端确认的企业与创建人，准备、恢复及最终提交使用持久身份重新授权，不沿用排队线程或请求体身份。原店铺、草稿、任务成员和发布记录的企业关系逐项校验。外部提交已返回任务编号时先保存回执，随后撤权会停止后续查询和关联；恢复不会因丢失回执而重复提交。任务级重试已在下述 2026-10-26 专项验收后开放；其他高级接口继续使用各自精确门禁。

前端分别显示配置加载和素材处理阶段，避免把初始化显示为 `0/0`；失败明确显示原因并释放忙碌状态。提交结果未知时提示先查看上架记录，保留原请求编号用于幂等重试。未改变图片编辑、拖拽排序、模板复用及发布字段选择规则。

新增真实 MySQL 验证覆盖普通默认企业及客户 A/B、相同请求编号并发、伪造身份、跨企业引用、后台恢复、各阶段撤权、水印文件归属及已确认回执不重复提交。测试中的 Ozon、AI、OSS 和文件写入使用替身，不代表已替生产用户发布真实商品。

### 2026-10-22 普通运营商品拉取与性能

在线商品的待上架拉取此前同时受平台专属按钮和未验收同步门禁限制。现在仅开放 `POST /api/sync/online-products` 与 `GET /api/sync/online-products/status` 两个精确入口，要求当前有效企业的运营岗位；默认企业普通运营和客户企业规则相同。库存平台同步、财务同步和其他同步入口的权限保持独立。

后台任务从当前成员恢复身份，列表每一页、详情、库存回读、图片下载转存以及商品、库存和归档写入前重新校验成员、订阅及原店铺。店铺凭据按请求重新读取，不沿用过期快照。选中商品限定原店铺，进度和忙碌任务按企业隔离，请求体不能指定执行企业或人员。运行中撤岗、撤销成员、停店或店铺归属变化均停止后续写入。

空候选集不再触发 Ozon 的无筛选整店库存请求，也不清空已有库存。选中商品已有 Product ID 时直接读取详情；归档核对和缺 SKU 的严格待上架筛选保留。店铺并行上限为 3，每店商品与库存写入最多 2 路，每商品图片最多 3 路，给订单及其他员工请求保留数据库资源。

成功转存的原图地址与 OSS 地址映射保存在服务器写入的 `raw_json._erp_source_assets`，重复拉取只复用本次权威图片集合内、当前 OSS 配置认可的映射；不信任上游同名字段，不恢复已删除图片或旧主图。任务内缓存有界，失败转存不缓存为成功。旧行首次没有映射时仍需下载一次，不能把这轮成本报告成已经消除。下载使用校验并固定公共 DNS 的流式请求，重定向重新鉴权，保留超时、取消和字节上限。

页面显示拉取阶段及店铺、商品进度；启动或状态请求失败后释放忙碌状态并显示原因，可以再次操作。专项实库测试覆盖 A/B/default、同商品编号及 SKU、库存覆盖、跨企业引用、请求返回和图片完成后的撤权；外部 Ozon/OSS 请求使用替身。生产历史日志确认出现过数据库连接等待超时，但未据此编造实际加速秒数；线上真实耗时须以部署后的具体拉取记录为准。

本轮批量任务实库 36/36、水印实库 24/24、公共媒体安全 26/26、直接发布与相邻回归 83/83、既有媒体兼容 34/34，以及包含真实登录、两个新入口和企业配置读取的完整 HTTP/权限/AI 图片回归组 68/68 通过，均无跳过；这些组存在重叠。前端批量准备新增 8/8 通过，亮/暗 mock 页面验证配置加载、具体错误和同一弹框重试；刊登保护组的 5 项既有结构断言失败与修改前 HEAD 基线相同，不描述为整仓全绿。

### 2026-10-24 草稿轻量列表响应

仅 `GET /api/listing/drafts?paged=1&lightweight=1`（含 `compact=1` 别名）的概览行省略重复存储字段 `source_urls_json`、`source_images_json`、`template_payload_json`、`manual_facts_json`、`ai_payload_json`、`shop_copies_json`。对应的 `source_urls`、`source_images`、`template_payload`、`manual_facts`、`ai_payload`、`shop_copies` 继续返回；`effective_images`、人工清空意图、价格、发布统计、车型和任务字段不变。详情及非轻量读取保留原字段，不修改存储或发布内容。

此前 mysql2 原生 JSON 对象被当成字符串解析，导致概览的当前图片投影被丢弃。恢复正确解析会增加返回内容，不能通过再次丢弃当前图片来提速。本次只移除同一内容的原始 JSON 副本，仍需单独区分数据库查询、媒体映射及浏览器加载耗时；不据响应缩小承诺页面提速比例。

### 2026-10-26 运营任务重试与多 SKU 批量素材

仅开放 `POST /api/listing/publish-tasks/:数字ID/retry`，仍要求当前有效企业运营岗位。任务详情、草稿、店铺和待重试项必须同企业；准备期间每次额度、文案和素材请求前后复核当前操作者、成员、订阅及店铺。排队后执行恢复记录保存的身份，撤权停止外部提交。此入口不授予平台配置、跨企业或匿名插件权限。

草稿列表与详情增加 `publish_images`：按 SKU 顺序去重合并最终发布所需图片，用于批量及任务重试的浏览器素材准备；`effective_images` 继续用于首 SKU 展示及既有人工清空语义。轻量列表兼容 `editable_payload`、`editablePayload` 和顶层 `variants` 的图片投影。服务端仍严格校验来源图片集合与顺序，真正缺图、重排、过期清单及不同图片生成相同输出均停止整条发布，不能删图凑成功。前端只调整取图逻辑，页面布局与样式不变。

批量新建/重试可通过内部校验选项为缺失货号保留空位，随后由原有目标店铺唯一货号生成器补全正式货号；已有货号保留，不把预览用 `NEW-OFFER` 发给 Ozon，单编辑校验也不能通过请求体开启该内部能力。更新已有多 SKU 发布记录逐项保留原货号，禁止把首 SKU 货号复制给所有 SKU；身份集合有变化时要求在原记录核对。此轮未改写历史草稿、已提交回执或生产权限。

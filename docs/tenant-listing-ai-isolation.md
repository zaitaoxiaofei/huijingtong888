# 刊登、AI 与任务中心企业隔离验收

本文记录 `codex/saas-pilot-isolation` 的实现边界。测试使用独立、禁用 TCP 的临时 MySQL，每项测试创建并删除自己的随机数据库；没有读取业务数据库，也没有部署或重启服务。

## 企业与操作人

- 历史刊登/AI 数据使用字符串企业键 `admin`，对应数据库中 `slug = default` 的企业；新企业使用数字主键的字符串。核心库存、店铺、采购表继续使用数字企业主键。默认企业只能访问自身数字归属及被明确保留的历史 NULL 归属。
- `business-task-tenant.js` 从数据库重新检查企业、订阅期限、人员、有效企业成员及当前岗位。平台管理员身份不能替代后台业务任务的企业成员身份。
- 刊登发布记录、AI 生成任务、批次任务、矩阵任务和活动清理配置保存企业与操作人。后台执行恢复保存的身份，不能沿用调度线程的其他企业上下文。
- `team-task-tenant.js` 在任务中心 HTTP 入口检查当前 `team` 权限并建立独立上下文。任务自动刷新缓存按企业分开；无企业上下文的旧全局启动预热会跳过。

## AI 费用与文件

- `tenant_ai_limits`、`tenant_ai_usage` 按企业和北京时间月份计数。同一企业的并发请求通过事务锁统一预留额度；文本、视觉、图片调用均纳入总次数，失败的已提交尝试不退回次数，已有供应商任务轮询不重复计数。
- 新企业没有额度行时额度为 0；平台明确写入 NULL 才表示无限额度。默认历史企业没有额度行时保留原有无限策略。请求体不能指定计费企业或操作人。
- AI 默认业务上下文要求 `operations`；订单分析可以显式使用 `analytics`。预留额度时再次检查对应权限，分析上下文不能被其他运营业务当作运营授权复用。
- `ai_image_task_owners` 在写入新 AI/裁图任务文件之前保存企业与操作人。文件、下载和 ZIP 入口检查归属和路径边界；裁图处理在启动处理器之前完成检查。
- 原始 AI 输出保持私有 API 文件地址。素材被明确保存为刊登发布图片后，才进入 Ozon 可公开抓取的发布资产流程。`/uploads/listing-media` 是发布资产边界，不能用它代替原始任务文件授权。

## 数据与迁移

- `migrate-tenant-ai-background.mjs` 迁移 15 张既有 AI/后台表并建立 3 张额度、用量和文件归属表；AI 业务编号唯一键带企业维度。
- `migrate-tenant-team-tasks.mjs` 迁移 9 张团队任务/项目/候选/灵感/关联/热力图表。自动任务唯一键、固定负责人和热力图主键带企业维度。`team-task-schema.js` 提供全新数据库的完整建表定义。
- 两个迁移默认只读预览，执行需要明确数据库与管理员 socket。实际迁移使用数据库级 advisory lock，并在变更后验证列和主键/唯一键；历史归属仅保留默认企业，不推断其他企业成员。
- 团队任务人员引用检查当前企业成员；项目、候选、产品、草稿引用检查企业归属。运营统计的订单、采购、库存来源均在 SQL 中限定当前企业。
- 默认企业选品列表、分页、汇总和筛选使用一致的产品范围，供应商及人员关联同样收口；发布任务关联不能读取其他企业的任务，即使存在错误产品引用。

## 评价与活动

- 评价列表、总数、同步、回复和评论读取根据店铺企业归属授权；回复操作人取已授权会话。
- Ozon 活动的 7 个外部操作入口均在取店铺凭据和外部请求之前检查当前企业。
- 自动活动清理配置保存服务端确认的企业和操作人，恢复执行从数据库配置读取身份。旧配置缺少身份时拒绝执行，需要企业运营重新保存配置后启用；不会给旧全局任务推断管理员身份。
- 现有评价回复模板为共享预置文案；当前接口不提供企业自定义模板写入。

## 验证范围

### 2026-10-22 AI 裂变运营入口修复

普通运营人员原先已通过岗位鉴权，但识别、规划及图片生成接口遗漏于中央企业隔离清单，返回 `TENANT_ISOLATION_PENDING`；默认企业的平台管理员因维护入口绕过该清单而不受影响。这不是要求运营人员拥有平台权限。

补齐以下精确 POST 入口：`ai-variant-lab/analyze-image`、`ai-variant-lab/batch-plan`、`ai-variant-lab/batch-run-images`、`ai-variant-lab/batch-resume-images`、`listing/generate-offer-id`。默认企业普通成员和客户企业使用同一套规则，仍要求有效企业、成员、订阅及运营权限；不按模块前缀开放其他高级接口。

图片批次从数据库保存的企业与创建人恢复独立上下文；每行、通道重试、服务商轮询、结果保存及延时唤醒重新检查权限。失败记录和运行标识固定企业，不能沿用调度线程的其他企业身份。已有服务商任务继续拉取时不重复扣生成额度。请求体不能覆盖计费企业或任务创建人。

公开参考图读取复用 DNS 地址校验及连接固定，拒绝私网、元数据地址和重定向越界，下载限制 20 MB；私有 AI 文件仍验证任务归属，历史公开刊登素材只允许真实 `public/uploads/listing-media` 目录中的文件。

新增回归覆盖完整 HTTP 登录后的普通运营入口、A/B/default 同编号规划与任务、错误企业引用、并发额度、持久任务恢复、运行中撤岗/撤销成员/订阅过期、服务商内部连续轮询撤权、错误清理与唤醒，以及四类货号占用来源隔离。所有付费 AI 请求使用网络替身，生产只读验证不会代替真实付费生成结果验收。

实际 MySQL 与服务测试：

- `tenant-ai-business-mysql.test.js`：同业务编号 A/B/default 隔离、并发额度、后台身份恢复、权限撤销、分析权限上下文。
- `tenant-listing-background-mysql.test.js`：批量保存草稿、重试与重启后身份恢复。
- `tenant-ai-media-mysql.test.js`：AI/裁图文件和 ZIP、私有水印、矩阵任务/文件/素材删除隔离。
- `tenant-listing-publish-mysql.test.js`：真实发布 SQL 和外部调用 spy，包含默认历史店铺、并发重试、错误店铺引用和执行前撤销权限。
- `tenant-listing-crud-mysql.test.js`：采集箱、模板、草稿和发布记录 CRUD；无图片的采集转模板仅模拟 OSS 已启用边界，后续实际 SQL 和草稿服务保持真实。
- `tenant-team-tasks-mysql.test.js`：任务、项目、候选、灵感、草稿关联、负责人、热力图、采购/发货统计与明细、迁移重复执行和撤销授权。
- `tenant-selection-products-mysql.test.js`：默认选品列表、汇总、筛选、人员和供应商关联、错误企业的发布任务引用。
- `tenant-reviews-actions-mysql.test.js`：实际服务和网络 spy 验证评价/活动店铺边界及持久清理身份。

这些测试验证企业数据边界和外部调用归属；没有向真实 Ozon、AI 供应商或 OSS 发送验收请求。生产冒烟与实际发布结果需在正式发布流程中单独验证。中央接口放行清单由统一的企业隔离入口维护，不应仅凭模块名前缀整体开放。

# FBP预测预警与正式申请分开

基线：从远端 release/2026.10.21-task-brand 的 c358708 开发，提交前合入最新 8292962 首页渐进加载改动。保留其他窗口的报表及历史修复。只在独立分支开发；上线需另行确认。

## 四个用途

|用途|性质|采购数量|
|---|---|---|
|FBS真实订单|必须|订单扣除本地实物和已分配在途后的缺口|
|本地保障|黄色建议|优先覆盖真实需求后，剩余本地保障缺口|
|FBP正式申请|必须|待审核申请及未被实物覆盖的确认锁定，扣除共享现货/在途|
|FBP预测预警|黄色建议|各店铺SKU预测，扣除官方可售、发往FBP在途、确认备货及同SKU待审核申请，再扣除本地剩余货源|

例如预测20件，确认8件申请后，只保留12件预测；完全确认后预测为0。跨店铺、跨SKU不互相抵扣，现货与采购在途只使用一次。FBS销量不抬高FBP安全目标；未同步或未知数据不按0处理。

FBP预测本来已参与底层总量，但此前与正式申请合成一类。现在共享库存工作流、采购理由及筛选、入库历史、流转图和反馈均拆成四类。无需变更数据库枚举：新增原因 flow_fbp_forecast，历史已采购记录不重写。

## 运营入口

保障补货中展示本地保障与FBP预测。即使本地货源足够、采购净缺口为0，平台仓仍缺货时也保留运营黄色调拨提醒。采购按钮保持禁用，避免重复购买；运营可查看分店SKU目标、可售、已有覆盖和待审核数量，然后选择套数创建FBP申请。

快速确认使用独立申请，不覆盖同日旧申请或顺带提交未勾选草稿；UUID及服务端指纹保证重试不重复创建。同一事务内缩减/关闭尚未采购的预测提醒，并审计旧量与剩余量；已采购、合并及历史记录保留。正式申请的库存不足部分进入必须采购，部分确认后的剩余预测仍黄色显示。

页面沿用现有表格和样式，不自动刷新用户正在阅读的列表。需要重建四类快照时升级 demand-v4-fbp-advisory；后台建立快照，未知期间不伪造0条需求。

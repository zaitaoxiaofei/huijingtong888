# 库存编号与查询兼容

当前库存编号是无补零的三段数字：`核心品名号-汽车品牌号-组内序号`，例如 `1-3-1`。示例中的数字不代表固定的品名或品牌映射。核心品名号 `0` 或品牌号 `0` 表示历史资料待核对；品牌号 `1` 表示已明确的通用适配。待核记录显示提示，完善身份资料后由编号规则重新发号。

`products.id` 仍是业务关联键，`products.code` 和已有 P 编码保持原语义。`products.inventory_number` 显示当前编号；`inventory_number_aliases.alias_number` 保存已发放旧号与原产品、企业的关联。修改核心品名或汽车品牌后，历史采购、订单、流水及 JSON 快照不靠改写旧编号建立关联。

| 搜索方式 | 输入示例 | 语义 |
| --- | --- | --- |
| `inventory_id` | `1-3-1`、旧两段号、P 编码 | 完整编号精确匹配，接受当前编号和历史别名 |
| `inventory_prefix` | `1-3` 或 `1-3-` | 当前编号属于指定核心品名与品牌的全部产品 |
| `inventory_prefix` | `1-3-1` | 当前编号以此开头，包含序号 1、10、11 等 |
| `auto` | 完整两段号或三段号 | 精确匹配，避免旧号变成新号分组搜索 |
| `auto` | `1-3-` | 按当前编号的品名与品牌边界搜索 |
| `auto` | 不完整旧号片段，如 `99-` | 保留页面综合关键词搜索，并搜索历史编号别名 |

前缀搜索仅查询当前编号。`1-3` 的分组前缀是 `1-3-`，不会匹配 `1-30-1` 或 `11-3-1`。旧版采购导出中的完整两段下划线形式（如 `1_23`）可按对应旧号 `1-23` 查询；新导出统一保留连字符。

所有入口保留各自企业、状态、店铺和业务条件。别名查询另外校验别名所属企业有效且与产品一致；历史 NULL 归属产品仅属于实际默认企业。普通产品页不会因旧号搜索显示隐藏产品；隐藏产品页继续使用自己的隐藏状态边界。采购或流水历史页沿用既有历史记录筛选。

库存预警和 FBP 缓存通过 SQL 解析匹配产品 ID，再与当前页面快照取交集，不给所有缓存行追加别名数组。编号排序依次使用品名号、品牌号、序号。采购 Excel 的编号单元格保存为文本，避免被电子表格解释成日期。

验证入口：`test/inventory-search-modes.test.js`、`test/inventory-number-consumer-mysql.test.js`、`test/inventory-common-search-mysql.test.js`、`test/inventory-receiving-common-search-mysql.test.js`。MySQL 测试只使用显式指定的独立 socket 和随机测试库。

# 企业 AI 积分执行规则

2026-11-10：所有有效企业空间恢复 AI 技能入口；默认企业也使用同一积分账本，不再沿用内部免费图片额度。企业成员、业务岗位、订阅、资源归属及精确路由权限仍需满足原有规则。

## 积分与赠送

- 1 积分 = ¥0.01；每张成功生成的文生图、图生图、模板图或裂变图片扣 10 积分。文本、视觉识别文本结果和流式文本免费；不使用旧的月度请求额度限制。
- 每个有效企业按北京时间自然月赠送 100 积分，未用完可累计；同企业的多个账号共享余额，不重复赠送。首次访问积分页或生成图片时补发当前月，后台每小时对有效订阅且有有效成员的企业巡检。不会为首次开户之前的月份补发历史赠送。
- 每月流水编号固定为 `monthly:YYYY-MM`，企业行锁、事务及企业内唯一流水约束共同防重。失败事务整体回滚，再次执行复用相同编号。
- 默认企业首次总积分补足到 `10000000000000000`，包括首次当月 100 积分；固定 `default-opening:20261110` 流水仅登记一次，之后按相同图片规则扣费，按自然月额外赠送 100。已有余额超过目标时不扣减，不在刷新、重启或重试时重置余额。
- 新企业自动初始化积分账户和固定图片价格，不自动充值现金。平台主动停用的账户不会被赠送任务重新启用。已有流水、任务或显式开通标记但钱包丢失时停止处理，不能重新开户覆盖历史余额。

## 精确金额

数据库沿用带非负检查的有符号 BIGINT。余额和流水计算使用 BigInt，专门的账本 SQL 将金额字段 CAST 为十进制字符串读取。API 对安全范围内积分保留数字，对超出 JavaScript 安全整数的余额使用十进制字符串，不输出 JSON BigInt。

前端使用 BigInt 格式化余额、人民币和流水；默认企业扣除 10 积分后的余额精确为 `9999999999999990`。单次人工充值及任务报价仍使用既有安全范围校验。

## 图片执行

- 每张图片拥有持久逻辑提交号。模板任务使用保存的 task_no，裂变使用 jobNo+itemNo，素材优化使用 item+slot，矩阵使用批次+店铺。HTTP 直接生成必须携带固定 Idempotency-Key。
- 服务端选择已启用图片通道，持久绑定供应商、模型、通道、地址及账号指纹。浏览器传入的密钥或 providerJob 地址不授予调用权限。
- 先预占积分，持久登记供应商尝试和回执，再查询或提交；真实本地图片通过大小、类型、像素解码、内容摘要及归属校验，保存私有结果后才扣款。
- 每次 1–3 张请求逐张记账。明确失败返还积分，部分成功只扣成功张数；裁切及复用已有图片不重复收费。批量结果保留合并下载包。
- 状态不明保留冻结，只核对原任务；不盲目重发或自动退款。已保存结果而结算中断时恢复校验原文件，不重复调用供应商。撤权、停用或企业切换后不能据旧回执启动新请求。
- 私有结果默认位于 `data/ai-credit-results`，禁止置于公开目录；ECS 使用共享私有目录。图片文件继续通过鉴权路由访问。

## 验证与上线

离线测试覆盖实际账本 SQL、64 位整数、自然月边界、多员工重复领取、事务回滚、默认余额扣费与重启、余额耗尽及丢失钱包保护；原图片适配器测试使用真实图片解码，不调用付费模型。测试 SQL 夹具将 MySQL 语法适配至独立内存 SQLite，不替代 MySQL 行锁验收。专用 MySQL socket 不可用时，对应测试明确跳过。

积分页面已用真实 Vue 组件和模拟数据验证普通企业余额、默认企业大整数显示及收费说明。生产部署、重启及默认余额入账须按 AGENTS.md 对具体发布版本单独批准，不能复用上一版本的审批。

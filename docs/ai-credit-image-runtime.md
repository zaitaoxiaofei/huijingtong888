# 企业 AI 积分：单张图片执行边界

本轮把既有积分账本接到单张 `generateImages` 业务。它是可拆分的服务端模块边界，尚不是已上线销售的完整 AI 积分产品。没有在生产开户、定价、充值或执行真实付费请求。

**当前交付门槛仍不允许对外开通付费 AI 账户。** 客户界面尚无报价确认、余额及冻结积分交互；文案、视觉和矩阵等完整业务尚未接收费；独立网关及收费私有文件备份恢复验收也未完成。默认企业继续按原内部模式日常使用。

## 业务范围

- 数据库实际 `slug=default` 的默认企业，或平台显式审阅并设置 `ai_internal_mode_reviewed=true` 的内部模式，保留原来的请求次数与图片流程。外部企业未开户时明确提示联系平台开通，不能因没有账户就使用内部额度；请求会话自称默认企业无效。
- 内部模式标记只供平台审阅，现有企业负责人 API 不接受或写入 `feature_flags_json`；测试中的 A/B 内部额度模式在 fixture 中明确设置，不是生产默认开通。
- 平台显式开户时同时写入企业 `feature_flags_json.ai_credits_opted_in=true`。已有账户即使停用，也不会退回内部额度。标记存在但账户丢失、表异常、余额不足、没有价格均停止执行。
- 当前收费能力为单张图生图/文生图，价格键为 `image.generate`。价格必须由平台显式创建；迁移不创建价格或账户。多张请求明确拒绝，后续应按稳定的逐张子任务保留顺序与部分成功。
- 文案、视觉识别、流式对话和直接调用底层图片的矩阵等入口，尚未迁移到积分执行器，积分企业调用时明确拒绝。普通内部企业的既有功能继续使用原规则。不能据此宣称外部企业的全套 AI 优化、裂变和矩阵已完成收费验收。

## 单图流程

1. 企业、原操作人和当前资源权限来自服务端上下文；当前岗位、订阅与成员仍按业务规则检查。
2. 持久 `ai_generation_tasks.task_no` 是逻辑提交编号，服务重启和重试继续使用原编号。裂变已有图片行可使用持久 `jobNo + itemNo`，不使用时间戳 `requestKey`。直接 HTTP 单图入口接受 `Idempotency-Key` 或显式 `idempotencyKey`；未提供时拒绝收费请求，不在服务端临时生成编号。
3. 服务端重新读取已启用通道，不使用请求体提供的密钥、模型、地址或 `providerJob.statusUrl`。原供应商、地址、通道、模型和账号指纹合成不可逆绑定摘要；上游账号变化后不查询旧回执。
4. 一个逻辑单图任务预占一次积分，提交前持久记录尝试。异步供应商回执先写钱包，再更新业务任务，随后才轮询。
5. 队列出队、每次轮询与实际供应商调用前重新检查权限及积分许可。停用积分账户或撤权不会借保存的 `runtimeConfig/providerJob` 绕过。
6. 成功必须有原任务所有权、真实本地文件、限定大小、有效格式和 Sharp 像素解码；写入并校验内容摘要后才保存私有结果和结算。只返回 HTTP 200、URL 或损坏图不能扣款。
7. 结果未知保持预占和 `provider_pending`，恢复只查询原回执。无回执、通道变化或原回执失效时不自动退款或重新提交。明确终止失败才释放积分。结果回放从持久结果读取，不重新调用供应商，图片被改动会报完整性错误。已存结果但结算中断的恢复必须调用适配器 `verifySavedResult` 重新核对文件摘要与像素，不能直接信任孤立结果清单。

必需提示词、单张数量、来源地址语法、data 图片像素和私有素材归属在预占前校验。这些可预知的输入错误不会先冻结积分。合法远程 URL 的临时可用性仍在实际下载时判断；这类错误目前保守保留待核对，后续应增加可复用的媒体预检，不能按模糊错误消息推断供应商未接单并退款。

## 持久化与部署

结果清单默认 `data/ai-credit-results`，可用 `AI_CREDIT_RESULT_ROOT` 指定受保护目录，禁止落在 `public`、`uploads` 或指向其内部的真实路径。正式发布把该目录连接到 ECS 共享私有目录；原生成图片仍通过鉴权的 `/api/ai/file/...` 访问。收费开通前必须完成私有结果与图片文件的备份、恢复和新版本回放验收。

新运行模块没有启动时自动迁移、开通账户或授予额度。后台恢复会复用持久业务身份和原任务编号；原账号被停用的未完成任务由平台按回执核对，而不是换一个操作人重新收费。

# 企业 AI 积分：图片成功计费

`generateImages` 使用逐张积分任务承接文生图、图生图、模板生图和裂变。它是可拆分的服务端模块边界，尚不是已上线销售的完整 AI 积分产品。没有在生产开户、定价、充值或执行真实付费请求。

**对外付费生成仍未开放。** 积分余额、冻结积分、充值与使用记录已有界面入口；报价确认、文案、视觉和矩阵等完整业务收费，以及收费私有文件恢复验收仍需后续完成。默认企业沿用现有 AI 配置。

## 2026-11-09 积分入口与技能暂停

- 非 `default` 空间的 AI 技能库保持可见但不可点击，直接地址同样受页面权限限制。HTTP 写入和供应商边界分别拦截；已排队的积分任务在冻结积分前拒绝执行。积分余额、已有内部审阅标记及平台身份均不自动解除此限制。
- 企业成员可从独立“AI积分”入口或会员中心查看本企业余额与流水；平台管理员在“企业与授权 → AI积分”中显式选择企业，管理账户并登记手工充值。默认企业不会被自动切换为积分模式。
- 开通账户、充值与读取余额均不会开放技能库，不自动赠送积分、不接线上扣款。充值沿用既有账本事务和企业内唯一收款编号，失败重试保留原编号；平台读取每次重新检查有效平台授权，不冒用客户成员身份。
- 页面请求按账号和企业限定，切换空间或退出后丢弃旧响应。日期统一显示北京时间。生产上线需按仓库发布规则单独批准。


## 业务范围

- 数据库实际 `slug=default` 的默认企业保留原来的请求次数与图片流程。非默认企业现统一暂停供应商调用；历史内部审阅标记不会豁免暂停规则。请求会话自称默认企业无效。
- 内部模式标记只供平台审阅，现有企业负责人 API 不接受或写入 `feature_flags_json`；测试中的 A/B 内部额度模式在 fixture 中明确设置，不是生产默认开通。
- 平台显式开户时同时写入企业 `feature_flags_json.ai_credits_opted_in=true`。已有账户即使停用，也不会退回内部额度。标记存在但账户丢失、表异常、余额不足、没有价格均停止执行。
- 图片价格键为 `image.generate`，统一 1 积分 = ¥0.01，每张成功图片扣 10 积分。平台显式开通积分账户时登记此价格；数据库迁移和普通生成不会自动开户或赠送余额。新图片任务拒绝不符合 10 积分的价格，历史任务保留原报价。
- 每次 1–3 张生成逐张使用稳定子任务，各自预占、保存、结算；明确失败的图片返还积分，部分成功按成功张数收费。多张图片合并为同一下载包，裁切衍生图不另收费。未知结果停止后续提交并保留预占，原任务重试先恢复已成功的子任务。
- 文案、视觉识别和文本流式请求不扣积分，仍检查技能暂停、当前身份和原有请求额度。矩阵 AI 相似主图使用统一图片执行器；素材优化按持久 item+slot 编号去重。普通水印、裁切和已有素材复用不调用生成服务，也不重复收费。
- 默认内部模式保留原工作方式，返回成功张数及按统一标准折算的金额，`chargedPoints=0`；它不是客户积分扣款或供应商真实账单。裂变成本摘要按已完成图片行重算，不把轮询和失败尝试当作成功图片。已开通积分模式的企业使用账本扣款，非 default 空间仍暂停。

## 单图流程

1. 企业、原操作人和当前资源权限来自服务端上下文；当前岗位、订阅与成员仍按业务规则检查。
2. 持久 `ai_generation_tasks.task_no` 是逻辑提交编号，服务重启和重试继续使用原编号。裂变已有图片行可使用持久 `jobNo + itemNo`，不使用时间戳 `requestKey`。直接 HTTP 单图入口接受 `Idempotency-Key` 或显式 `idempotencyKey`；未提供时拒绝收费请求，不在服务端临时生成编号。
3. 服务端重新读取已启用通道，不使用请求体提供的密钥、模型、地址或 `providerJob.statusUrl`。原供应商、地址、通道、模型和账号指纹合成不可逆绑定摘要；上游账号变化后不查询旧回执。
4. 一个逻辑单图任务预占一次积分，提交前持久记录尝试。异步供应商回执先写钱包，再更新业务任务，随后才轮询。
5. 队列出队、每次轮询与实际供应商调用前重新检查权限及积分许可。停用积分账户或撤权不会借保存的 `runtimeConfig/providerJob` 绕过。
6. 成功必须有原任务所有权、真实本地文件、限定大小、有效格式和 Sharp 像素解码；写入并校验内容摘要后才保存私有结果和结算。只返回 HTTP 200、URL 或损坏图不能扣款。
7. 结果未知保持预占和 `provider_pending`，恢复只查询原回执。无回执、通道变化或原回执失效时不自动退款或重新提交。明确终止失败才释放积分。结果回放从持久结果读取，不重新调用供应商，图片被改动会报完整性错误。已存结果但结算中断的恢复必须调用适配器 `verifySavedResult` 重新核对文件摘要与像素，不能直接信任孤立结果清单。

必需提示词、有效数量、来源地址语法、data 图片像素和私有素材归属在预占前校验。这些可预知的输入错误不会先冻结积分。合法远程 URL 的临时可用性仍在实际下载时判断；这类错误目前保守保留待核对，后续应增加可复用的媒体预检，不能按模糊错误消息推断供应商未接单并退款。

## 持久化与部署

结果清单默认 `data/ai-credit-results`，可用 `AI_CREDIT_RESULT_ROOT` 指定受保护目录，禁止落在 `public`、`uploads` 或指向其内部的真实路径。正式发布把该目录连接到 ECS 共享私有目录；原生成图片仍通过鉴权的 `/api/ai/file/...` 访问。收费开通前必须完成私有结果与图片文件的备份、恢复和新版本回放验收。

新运行模块没有启动时自动迁移、开通账户或授予额度。后台恢复会复用持久业务身份和原任务编号；原账号被停用的未完成任务由平台按回执核对，而不是换一个操作人重新收费。

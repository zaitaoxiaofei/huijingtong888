# 仓库库存补足与采购工作台

订单列表的采购信息新增“提醒采购”。有本企业仓库打包或库存管理权限的人员，可选择订单绑定的实物商品、填写整数件数和说明。组合商品按子产品选择；FBP 官方仓订单不发起本地补足。

提交会在一个事务中建立已提交的仓库采购申请，并给本企业有效 owner/admin 和采购岗位人员建立“库存补足”站内通知。申请保留提醒人、关联订单、商品、数量和说明。通知可进入采购工作台查看申请。请求重试复用 UUID；相同提交不会重复建单或通知，已提交标识配不同内容返回冲突。

提醒本身不调整实物、不建立订单库存分配、不调用 Ozon。订单编号仅作上下文，需求类型仍是仓库申请，不能重复算作真实订单需求。后续采购沿用已有确认、入库流程。收件人为空时明确提示配置岗位，通知落库失败时申请一起回滚。切换企业或岗位撤销后，服务端重新核实权限和记录归属。

采购工作台默认“全部待采购”，真实订单缺口在服务端分页前优先排列。顶部依次保留需求类型、关键词、供应商、采购负责人、采购平台和原有采购时间导出组件；时间范围继续用于已确认采购记录导出。查询、重置、采购选中、自由采购放在右侧，移除说明标题和额外结构筛选。

采购需求突出类型及件数；主表不展示需求原因，仓库申请详情仍保留说明与拒绝操作。近期销量保留 30 天和最近三周。库存列只保留共用库存流程明细入口，历史订单、历史采购和采购链接保留。

# 利润页二期设计

## 目标

利润页一期已经完成整体汇总、SKU 利润排行、产品利润排行三个 tab。二期不改利润计算口径，重点提升经营分析效率：快速筛选、按字段排序、导出复盘、后端分页承载大数据量，并补一个轻量店铺图表。

## 交互原则

- 三个 tab 继续共用顶部日期范围。
- 默认仍然进入整体利润汇总，本月为默认日期。
- 不提供未来月份快捷按钮。未来日期只能由用户手动输入自定义范围，用于特殊场景或测试。
- 二期功能优先做成每个 tab 内自己的工具栏，避免顶部查询栏变重。

## 1. 表头排序

### 适用范围

- 店铺利润明细表
- SKU 利润排行表
- 产品利润排行表

### 第一批排序字段

- 店铺表：销售额、利润、利润率、有效订单数、退货率、广告费、取消金额。
- SKU 表：利润、销售额、出单量、利润率、广告费、退货数、取消数。
- 产品表：利润、销售额、出单量、利润率、SKU 数、当前库存、退货数、取消数。

### UI

表头可排序列显示轻量箭头：

- 未排序：字段名
- 升序：字段名 ↑
- 降序：字段名 ↓

默认排序：

- 店铺表按销售额降序。
- SKU 表按利润降序。
- 产品表按利润降序。

### 状态设计

前端状态按 tab 独立保存：

- `profitSort.summary = { field: "revenue", direction: "desc" }`
- `profitSort.sku = { field: "profit", direction: "desc" }`
- `profitSort.product = { field: "profit", direction: "desc" }`

点击当前排序字段时切换 `desc -> asc -> desc`。切换排序后页码回到第 1 页。

## 2. 店铺筛选

### 适用范围

- SKU 利润排行
- 产品利润排行
- 店铺利润明细可保留“全部店铺”，也可以按单店铺查看。

### UI

在每个 tab 的表格标题右侧增加紧凑工具栏：

- 店铺筛选：全部店铺 / 店铺 A / 店铺 B
- 每页条数：10 / 30 / 50 / 100

产品利润排行里的“涉及店铺”如果选择单店铺，只展示该店铺贡献过订单的产品。

### 数据逻辑

一期可以前端筛选现有汇总数据：

- SKU 表按 `shop_id` 或 `shop_name` 过滤。
- 产品表如果后端已提供 `shop_breakdown` 明细，优先按明细过滤；如果只有字符串，先用包含匹配，后端分页阶段再补结构化字段。

## 3. 导出 Excel

### 导出入口

每个 tab 的工具栏右侧放“导出”按钮：

- 整体利润汇总：导出指标汇总 + 店铺利润明细。
- SKU 利润排行：导出当前日期范围、当前店铺筛选、当前排序下的全部 SKU 行。
- 产品利润排行：导出当前日期范围、当前店铺筛选、当前排序下的全部产品行。

### 文件命名

- `利润汇总_2026-05-01_2026-05-31.xlsx`
- `SKU利润排行_2026-05-01_2026-05-31.xlsx`
- `产品利润排行_2026-05-01_2026-05-31.xlsx`

### 第一版实现建议

先做前端导出 CSV，成本低、够用：

- UTF-8 BOM，避免 Excel 打开中文乱码。
- 金额保留 2 位。
- 百分比保留 2 位。

后续再升级为真正 XLSX，并支持多 sheet。

## 4. 后端分页

### 触发时机

当订单量、SKU 量、产品量继续增长后，前端一次拉全量利润汇总会变慢。建议在二期后半段把排行数据拆成独立接口。

### 接口设计

保留现有 `/api/profit-summary?from=&to=`，只返回：

- 顶部核心指标
- 店铺汇总
- 三个 tab 的数量统计

新增：

- `/api/profit-summary/shops?from=&to=&page=&pageSize=&sort=&direction=`
- `/api/profit-summary/skus?from=&to=&shopId=&page=&pageSize=&sort=&direction=`
- `/api/profit-summary/products?from=&to=&shopId=&page=&pageSize=&sort=&direction=`

返回结构统一：

```json
{
  "rows": [],
  "page": 1,
  "pageSize": 30,
  "total": 241,
  "totalPages": 9
}
```

### 前端兼容策略

先保留当前全量接口和前端分页逻辑，再逐个 tab 切到新接口。这样改动可控，不会一次性影响整个利润页。

## 5. 店铺图表增强

### 放置位置

整体利润汇总 tab 中，指标卡下面、店铺表上方，放一个可折叠的小图表区。默认展开高度 180px，不影响表格作为主视图。

### 图表内容

第一版图表只做一个“店铺利润柱状图”：

- 横轴：店铺
- 柱：利润
- 颜色：盈利为绿色，亏损为红色
- 鼠标悬停：显示销售额、利润、利润率、有效订单

### 后续增强

- 支持切换指标：利润 / 销售额 / 有效订单 / 退货率。
- 支持 Top 10 / Top 20 / 全部店铺。
- 支持和店铺筛选联动。

## 推荐落地顺序

1. 移除下月快捷入口，固定为“上月 / 本月 / 自定义查询”。
2. 加每个 tab 的工具栏：店铺筛选、每页条数、导出按钮位置先占好。
3. 做前端表头排序，排序后页码回到第一页。
4. 做前端店铺筛选。
5. 做 CSV 导出。
6. 加整体汇总里的店铺利润小图表。
7. 数据量变大后再拆后端分页接口。

## 验收标准

- 默认进入利润页时日期为当前自然月。
- 没有“下月”快捷按钮。
- 三个 tab 切换时日期范围不丢失。
- 排序、筛选、分页互相不挤压，切换 tab 后各自状态独立。
- 导出的行数与当前筛选条件一致，金额和百分比格式清楚。
- 后端分页上线后，大数据量下页面首屏仍能快速显示整体汇总。

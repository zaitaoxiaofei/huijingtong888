# 库存流转中心

入口：`/inventory/flow-center`。独立 Tab，不替换商品库存、库存预警、采购工作台和原 FBP 页面，不更新原产品的周期字段或原预警算法。

## 数据与数量

- 以本企业实物产品汇总关联店铺 SKU，复用原实物余额 SQL；订单已经记账但尚未真实发走时的校正保持原样。
- 安全目标不含真实未发订单。自由可配 = max(0, 实物 - 订单占用 - 已批准备货锁定 - 安全目标)。负实物保留并提示盘点。
- 本地保障至少7天，FBP保障至少15天。生产、本地运输及FBP运输周期可在新中心单独配置；FBP运输默认7天。
- 日期区间表示整体补货受影响时间，重叠日期只计算一次。当前产品设置可以覆盖默认周期；节假日沿用企业默认设置。
- 日销量使用北京完整自然日；本地历史用近7天，FBP需求用近14天。组合SKU显示时按组成件折算。
- 有FBP可售库存时，按现有可售天数与补货周期预测本地接替需求；尚未可售的在途不当作可售库存。历史订单不修改渠道归属。
- 官方库存未知时显示待同步，不当作0生成自动建议。FBP官方数量按SKU合计到实物，但补货逐SKU计算。
- 采购建议包含已有申请和已锁定数量的覆盖关系，不自动创建、修改或取消采购。采购在途只减少未来缺口，不增加现在可发出的实物。
- 需求向上取整到单件；FBP建议正数至少5件、不强制5的倍数。采购另外按起订倍数向上取整。

## 操作与权限

- 企业库存读取权限可查看；库存编辑权限可申请和保存新中心规则；仓库打包权限可锁定、发运、确认到仓、核实少发。
- 每次提交使用稳定提交标识，按店铺生成新的独立申请，不并入旧申请。申请人不能确认自己的备货。
- 确认前可调整数量；仓管只确认实际可提供的部分。确认后保存锁定版本，未采用部分不结转，下周期重新预测。
- 备货使用原有单据和库存流水，让两个入口共用实物账。新中心发运前重新核对锁定快照，其他入口修改过的单据会阻止发运，不能按过期版本扣货。
- 锁定和发运在数据库事务中执行，锁行并检查版本；重复发运拒绝，不重复扣减。到仓可以分批确认，但不会自动增加Ozon官方可售库存。
- 少发纠错仅适用于已核实货仍在本地，追加正向流水与核实原因；运输丢失不能补回本地。实发数不得小于已确认到仓数，异常到仓数需要先核实。
- Ozon同步独立请求真实接口；缺凭据、缺SKU或请求失败保留原快照并报错，不使用演示或缓存代替。成功的目标SKU按店铺事务更新FBP快照，不修改FBS虚拟库存。

## 本轮边界

- 组合SKU需求可读，备货写入仍使用原流程；新中心明确拒绝组合SKU写入，避免组成件重复出库。
- OGR预留概念，不实施供货预测或排序。原有订单、利润、定时任务及历史清理不变。
- 当前页筛选与计数只针对本页，全部产品数量单独显示。任务最近100条、审计最近200条，不宣称全历史统计。
- 未建立逐批采购到货时间模型；采购在途仅作数量覆盖。FBP接替保障采取保守预测，不承诺精确断货日。
- 未启用周一定时创建备货申请；推荐随读取更新，运营人工确认。未实施采购、发运自动化。

## 验证与发布

新规则、企业隔离、真实订单用量、部分锁定、重复发运、少发纠错、分批到仓、规则版本冲突，以及原库存采购回归分别验证。测试只连接禁用TCP的独立MySQL临时库。发布从已合并并推送的release精确提交构建，遵循候选预热和回滚流程；生产部署仍需具体版本确认。

正式发布通过 `migrate-inventory-flow-center.mjs` 只读检查三表；缺表进入发布计划并触发备份，备份后增量创建、核对列及企业唯一键，再启动候选。无需开启全库维护或运行完整初始化，不改写历史业务记录；已有不兼容结构会阻止发布。

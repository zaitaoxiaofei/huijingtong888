# FBP 库存视角与标签打印

- 库存视角按完整筛选结果加载、按库存 ID 聚合再分页，不再使用左侧展开箭头。右侧固定“查看明细”“打印标签”“采购申请”。
- 主表展示当前本地可用推算、采购在途、FBP 待入仓、最近实际发货数量／北京时间、本次备货数量。待发货页突出“本次备货”，其他状态标为“筛选备货合计”，取消数量不进入合计。
- 本地可用从当前库存流水计算，剔除 FBP 预留与释放这种非实物流水，再扣除本筛选范围以外的待发 FBP 计划。采购在途只统计 pending_arrival 收货记录；FBP 待入仓是已发货数量减已入仓数量，两种在途不能混用。负账面按 0 展示，以实盘为准。
- 商品事实每页批量读取，不逐行查询。历史发货按实际发货时间最近的一批统计；同一时刻的同库存发货合并显示。
- 查看明细弹框保留店铺、SKU、原单、最终数量、调整记录、删除入口；修改有旧数量校验，防止覆盖他人的数量调整。缺货可在明确确认后保存计划，但并不增加库存或表示已能发货。待发货单真正发出时使用最终调整数量，而不是原审核数量。已发／已入仓的计划调整只留痕，不倒改实际出入库。
- 每条原始备货明细应打数量 = 正数备货数量 + 2；零数量及已取消不打印。关联汇总仍按原明细分别计算，不同店铺标签不混用。默认本次打印 = 应打减去已确认张数；已完成后补打须手动填写。单个 SKU 每批最多 999 张，超过请分批。
- 打印生成不记成功；操作人按 SKU 确认实际成功张数。部分失败只重试未确认项，使用原 request_key 防重复。数量变化后重新计算未完成张数。
- fbp_replenishment_print_records 追加保存每次确认数量、当时备货数量、SKU／店铺、首次或补打、操作人、时间。累计数量不覆盖旧值。旧系统只有最近一次打印数：保留此基数，不捏造旧的逐次历史。删除备货明细不删除已留存的打印审计。
- 运营视角同步累计／应打数量；库存导出包含在途、历史发货和分 SKU 打印数量。

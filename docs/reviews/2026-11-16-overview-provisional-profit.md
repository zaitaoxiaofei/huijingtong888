# 经营总览净利润与月份状态修复

基线：远程 release/2026.10.21-task-brand 的 b2810d25a36405db8b0587333f40f1e03ac48b6d。

## 原因

退款状态已到达但退款收入凭证未匹配时，既有保护逻辑令 net_profit=null。年表任一月份为空，就把累计值也显示成“待补”。线上只读核查中1—10月均受此影响，8月40单、10月5单；不是工资恢复失败。

## 本次变更

- 保持 net_profit=null 的确认语义，另加 estimated_net_profit。按现有营业额减已记录成本、工资、平台外费用、提现费和已归属图片费用计算；不重复减固定GPT费用。AI成本未知时两者仍为空。
- 经营总览和月度账单采用同一显示投影，显示暂估金额及待核对订单数；年度可以汇总暂估月份，仍有真正缺失值则不强行补零。
- 过去月份只有当前收入对账、费用对账和订单结算计数均无待核对且净利润可确定，才标“已完成”。当月为进行中；其余为待核对。这里的完成是当前已采集数据的经营对账状态，不是税务关账或全部发票齐备。
- 新增有界、15秒的服务进程内汇总缓存，复用并发请求。先确认租户及公司权限，再读取缓存。相关mysql写入及事务提交后清除缓存，回滚不清除；旧请求不能回填新版本。强制刷新refresh=1绕过缓存。清理连接池同时清缓存，防止跨数据库复用。
- 缓存不是持久化的月结快照：重启、过期或相关写入后仍需重算；绕过共享SQL封装的外部写入最多受15秒TTL影响。首次冷加载仍需真实计算。没有承诺“已完成月份永久不重算”。

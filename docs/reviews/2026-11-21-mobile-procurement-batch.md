# 手机采购刷新与批量登记

本次开发基于最新远端 `release/2026.10.21-task-brand` 的 `dfb57910`。只读检查生产版本仍为 `6e6c5e38`，最新 release 的手机刷新修复尚未上线。

## 原因与处理

- 旧手机页面只读取一次需求快照，收到后台计算中后没有继续获取完成结果。反复刷新可能再次要求全量核算，切换页面后的重新读取才偶然显示完成结果。这个现象不能单独认定为服务器性能不足。
- 保留并验证最新 release 已有的保存后刷新、`poll_snapshot=1` 只读轮询、失败/等待超时提示。轮询不再次启动核算；切换页面、账号或企业后旧响应不能覆盖当前页面。
- 登记采购、必须采购、保障补货页新增商品多选、选择本页与批量登记入口，每次最多50项。选择只打开采购表，不自动提交，逐项填写实际数量、货款与运费后通过原有批量接口一次提交。
- 过期或仍在核算的建议不预填采购数量，保留手工确认实际采购数的保护。翻页、查询、刷新、切页、切企业和采购权限撤销会清理选择；后台轮询只保留仍有效的所选商品。
- 批量表单等待全部所选商品及套装配件读取完成后才允许提交。读取失败时明确阻止提交部分商品并提供重新读取入口；关闭、重开或切企业后旧读取不能追加到新表单。
- 保留原有批量验收入库、到货提醒、实物到货及库存核对流程。仓库人员可访问共享收货页面，但不会获得采购登记权限。

## 本地验证

- 快照、增量核算、工作区读取、手机采购选择与共享收货回归测试。
- 浏览器使用真实 Vue 组件和合成 API 数据，地址固定为本地 `8788`；验证核算完成自动更新、手动刷新只发起一次核算、失败提示、批量实际采购、相同请求重试、切换页面/企业，以及原有批量收货。
- 检查375、390、430宽度与390×480矮屏：列表无横向溢出，实际采购表单可滚动，确认按钮保持可见。
- 前端正常构建、安全检查、UTF-8与SQL绑定检查通过。生产环境配置只读预检通过，没有复制生产凭据。

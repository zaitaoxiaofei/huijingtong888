# 五企业 HTTP 混合验收与积分接口接线

日期：2026-10-24（北京时间）。这份记录说明本地测试证据及其适用范围。本轮启动并停止了本地 `8788` 临时测试服务；未部署 ECS、未重启生产服务、未读写生产业务数据、未调用真实 Ozon 或收费 AI。

## 业务结论

默认企业加四个独立企业、30 个登录身份同时操作的脚本场景通过。订单、草稿、OGL 已保存申请及详情均返回实际业务行，订单统计每企业准确为一万单，未混入其他企业；五个普通运营发起的后台商品同步同时运行，结果各写入本企业店铺。

新积分的八个 HTTP 接口已经在完整服务中接通，企业 A/B 的余额、流水分页和任务隔离通过；企业负责人、运营、仓库成员均不能充值、改价或核对扣费，撤销平台授权后旧会话立即拒绝管理操作。

这是代表性本地短时负载与接口边界验收，不能据此承诺 ECS 可承载 30 个真实在线用户，也不能把钱包接线视作所有 AI 生成入口已经完成收费迁移。

## 数据、环境与操作

- 独立 MySQL 命名管道实例，TCP 关闭；每轮随机建库，结束后仅删除该测试库。积分 schema 通过显式运行 `scripts/migrate-ai-credits.mjs --database=<随机库> --mysql-admin-socket=<测试管道> --apply` 建立，没有让读取接口隐式迁移。
- Windows 本机：16 个逻辑 CPU、约 31.9 GiB 内存，应用和 MySQL 同机；应用连接池上限 10、等待队列上限 100。没有在 ECS 同规格环境测量，磁盘、CPU、内存、系统及数据库连接方式都不能直接等同于线上。
- 五企业、十店铺；每企业一负责人、三运营、一采购、一仓库，共 30 个独立登录身份；另设独立平台管理身份供权限校验。默认企业包含历史 NULL 店铺归属路径。
- 总计五万订单、五万明细、五万官方 raw（每条约 1 KiB 附加原文），覆盖 80 天和五种订单状态；500 个库存产品、500 条 SKU 映射、500 条开账库存流水；五千草稿，每条有约 2 KiB 人工事实；五个 OGL 已保存申请和 100 个本地匹配成员。
- 通过实际 HTTP 发起五个普通运营的商品同步任务，使用真实鉴权、任务执行器、Ozon SDK 和持久化代码。只有供应商响应被替换：每次模拟 80ms，分页 100 条，每店铺 800 个商品，总计落库四千条。未启用真实图片下载、AI 生成或外部发布。
- 测量前协调同机其他工作暂停重 SQL 和构建。先各企业首次访问业务接口，再以 30 个脚本身份、每人六次顺序读取、每次 50–90ms 间隔混合操作；另外五个负责人各查询一次订单统计。
- 所有五个同步任务在混合阶段开始时均在运行，约 1.394 秒前台混合窗口内实际发生 43 次供应商替身调用；整个后台流程有 885 次调用。该短窗口没有覆盖持续数小时的排队、内存增长或任务积压。

“首次访问”指应用启动后该企业首次请求，不是清空 MySQL 缓冲池或冷磁盘：建数和服务初始化已经访问数据库。冷启动、首次请求、热缓存不能混为一种结果。

## 八个积分 HTTP 接口

| 接口 | 实际校验 |
| --- | --- |
| `GET /api/ai-credits/wallet` | 未登录拒绝；伪造企业查询参数仍只返回当前企业余额；响应禁止缓存 |
| `GET /api/ai-credits/entries` | 每页两条、游标下一页一条，无重复、无其他企业充值原因 |
| `GET /api/ai-credits/audit` | 充值及未知结果核对后账目仍一致 |
| `GET /api/ai-credits/tasks/:id` | 本企业任务可读，企业 B 读取企业 A 任务返回 404，伪造企业参数无效 |
| `POST /api/platform/ai-credits/accounts` | 平台明确开通；普通企业岗位拒绝；平台授权撤销后拒绝 |
| `POST /api/platform/ai-credits/prices` | 平台建立价格版本；普通企业岗位及撤权后的旧平台会话拒绝 |
| `POST /api/platform/ai-credits/recharges` | 三企业各三笔明确充值；普通企业岗位及撤权后的旧平台会话拒绝 |
| `POST /api/platform/ai-credits/reconcile` | 本地账本创建未知结果任务后，平台核对为零成功并释放冻结；普通岗位拒绝 |

平台专属账号撤销唯一授权后，整会话可能失效而返回 401；仍有有效会话但无平台能力时返回 403。两者都没有执行管理写入。本轮没有发现新积分路由接线问题。任务属于企业，并没有承诺同企业成员之间互相隐藏任务。

## 复现与后续

测试入口：`test/tenant-pilot-capacity-credits-http-mysql.test.js`。确认 `8788` 未被其他工作占用，设置 `TENANT_TEST_MYSQL_SOCKET` 为已关闭 TCP 的独立测试 MySQL 管道，再运行 `node --test test/tenant-pilot-capacity-credits-http-mysql.test.js`。默认就是上述规模；缩小环境变量只供调试，不能引用为同规模容量结果。

证据输出：`.verification/pilot-capacity-credits-http-report.json` 保存各请求样本、P50/P95、错误/繁忙比例、数据规模、任务重叠时间和环境；同目录的 `pilot-capacity-credits-http-full.log` 为 4/4、零跳过结果，`pilot-capacity-credits-http-child.log` 为测试子服务诊断。报告不包含登录密码、会话令牌或供应商密钥。

还需在接近 ECS 的资源限制下做更长时间的稳定负载，加入真实分布的较大草稿、历史/财务数据、真实媒体处理和任务失败积压；AI 生成收费链、外部商品图片/数量和 OGL 标签的真实业务结果应单独验收。当前结果不能替代这些业务闭环，也没有据此删除任何存量数据或修改生产配置。

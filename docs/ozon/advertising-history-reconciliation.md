# Ozon 广告历史对账

## 当前口径

- 权威币种为 RUB。
- 广告统计通过 Ozon Performance API 的活动统计报表获取，并按北京时间自然日、自然月汇总。
- `ozon_ad_sku_daily` 是活动商品明细，不应仅凭其中的 `ozon_performance_pending` 行数判断历史月份完整。
- 历史核准必须同时覆盖活动目录、报表返回状态和金额差额。

## 活动发现

历史补数使用当前活动接口、`ozon_ad_campaign_catalog` 历史活动目录，以及 `ozon_ad_sku_daily` 已出现过的活动 ID 的并集。即使活动以后停止、归档或不再出现在当前列表中，历史活动 ID 仍可继续参与补数。

## 审计和修复接口

- `GET /api/advertising/history/audit?from=YYYY-MM-DD&to=YYYY-MM-DD`
- `POST /api/advertising/history/repair`

实际补数请求示例：

```json
{
  "from": "2026-05-01",
  "to": "2026-05-31",
  "apply": true,
  "shop_ids": [4],
  "campaign_cursor": 0,
  "max_campaigns_per_shop": 1
}
```

保护规则：

- 默认只审计，并排除北京时间当天。
- 实际修复每次只能指定一个店铺，默认每批只处理一个活动。
- Ozon 报表未生成时不覆盖现有金额。
- 历史核准状态独立记录在 `ozon_ad_history_reconciliation`，不能用普通 pending 行数替代。

## 已知限制

Ozon 历史活动报表可能超过 10 分钟仍未生成。UUID 持久化恢复已在下方本地批次实现，部署前线上仍只能使用请求内的 UUID；本批不替代现有活动游标和分批调度策略。

## 本地验证

仅使用专用本地端口 `8788`。不得自动操作 `8787` 或 `8087`。

## 2026-11-12：广告查询限流保护（已部署）

- 广告 GET 查询按店铺排队；HTTP 429 保留状态码和 `Retry-After`，单次查询最多重试两次。重试前重新验证企业、店铺和操作人权限。
- 广告改价、预算、启停和报表创建不进入 GET 自动重试队列；报表创建原有的显式配额等待会尊重 `Retry-After`，额度耗尽不切换接口继续创建。
- 活动目录和商品设置读取中途限流时明确失败，不把部分目录或空商品设置作为完整结果。报表轮询耗尽配额时停止本次轮询并保留原报表 UUID 错误上下文，已有统计金额不按空结果覆盖。
- 本批不修改投放参数、报表金额口径或订单利润，不新增表。PR #188 已合并；发布提交 `199b26a29ff1e4158907e77e92bf2d9574c3428b`，ECS 版本 `2026.11.12-advertising-read-199b26a`，只读登录、版本及服务就绪检查通过。

## 2026-11-12：UUID 持久化与跨重启恢复（本地待上线）

- 复用 `system_settings` 保存每个企业、店铺、广告凭据版本、活动集合和日期范围对应的创建占位、UUID、原始查询范围及下次可轮询时间。不保存 token、明文密钥或整份报表，无需表结构迁移。
- 创建之前通过短事务锁定店铺和领取记录；同一查询只有一个创建名额。进程退出后，已领取但尚无回执的请求不会靠过期计时器自动重发，避免“超时但 Ozon 已受理”导致重复创建。
- 常规后台广告同步和手动同步会优先恢复所选活动的原任务。跨天后仍按原报表日期入库；恢复旧范围的这轮明确返回 `report_pending`，当前范围交由下一轮调度补齐。调整活动批次大小也不会拆掉一个已创建报表、再次创建子报表。
- 429 持久保存 UUID 和 `Retry-After`；至少等待一分钟再恢复。暂时 404、仅有 ready 状态却没有报表行容器、轮询超时和取消都不能触发替代报表创建，也不能把未知结果当成零金额。
- 报表读取完成后保留 UUID，只有解析、每日统计写入及当前权限复核都成功后才清除。写入失败或写入后进程退出仍可重复读取原报表，沿用现有每日统计自然键 upsert；未声称跨整个导入流程实现一次且仅一次。
- 每次数据库操作、提供方请求和恢复过程重新验证企业/成员/店铺及广告凭据；更换密钥后不使用旧授权下的 UUID。新凭据使用独立命名空间，旧凭据记录保留供授权后审查，不自动跨凭据恢复。
- 边界：需要现有广告同步调度启用且店铺凭据有效；不会在启动时绕过权限直接发请求。每次最多读取 20 条待恢复记录。创建请求网络失败、5xx 或无 UUID 时保留“创建结果待确认”，需要人工确认后再处理，不提供自动清空不确定任务或推测 Ozon 报表过期的逻辑。
- 本地验证涵盖独立 Node 进程保存/恢复、并发领取、旧回调保护、跨企业和密钥隔离、限流等待、跨天恢复，以及故意让真实 MySQL 导入失败后复用同一个 UUID 再次入库。48 项单元/逻辑测试、21 项隔离 MySQL 测试（共 69 项，无跳过）、前端构建、UTF-8 与 SQL 绑定检查通过。所有 Ozon 请求均为测试替身，未变更真实广告投放。新批次未公开发布或部署。

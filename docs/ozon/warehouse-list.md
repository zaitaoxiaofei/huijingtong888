# Ozon 仓库列表兼容修复

2026-11-04，基于发布分支 `b394600a8ec9fae14575431518784effba903169`。本修复独立于密钥预警 PR #96。

## 影响与行为

`GET /api/online-products/warehouses` 用于在线商品页批量更新库存时选择 Ozon FBS/rFBS 仓库。它不是 FBO 供货单接口，也不代替 FBP 实体库存同步；不更改仓库身份、SKU 绑定、库存数量或历史利润。

- 调用 `POST /v2/warehouse/list`，每次传 `limit: 200` 和 `cursor`；根据布尔 `has_next` 读完，不以短页或过滤后的数量判断结束。
- 保留现有归档/停用仓库过滤。要求每条原始仓库有可确认的编号；重复编号、缺失结构、无法推进的游标、空中间页或超过分页上限明确报错，不返回已读取的一部分仓库。
- 删除已经过迁移日期的 v1 回退。403 不切换版本；429 和网络错误沿用通用客户端的有界重试及 Retry-After 行为。
- 每次请求、每次响应后重新读取当前企业的店铺。停用、身份归属变化、授权被替换时停止，避免跨店铺或跨凭据混合分页。取消信号从路由传到外部请求。
- 缺少真实凭据的业务店铺不能获得演示仓库；直接说明应到企业店铺配置 Client ID/API Key。
- 页面只缓存完整成功列表，最多一分钟。强制刷新先移除旧缓存；失败清除可提交的仓库选择并持续显示错误，不能再次读出失败刷新前的缓存。成功空列表与失败分别提示。较旧、跨店铺、跨登录范围和已离开页面的响应不能覆盖当前列表；未核查完整时禁止提交库存更新。
- 只读探测脚本的 warehouse-v2 请求也补齐参数；探测成功只表示一次响应，不证明多页完整或执行过库存写入。

## 验证

覆盖短页多页、归档整页、空终页、缺字段、重复游标/仓库、第二页 403、取消、逐页授权刷新、失败刷新清缓存、切换店铺及同店铺乱序响应；沿用商品和企业隔离回归。

另用关闭 TCP 的专用临时 MySQL 跑真实业务读取函数，验证本企业完整分页、另一企业/已停用/无凭据店铺在请求前拒绝，以及在途换钥后不会再请求下一页。供应商接口全部模拟，没有读取真实店铺凭据或写入生产。

本阶段不包含 FBO 供货单和评价同步，尚未部署 ECS。后续部署须以确切合并发布提交构建，并按现有规则取得明确批准。

官方契约：[WarehouseListV2](https://docs.ozon.ru/api/seller/#operation/WarehouseListV2)。当前 schema 中 limit 为必填、最大 200；示例中的占位值不用于实现。

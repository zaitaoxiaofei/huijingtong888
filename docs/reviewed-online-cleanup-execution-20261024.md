## 生产维护范围

仅 `online_products` 需要严格影子表重建。工具按该表实际分配空间计算预算：表空间估计的四倍加 1 GiB 运行余量；演练约需 1.43 GB，生产只读时空闲约 11.9 GB，不要求十五表重建或新的整库备份。

现有服务没有可证明完整停写的在线维护开关。备用进程即使关闭定时任务，仍可能接收写请求；仅数据库只读、停主进程或命名锁均不够。现场最近两次退出约 25 秒、冷启动约 64–67 秒；因此不能把 7 秒的数据库演练称为 7 秒服务中断。预计窗口约 3–5 分钟，以真实恢复就绪为准。

维护执行须：

1. 持有正式发布锁，重新核对当前版本、主备进程身份和运维单元，保存原始状态。
2. 停止运维 timer/oneshot，关闭事件调度；停掉主备应用 writer，并确认无项目写进程、应用连接或活动事务。数据库只读仅作为附加防线。
3. 在停写状态重新生成最终原生证据；比较全部 16 个业务身份、28 条引用及保护项。新增引用或身份变化不能静默扩大授权。

6. 验收通过后恢复原先的数据库设置、应用和 timer，检查就绪、当前版本及订单、草稿、OGL 的业务读取。

失败时读取本轮匹配日志并在停写状态恢复，不能盲目重跑相同修复 ID，也不能未知阶段自动恢复写入。旧十五表维护脚本绑定旧提交、旧修复 ID，禁止直接执行。

## 运维兼容经验

- `systemctl show` 对 timer 可不返回 `MainPID`；只对 timer 将缺失值视为无进程，不能降低 service 的 PID/起始 ticks 检查。
- 本机 MySQL 8.4 支持的 `--no-login-paths` 在本次 ECS MySQL 8.0 客户端不支持；维护前在目标机确认客户端支持参数，不能仅依赖本机演练。
- 后台启动返回 PID 后，进程可能尚未完成 exec。保持完整 UID、cwd、exe、参数和环境标记校验，短暂等待同一进程满足全部条件，再判定失败；不放宽身份检查。
- 正常退出期间保持数据库可写，完成主备进程、连接、事务排空后再设置只读附加防线，避免外部请求回执在排空期间保存失败。
- SHOW CREATE 的字符集冗余显示差异必须逐项确认列、索引和表元数据相同；不能采用宽泛去除 DDL 内容的方式掩盖结构差异。

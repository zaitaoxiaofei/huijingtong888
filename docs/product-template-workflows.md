# 产品模板工作流

入口：AI 技能库 → 产品模板工作流（`/product-workflows`）。顶部按日常使用顺序排列：**已有流程 → 新建／编辑流程 → 生产任务／待人工检查 → 生产结果**。

## 工程师配置

1. 第一项导入本企业已有上架类目模板，沿用真实 Ozon 类目、商品类型和属性定义。
2. 必填类目属性自动加入；其他属性可从左侧拖入。配置默认值以及填写范围：商品公共资料只填一次，变体属性在表格中分别填写。字典属性通过已有接口搜索并选择，只将选择值写入上架属性。
3. 配置产品字段、参考图槽位、主图、人工确认、详情分镜、文案、价格与包装参数节点。参考图区分真实产品、适配对象、视觉风格；钥匙图和风格图通常设为商品共用，产品主图设为逐变体上传。
4. 详情图节点可复制，所有变体遵循同一分镜提示词。生产时可以对单个变体添加分镜补充要求，不改动原流程。
5. 保存到企业流程库，或导出 `.workflow.json`。导入文件后需重新绑定本企业类目模板。钥匙壳示例在 `docs/examples/key-case.workflow.json`。

## 运营生产

1. 首页选已有流程并点击使用，打开统一的材料表单。
2. 商品公共资料和共同参考图只填写一次。在批量上传区或任一产品卡片的主图位，一次选择或拖入多张 JPG、PNG、WEBP 图片，按顺序自动建立产品卡片；也可从文件夹导入或直接添加空卡片，每批最多 20 件。已有空主图卡片优先复用，保留其备注、属性、补充角度与特殊要求；多选图片不放入同件产品的角度槽。
3. 提交后任务在服务器后台推进，页面可以关闭。所有变体各自生成主图，到人工确认节点暂停；其他不依赖该确认的节点仍可执行。
4. 任务页显示排队、生成、待人工检查、失败。进入预览确认对应变体主图后，后台自动继续详情和文案，无需逐节点点击继续。
5. 检查整套图片、文案与属性，可修改文案或重生成节点。默认一次提交为每件产品建立独立任务，检查通过后各生成一份操作箱草稿，进入生产结果。只有在“更多设置”勾选合并时，才生成一份包含全部变体的草稿；人工检查和自动审批仍遵循原模板配置。
6. 在结果页查看完整产出、打开现有操作箱编辑器，选择店铺、补齐库存等上架要求并提交。工作流本身不会跳过最终人工确认自动发布到店铺。

## 持久化与执行

- `schemaVersion: 1` 的通用节点协议，品类是数据，不参与执行分支。新增可选的 `scope`、类目属性节点和变体 `promptOverrides`，旧文件可导入后重新绑定类目。
- 依赖必须指向前序节点，拒绝重复 ID、前向引用和环路。首版不含条件、循环和任意脚本。
- `product_workflow_documents` 保存企业隔离的模板、生产快照、材料、类目模板快照、结果和版本。生产提交后锁定输入与类目归属。
- `product_workflow_jobs` 保存后台状态和 90 秒租约。领取任务使用行锁与 `SKIP LOCKED`，写入检查租约和文档版本，避免多个实例同时推进同一任务。服务器启动恢复队列，失效租约到期后可继续。
- 每次后台推进重新核实成员、企业订阅及运营权限；AI 提交前再次核实租约和授权。只通过既有 AI 持久任务接口调用供应商。
- AI 提交前保存意图和确定的任务编号。服务中断后先按原编号查回；结果未知时不自动另建任务，人工恢复仍使用同一编号，数据库唯一键阻止重复提交。
- 人工确认和文案编辑通过服务端动作接口进行，后台任务不能由浏览器整体覆盖。修改输入需创建新生产任务。
- 公共输入在创建时展开为独立变体快照；每个变体保留自己的产品图片、属性和分镜补充要求，不自动共用不同变体的成图。
- 重生成会清除依赖该节点的结果；文案修改同样清除依赖它的后续结果。最终导入要求全部生成内容和人工节点通过检查。
- 导入先记录意图，正常重复调用返回同一草稿。中断后按企业和工作流标识核对已有草稿，结果不唯一时阻止重复创建。
- 多变体走完整草稿保存路径，不继承类目模板的旧图或 SKU 身份。上架类目模板分类变更会阻止旧任务导入。
- 模板维护和生产均使用现有企业运营权限，尚未新增独立的模板工程师岗位。

## 验证边界

测试覆盖公共资料与变体隔离、类目属性映射、分镜覆盖、后台推进、人工暂停、重启恢复与避免重复提交，以及原有上架工作流。浏览器验收使用模拟服务和成图，不产生付费 AI 请求。真实 MySQL 迁移、实例租约竞争、供应商出图质量和最终店铺上架仍需在配置好的测试环境联调。

生产部署继续遵循 AGENTS.md：最新远端 release 基线、完整验证后合并、从精确合并提交构建；ECS 部署须另获明确批准。

### 自由字段配置

导入类目模板只加载字段库，不自动加入平台必填属性。工程师按需搜索、拖入或点击字段，并独立设置“本流程要求填写”。未配置的平台必填属性不会阻止生成图片与文案，仍由操作箱原有上架检查处理。

配置区按属性、图片、文案、上架参数分组，底层仍保留可复用节点与前序依赖。属性值来源可选择使用者填写（公共或逐变体）、工程师固定预填，或对非字典属性映射已生成的标题、标签、简介、富文本。工程师固定值在后台展开变体时强制使用模板值。生成结果映射不作为生成前材料要求。

字典属性仅使用类目数据和既有字典检索接口的选项，不提供任意新建选项；后台提交时重新核实选中 ID 并采用服务端标签。图片节点可设置上传数量、逐张用途及公共／变体范围。文案节点可拆成标题、标签、简介分别编辑提示词。JSON 富文本默认按各变体的已检查主图和简介组装为 Ozon raShowcase 内容，可在文案区域关闭。字典属性的自动识别暂未开放；例如汽车品牌可先交由使用者从真实字典中选择。

### 按模板字段绑定来源（本轮调整）

编辑器只暴露三类来源：人工输入、AI 文本、AI 图片。上架类目模板是输出目标，不再要求把每个属性都作为顺序流程节点。左侧可添加来源并选择模板字段，中间编辑当前节点及字段绑定，右侧拖入已有节点输出。可将同一输出复用到多个字段；图片集按绑定顺序装配，富文本接受多张图片和多个文本输出。字段仍服从数据类型：图片进入图片集或富文本，字典属性必须精确匹配服务端类目选项。

便携 JSON 增加 `bindings`：每个键对应标准上架字段或 `attribute_<id>`，其 `sources` 顺序保存 `{nodeId, output}`。节点依赖仍由 `inputs` 表示，执行前验证引用顺序；字段绑定是最终装配，不参与节点拓扑。没有 bindings 的已运行任务沿用旧语义；编辑旧模板时生成默认绑定，不修改旧任务快照。新的通用文本节点使用现有持久 AI 任务与租户上下文，按自身提示词生成，不套用整组电商文案的标签数量／字数限制。

生产默认按产品独立生成，无需先切换模式；单件也是一个独立任务。“更多设置”保留同一商品合并多变体选项。批量模式每行资料复用相同定义与共用材料，但各自保存独立任务快照、结果和草稿。提交前校验整批材料；每行客户端 UUID 作为企业内任务创建标识，网络中断重试及并发重复请求不会新建另一条相同任务。已提交行冻结，部分成功后只提交剩余行。本轮每批最多 20 行。不同批次的商品仍需各自提供事实材料，不能把不同适配对象误设为整批共用。

所有已保存企业模板、钥匙壳预设和默认示例共用同一生产表单，不修改已存模板的节点、风格、类目或审批规则。导入先对整批文件校验容量；超过上限时不上传任何文件。单个文件上传失败不清除成功图片，也不停止后续图片，失败文件可单独补传。同件产品的背面、细节图继续在自己的补充图片位逐张上传，不拆成其他产品。

生产表单按产品逐行紧凑展示，备注、产品主图与补充角度、必填资料和操作放在同行。选填属性与分镜要求从该行“补充资料”展开；产品列表限制高度并独立滚动，5件与20件不会继续撑长整张表单。共用信息并排填写，钥匙上传使用紧凑图片位；完整用途、图片预览、资料库候选及保存入口仍可访问。紧凑样式仅用于生产表单，不改变工程师编辑器或模板执行规则。

模板可保存一个或多个默认店铺 ID。进入操作箱时，仅恢复当前企业店铺列表中仍有效的 ID；实际发布继续走原有店铺权限、属性及媒体检查和人工确认，不自动发布。

### 钥匙壳首个生产目的

选择本企业真实类目后，点击“一键配置钥匙壳生产流程”。默认输出一张主图与五张详情：适配原钥匙／按键特写（钥匙壳小比例陪衬）、材质外观与已确认卖点、日常防护及按键操作、对应车型场景、高端礼盒包装。包装声明取自用户确认的事实；没有确认时不自动宣传礼盒。未确认具体材质时只描述碳纹外观。

所有文本与图片调用都走 ERP 已有服务、模型配置和持久任务系统，不依赖聊天助手的 imagegen 工具。任务输出需检查，HTTP 成功或任务 done 不等于内容质量合格。车型、适配钥匙、款式和配件不能从风格参考继承。

工程师一次保存主图风格与最多五张详情参考。每张详情只引用对应槽位；超过八张参考图时明确报错。缺少独立钥匙图片时，可以复用产品原图，并明确只从右下角钥匙卡片提取兼容依据；不要求运营重复上传相同图片。可选车辆实拍用于准确车型场景，没有实拍时只生成不带车型识别标志的车辆局部。

同车型批量换款可共用型号与钥匙图；换车型模式逐行提供自己的型号和钥匙参考。任务材料与输出独立。主图确认后继续详情，最终检查生成草稿，再按现有店铺发布流程上架。

### 图片池路由修复

真实验收发现，AI 裂变显式传递已选图片池通道，而通用 `generateImages` 的非积分分支未选择图片池，底层因此读取旧单通道并请求旧 `/images/edits`。现已让没有显式通道的调用从同一 `aiImageRuntimePoolConfig` 选择服务端运行配置；裂变与积分分支原有显式通道保持不变。异步恢复按保存的 channelId／原入口匹配，原通道不可用时停止，不换通道重新付费提交。通道密钥不写入任务输入或输出。


## 价格、恢复与并发

- 工作流默认以人民币（CNY）配置售价和划线价；已有明确标注其他币种的模板保留原币种，不隐式换算金额。类目字典展示中文标签，提交仍使用平台原始字典 ID／值；编辑模板时刷新官方字段，保留已配置值。
- 工作流调度默认同时推进 3 条任务（`PRODUCT_WORKFLOW_CONCURRENCY`，上限 8），文案任务并发 3。实际图片请求继续遵守图片池通道限额和资源压力控制，超出容量排队；SQL 租约避免多个实例重复推进同一任务。
- 图片供应商任务回执保存在数据库，服务重启后按原回执查询。图片已生成但归档失败时，先持久化原图结果断点，后续只重试归档；工作流轮询不会清空断点或另建付费请求。
- 只有明确的供应商终态失败才展示生成失败。传输错误、提交结果不明等展示“结果待核对”，恢复沿用原任务标识。同步供应商若没有可查询回执，且响应在保存前丢失，不能保证找回结果；不得为此自动重复提交付费生成。
- 本轮验证使用模拟供应商、持久化断点序列化和已有积分账本恢复测试，不包含生产重启或真实付费生图。

## 裂变文案的品牌型号一致性（2026-11-12）

- 源车型字段中的逗号备注不参与型号匹配，例如 `Volkswagen Jetta，三按键钥匙` 以 `Volkswagen Jetta` 为源身份。标题优先采用与目标一致的模型输出，兜底替换也使用同一身份边界，避免把新型号拼到旧标题前后。
- 标题、描述及标签均校验目标身份和源车型残留；保存裂变草稿时按企业范围读取批次源身份再次校验。文字、主题标签及变体标签同步所有现有别名。钥匙壳兜底词不使用收纳盒、门槛条或车内收纳词，不为凑数量填入无关标签。
- 恢复历史批次时，快照源身份为空则补用批次原值；返回文案重新通过产品事实校验，防止旧批次再次导入污染文案。保留原图片、视频和人工图像提示词。
- 已存草稿恢复复用 `repair-reviewed-ai-fission-copy.mjs`：先只读审计明确的逐字段清单，再校验哈希、保存私有原始备份，最后事务内更新文案并复核；其他字段变化会拒绝应用。不改正在上架或已上架商品，不重新请求生图。
- 裂变保存时，内部品牌型号索引以当前目标车型为准；汽车品牌（7204）和型号（7212）只映射官方缓存中的精确选项，不继承母商品的旧选择，不伪造字典 ID。缓存缺失时保留已有的精确目标字典选择；不匹配的旧值清空，实际发布继续走现有官方字典解析。
- 品牌型号恢复使用 `repair-reviewed-variant-compatibility.mjs`，只接受明确企业、草稿/独立模板、目标与完整原值哈希；执行时重新核对官方字典并重算预期结果。仅修内部索引的条目需显式 `metadata_only`，保留现有正常文案、属性及媒体。

- 扩展检查同时覆盖其他汽车品牌、母标题中的旧型号、隐藏标签别名及不同产品核心词污染。导入工作台保留所选源变体，避免保存时误带母商品的其他 SKU。
- 本次历史恢复范围限定为北京时间 2026-11-11 创建的四品牌记录：88 条中 56 条钥匙壳修复（42 条文案、14 条仅关联），32 条车罩不动。另按用户确认单独恢复旧 CX-50 草稿为单商品，当前主图、根价格与包装信息为准。共享母模板不改，先文案后关联，逐阶段哈希检查和备份；这份范围说明不代表已在生产执行。

## 生产记录管理与失败恢复（2026-11-13）

- 生产任务和结果使用服务端搜索、计数和分页；列表只读取摘要，不传输完整任务快照。顶部搜索与底部系统分页固定，中间表格滚动。
- 查看记录打开详情侧栏，失败节点显示原因及重试／恢复入口；任务级失败可继续执行，已有结果不清空。未确认供应商失败的图片继续查询原回执，不重新申请付费图片。
- 同企业有运营权限的员工可以通过已归属本工作流的任务回执接手恢复。查询同时限制企业、工作流、任务编号与来源；公共 AI 任务接口仍按创建员工隔离。重复提交只复用编号、字段和提交标识一致的回执，不覆盖已有输出。
- 流程、任务和结果删除均保留记录快照，仅从列表隐藏。已生成草稿、图片和视频保留；运行中／排队中任务不可删除，版本变化或后台租约会阻止覆盖。已删除流程不会影响按旧快照运行的任务。
- 任务与结果列表优先预览已生成主图，未生成时展示产品原图并明确标注来源；点击缩略图可放大。详情顶部按变体展示整套已生成图片和生成数量，逐张节点仍展示待检查／已确认状态。

## 手动刷新与统一操作（2026-11-13）

- 页面不再定时刷新任务、结果或详情，保留显式刷新按钮；搜索、翻页及提交操作后按需读取数据。后台生产执行不受影响。
- 导航统一为已有流程、管理流程、任务管理、生产结果及企业生产资料库。流程卡片按使用流程生产、复制为新流程、编辑、查看、删除排序；查看是独立只读窗口。
- 删除、编辑和查看复用系统 Element Plus 按钮，删除使用红色描边按钮。
- 资料停用后可通过已停用筛选再次启用；删除另外标记 deleted，所有资料列表和直接读取均排除已删除项，保留历史快照和文件。删除采用企业和版本约束，不校验或修改旧资料的目录绑定。


### Ozon / WB 共用生产结果

同一个已确认的工作流产出可从生产结果列表或详情分别打开“Ozon 草稿”和“用于 WB”。WB 输出通过已有的企业隔离 run 查询，直接装配已确认结果；不重新申请图片模型、不发布商品，也不修改原 Ozon 草稿。多变体逐行保留自己的图片、描述、视频和已确认适配资料。

“风格与店铺”中可预设 WB 店铺和 WB 类目；进入 WB 编辑页时加载 WB 自身类目模板。Ozon 属性编号、商品制造品牌、条码、价格不会被猜测为 WB 字段。WB 草稿仍须补全本平台必填属性、人民币售价和条码，并经过现有预览确认后发布。

WB 标题与描述可手工编辑，也可点击对应生成按钮，调用系统现有积分文本任务。WB 标题规则为 60 字符，生成描述采用 2000 字符的保守上限；实际类目限制仍需核对。不能直接把 Ozon 标签或富文本 JSON 当作 WB 字段。

WB 每个变体的图文素材支持图片/文本区块、排序、删除、预览和 JSON 素材清单导出，最多 10 块；随本地 WB 草稿保存。关键词作为本地备忘保留。商品卡请求仍只发送 WB 已有白名单字段，**不发送这些图文区块或本地关键词**。根据 WB 官方说明，平台富文本是在商品卡发布后通过卖家后台独立编辑器创建、审核及发布；本地素材保存不代表已向 WB 发布富文本。

# 订单库存明细与历史核对

订单列表的分栏、布局和正常采购流程不变。库存信息的“明细”按需加载共享的采购库存对账窗口；组合商品从子产品明细打开实际库存。

- 只有已进入运输且本订单对应库存存在缺口时显示“补采购记录”或“核对历史收货”；历史订单不再从普通采购按钮新购。
- 弹框优先排列当前订单，历史采购只能补来源，不增加现货或在途。历史收货必须明确是否已经计入实物，默认不重复入库。
- 正常采购、登记实收沿用原流程。历史收货的只补记录模式与收货操作在同一事务内抵消库存影响，保留流水，并纳入后续采购数量纠正。
- 实物推算 = 本地账面 + 待发订单已提前扣除的数量；它不是盘点证明。可用推算扣除当前订单的现货覆盖。
- 校准存量负库存前，库管必须实际盘点（包含已分配但尚未发出的货），通过“本地库存去向 → 盘点调整”填写数量与原因。调整使用实物推算而非账面作为比较基准，避免提前扣减重复加回。历史缺记录保持独立，不清除历史订单。
- 不自动迁移、清零或猜测存量实物。未经盘点，旧负数仍需核对，不能承诺仅部署即可恢复真实库存。

验证场景：账面 −7、待发提前扣减 2，实物推算 −5；实际盘点 0，调整 +5 后账面 −2。到货 5 后账面 3；发走原 2 后实物 3。新单 1 件由现货覆盖，历史补记录不增减实物。

## 快速补齐历史采购

操作列“补齐采购记录”按整个库存的历史缺采购数量显示，不要求当前行自身为历史订单。汇总字段随原订单覆盖查询返回，不增加每行接口请求；补齐后该库存所有行入口同步消失。旧响应缺少汇总字段时，负库存允许打开核对，但不能按负数直接生成采购。

弹框自动带出实际缺采购记录数量，支持一次填写数量、总货款、运费、实际采购时间与原因。预览按历史订单进入运输的先后分配数量，并按数量分摊两项金额，尾差按累计金额舍入保证守恒。采购日期必须符合所有受影响订单，不同采购批次应分开补录。

确认后在单个事务中生成一张历史采购单及一个已完成的来源批次，关联多个历史订单，写入采购成本版本与各订单分摊审计记录；不增加现货、不增加在途、不覆盖已有采购。部分补齐只消耗本次填写数量；已采购但缺收货的部分排除。原快照版本、订单锁及请求幂等标识用于阻止过期提交和重复保存。

在采购记录查看该采购总成本；在库存明细“历史补录成本”查看最近 50 次操作中的原始订单分摊记录。这里是补录时的审计金额，不代表自动重开已结算财务期间或重算全部历史利润。

# ERP 前端交互与视觉统一规范

## 1. 页面结构

- 页面顶部统一使用“左侧标题与说明、右侧筛选与操作”结构。
- 标题只描述页面，不拼接日期、店铺或状态；动态条件放在筛选区。
- 页面主操作每个区域最多一个，使用主色按钮；其他操作使用次按钮或文字按钮。
- 日期、月份等账期切换统一显示“上一个周期—当前周期—下一个周期”，并提供清晰的可访问名称。

## 2. 筛选与查询

- 筛选项固定顺序：时间、店铺、业务状态、关键词、查询、重置、辅助操作。
- 查询条件应同步到 URL；返回页面时恢复筛选、页码和标签。
- 查询按钮负责应用条件，重置按钮恢复该页面约定的默认条件。
- 筛选区在窄屏下允许换行，不隐藏关键查询条件。

## 3. 表格与分页

- 金额右对齐，正负颜色只表达业务含义，不作为唯一状态提示。
- 状态统一使用：绿色成功、橙色待处理、红色异常、蓝色进行中、灰色无效。
- 操作列固定在右侧；每行保留一个主要操作，其余放入更多操作。
- 分页统一使用 `PageFooterPagination`。

## 4. 异步反馈

- 首次加载使用页面或卡片加载状态；局部刷新不清空已有数据。
- 触发异步操作的按钮必须显示加载状态并防止重复提交。
- 空状态需要说明原因和下一步操作；错误信息需要说明如何修复。
- 保存成功使用短消息；删除、覆盖和批量变更需要二次确认。

## 5. 基础组件

- `ErpPageHeader`：页面标题、说明和右侧操作。
- `ErpFilterBar`：统一筛选与辅助操作排列。
- `ErpPeriodSwitcher`：日、月等账期前后切换。
- `PageFooterPagination`：统一分页。
- 按钮继续使用 `erp-btn-primary`、`erp-btn-secondary` 和 `erp-btn-link`。

## 6. 变更边界

- 视觉统一不得改变 API、数据库、利润计算或任务执行逻辑。
- 复杂业务页分批迁移；每批必须通过相关测试、UTF-8 检查和前端构建。
- 新页面不得重新实现已有的页面头部、账期切换和分页组件。

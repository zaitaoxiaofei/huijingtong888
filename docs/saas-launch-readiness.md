## 当前交付边界

先准备人工开户、人工收款的少量企业试点。完整自助注册、购买支付和自动续费不属于这批安全修复的交付结果。现阶段不得将默认企业的完整功能直接宣传为新企业均可使用，也不得通过删除隔离闸门来开放未验收接口。

## 历史关系审计与修复

从配置了目标数据库的工作区执行：

```sh
npm run audit:tenant-default-access
```

默认模式只读取企业和成员关系，不建表、不运行应用初始化、不修改成员或会话；输出候选人员 ID、默认企业角色和其他有效企业 ID，不输出姓名、密码或令牌。候选表示需要复核的跨企业成员，不代表一定是错误授权。

由平台维护人员核实具体名单后，使用本机 MySQL 管理 socket 执行（Linux 示例；ID 和原因须替换成实际已复核值）：

```sh
npm run audit:tenant-default-access -- --apply --mysql-admin-socket=/var/run/mysqld/mysqld.sock --person-ids=101,102 --reason="Reviewed accidental default membership"
```

执行会锁定默认企业及选中成员，拒绝平台管理员、已变更名单以及没有其他有效企业归属的账号。只停用选中账号的默认企业成员关系，撤销其默认企业及尚未绑定企业的旧会话；保留其他企业成员和会话，并写入 `tenant_membership_repair_log`。审计表在事务前按需创建，成员修改及会话撤销和记录写入在同一事务内完成。修复结果必须记录在发布验收中。

## 后续试点门槛

1. 订单列表：完成全读链和统计/缓存的租户限定，再开放新企业入口。
2. 库存、采购：覆盖台账、占用、入库出库、关联库存及导出，逐步形成业务闭环。
3. 上架：覆盖提交、批量发布、重试和后台执行的租户身份传递。
4. 用真实 A/B 企业验证列表、详情、修改、删除、导出、后台任务、切换、重启及并发额度。
5. ECS 核验运行版本和迁移，完成人工开户流程、备份恢复验证和试点验收后才能接入收费客户。
6. 自助开通另接原计划切片 2B/3；授权续期审计接切片 4；员工指定店铺权限接切片 6。

## 本地验证方式

- 安全基础批次：38 个相关测试文件合计 217 项通过，无失败或跳过，包含下述独立 MySQL 测试；编码、SQL INSERT 绑定及 API 文档一致性检查通过。
- 单元与路由测试使用依赖替身，不连接业务数据库。
- `test/tenant-default-access-mysql.test.js` 使用显式提供的 `TENANT_TEST_MYSQL_SOCKET`，在独立 MySQL 实例中创建随机命名的测试库，结束后仅删除自己创建的测试库。覆盖真实事务、并发初始化、后来新增客户、只读审计、名单校验、会话撤销及修复后重启。
- Windows 临时 MySQL 数据目录应使用本机临时目录下的 ASCII 路径；中文 OneDrive 路径可能触发 InnoDB 文件扫描失败。测试实例关闭 TCP，只使用独立命名管道，不启动 ERP 服务。
- 上架相关保护测试在原始基线已有四个结构断言失败（健康筛选、平面表格更新、媒体首屏及采集 INSERT 路径）；本批不改动对应 UI。相关租户与新增行为回归须单独通过，并保留基线对照。

本地测试通过仅代表本批代码证据，不代表历史权限已清理、ECS 已部署，或所有业务模块均已完成隔离。

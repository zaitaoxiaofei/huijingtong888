# SaaS 人工开户试点验收

更新：2026-10-23。工作分支 `codex/saas-pilot-isolation` 本次修复基于 `release/2026.10.21-task-brand` 的 `ef7dc56`。交付目标仍为人工开户、人工收款的小范围付费试点；自助注册、支付、自动续费后置。历史上线与本次修复验收分别记录于本文末尾。

## 安全边界

- 企业会话、有效成员、订阅期限及岗位分别校验。默认企业普通员工和客户企业使用相同的已验收接口清单，默认企业身份不能直接放行旧全局接口。平台权限单独管理。
- 历史企业键 `admin` 只表示实际默认企业；核心表保留的历史 NULL 仅默认企业可见。列表、统计、缓存、导出、任务进度不能将其解释成全平台范围。
- 后台任务保存企业及原操作人；恢复、重试、关键写入重新检查当前成员、订阅和岗位。平台调度逐企业执行，不自动选择管理员充当原操作人。
- 新账号不自动加入默认企业。现有账号、密码、成员关系保持不变；平台授权仍为已确认的人员 ID 5、9、10。本次业务迁移不新增平台授权。
- 私有附件登记企业、用途与上传人，鉴权 API 读取；静态路径、跨企业 GET/HEAD、路径穿越均拒绝。公开刊登媒体与 AI 原始任务文件分开。图片代理拒绝内网和元数据地址，固定 DNS 校验后的连接并逐次校验重定向。
- SSE 每个业务事件发送前重新验证原会话；退出、成员停用、切换企业、订阅失效后停止旧企业推送。
- 启动就绪检查验证必需归属列、关键复合唯一键及 AI 企业键类型。迁移不完整时阻止候选版本切换。
- 上传和本地合成会把用户图片交给原生解码器；本轮将 Sharp 固定为 `0.35.5`，覆盖官方 [libvips](https://github.com/lovell/sharp/security/advisories/GHSA-f88m-g3jw-g9cj)、[libheif](https://github.com/lovell/sharp/security/advisories/GHSA-rgj7-g3m4-5g8c)、[librsvg](https://github.com/lovell/sharp/security/advisories/GHSA-wq5f-xc86-pv6w) 三项公告的修补下限。Windows 与 ECS 独立 Linux 实例的七项解码/缩放/文字渲染验证通过，实际应用目录的加载版本在补丁部署后另行核对。

## 仍受限的功能及试点承诺

中央门禁 `src/server/tenant-pilot-routes.js` 和 `src/server/tenant-isolation.js` 按完整路径、方法开放，未验收接口继续返回 `TENANT_ISOLATION_PENDING`。

- 批量发布任务重试、矩阵生成/发布、部分高级草稿绑定、历史全量利润修复等仍关闭给普通企业成员，不属于本次付费试点承诺。草稿箱的批量上架单独完成企业隔离验收，不据此开放其他高级接口。
- 新企业 AI 默认额度 0，平台通过企业额度更新接口显式配置；0 停用，正整数为北京时间每月次数，显式 NULL 为不限量。默认历史企业无额度行时保持既有策略。修改 AI 额度不重置账号/店铺额度。
- 当前按企业内岗位授权，员工指定到单个店铺的权限仍为后续切片。试点交付需要明确同企业内共享范围。
- 外部 Ozon、AI、OSS 使用网络替身验证凭据归属、次数和撤权边界；测试没有创建真实外部商品、发送客户消息或消耗付费生成。生产冒烟不能替代客户店铺实际业务验收。
- 基线已有 AI、刊登、图片回退的源码/UI 结构断言失败，发布记录区分这些旧基线与本轮新增回归，不能将整仓测试描述为全绿。
- 生产备份恢复发现历史重复自然键及部分父链异常，尚未完成业务修复和原约束下的恢复验收；因此本轮隔离代码发布不等于允许承诺整套 ERP 正式对外销售。见下方备份演练说明。

## 迁移与交付

只使用已入库 ECS 部署流程，从最新、干净、已推送的 release 提交发布。部署前完整 SQL gzip 备份，先只读预演冲突，再幂等迁移、候选就绪检查、切换及生产冒烟。

本轮新增或扩展：产品关联、库存采购、团队任务、热力图、素材、系统通知、客服、车型、AI 后台、私有附件迁移。三个采购导入表及客服模板只在显式迁移参数下将已确认历史记录归入默认企业，保护旧进程写入去重；其他历史 NULL 不推断为客户企业。原账号密码及成员关系不在此流程中修改。

旧客服自动任务、活动清理配置若缺少保存的原操作人，保持暂停并提示运营重新保存配置，不自动挑选负责人恢复外部写入。

人工开户：创建独立企业和首位负责人，核对订阅、账号/店铺与 AI 额度，配置本企业店铺密钥，再验收订单同步、库存采购和一次实际刊登，仅交付本文开放范围。

已有客户数据写入后，不能直接回滚至本轮之前的全局查询版本。优先回退到具备相同隔离迁移的版本或向前修复；整库恢复须核对备份时间及之后业务数据。

### 2026-10-22 备份恢复演练

生产 SQL gzip 在独立、关闭 TCP 和事件调度的 MySQL 实例中全量恢复：208 张表、2,204,798 行，逐表全字段无序内容摘要与原备份一致，人员、成员关系、企业订阅三组摘要一致。大字段导入需要服务端和客户端均配置足够的 `max_allowed_packet`，本次仅临时实例使用 1 GiB，未改生产配置。

原备份有三个现存 UNIQUE 键与实际数据矛盾：在线商品 8 组、订单状态历史 575 组、Ozon 类目映射 13 组。为保留全部原始行，仅恢复副本把这三个键降为同列 NONUNIQUE；`schema_exact=false`，不能把它记录成“原结构完整恢复通过”。生产数据与索引没有因此修改。

在线商品中两组分别存在不同的有效 Ozon 身份、不同的有效库存绑定；另有部分历史记录与订单父链的店铺字段不一致。通用去重不能推断正确业务关系。管理员工具 [审阅后的唯一键修复](reviewed-legacy-unique-index-repair.md) 默认只读，对这些冲突继续拒绝；不随部署自动运行。完成明确的业务修复、严格唯一键验证和新备份完整恢复后，才能解除此交付阻断。

| AI 视觉重试 | 两种供应商协议的第二次请求都重新预留额度并复核当前授权，按每次实际请求记录用量；退避期间撤权或额度耗尽不发出第二次请求，权限／额度错误保持原状态，不包装成供应商错误。 |

MySQL 单表 UPDATE 的赋值通常按从左到右执行，后续表达式读取已更新列值，见 [MySQL 官方赋值规则](https://dev.mysql.com/doc/refman/8.4/en/update.html)。密码变更后的凭据控制与登录节流也应覆盖不同登录渠道，参照 [OWASP 身份认证指引](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)。

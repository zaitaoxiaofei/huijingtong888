# 企业收费试点准备

更新日期：2026-10-21（北京时间）。开发基线：远端 `release/2026.10.21-task-brand`，提交 `eefe63d451b6ad5cb6ba6391438cbbed0b5cfe51`；工作分支 `codex/saas-launch-foundation`。

## 当前交付边界

先准备人工开户、人工收款的少量企业试点。完整自助注册、购买支付和自动续费不属于这批安全修复的交付结果。现阶段不得将默认企业的完整功能直接宣传为新企业均可使用，也不得通过删除隔离闸门来开放未验收接口。

## 安全基础批次

| 项目 | 本地进度 | 发布验收 |
| --- | --- | --- |
| 默认企业错误自动入组 | 启动不为任何账号新增成员，包括平台超级管理员；旧会话绑定需已有有效成员关系 | 核对历史成员、明确名单修复，再做真实客户登录与重启回归 |
| 历史默认企业成员审计 | 新增默认只读审计、显式名单事务修复及修复记录 | 审计候选必须人工核实，不能自动清理合法跨企业成员 |
| 二维码登录安全 | 密码扫码与普通登录共用限流；创建会话前验证二维码；并发失败会话撤销 | 验证现有普通登录、扫码与手机记住账号流程 |
| 企业插件令牌管理 | 仅放行现有五个精确接口；普通账号限定当前企业，保留成员校验；敏感响应禁止缓存 | A/B 企业伪造目标企业参数仍须被拒绝 |
| 草稿项目列表 | 修复编辑中、待上架状态多余 SQL 绑定；保留租户条件 | 项目状态、关键词、店铺及分页组合回归 |

普通人员及平台超级管理员均不自动加入默认企业。既有成员关系和已停用成员保持原样，历史关系通过审查后的清单处理；企业负责人、业务管理员和旧技术岗位不能因此获得平台权限。

## 默认企业升级兼容

已有启用账号和有效默认企业成员关系的人员，继续使用原登录名及密码；启动过程不修改密码、删除人员或批量停用原有成员。没有有效企业关系也没有平台授权的账号会拒绝登录，不能用重新自动入组来掩盖缺失关系。因此发布前必须对照实际人员名单核实成员状态，不能用测试账号通过替代生产逐人核查。

旧版本曾为所有启用人员自动写入默认企业 `owner`。对于仍没有独立岗位 JSON 的历史默认成员，统一按有效岗位解析权限：普通打包、采购、运营等员工仍是原岗位权限，历史业务管理员保留企业管理权限，但均不会获得平台授权。会话、企业选择器、人员列表、身份编辑及最后负责人保护使用相同解析；普通资料编辑不能把历史自动负责人转成正式负责人。通过明确的成员授权或迁移清单保存后，使用已确认的企业角色与独立岗位。

平台规则管理与业务消费分别校验。库存、选品和订单仍可读取安全的共用物流费率；默认企业运营人员原有的一键上架、上架重试等执行链继续保留，企业矩阵配置写入仍需负责人或管理员，非默认企业未完成隔离的执行链继续关闭。平台设置、监控、全局自动任务、AI 设置和提示词库需要明确的平台授权；原业务 `admin` / `technical` 不能直接沿用这些平台权限。

默认企业的 AI 任务唤醒与 SKU 提醒继续使用业务事件流，订阅身份取自服务端会话，业务事件匹配人员及企业；切换账号或企业时关闭旧订阅并忽略迟到事件。全局活动清理任务仍限平台人员，企业业务页不展示该全局调度入口。

身份迁移只对发生授权变化的账号撤销旧会话，要求用原密码重新登录，不等于修改密码。当前尚未核对全部实际生产人员，不能承诺直接覆盖发布不会影响任何人；必须先备份、核对完整迁移清单，再验证真实角色的登录及关键业务流程。

## 平台与企业拆分批次

本批本地代码把登录身份、平台授权、企业角色及业务岗位分开。实际业务库的人员名单和权限迁移尚需明确审查，不能根据人员姓名或开发用途直接赋权。

| 数据及入口 | 当前模型 | 本地接入范围及待验收项 |
| --- | --- | --- |
| 全局登录身份 | `people` 保留账号、密码及历史业务引用 | 保留人员 ID；跨企业共用账号的身份字段需受控修改 |
| 平台超级管理员 | `platform_grants` 的启用 `super_admin` 记录，映射为 `session.platform_role` | 平台专用账号可独立登录；平台授权不自动产生默认企业成员关系 |
| 企业角色 | `tenant_members.role` 的 `owner` / `admin` / `member` | 管理员只管理当前企业；成员停用及岗位修改撤销本企业旧会话 |
| 企业业务岗位 | 同一成员关系的 `business_roles_json` | 旧岗位保留兼容读取；平台权限不从旧 `people.role` / `roles_json` 推断 |
| 企业店铺与人员 | 企业店铺导航下的店铺管理、企业人员 | 创建账号及成员在同一事务完成；保留最后一位负责人，校验额度和身份字段修改范围 |
| 店铺矩阵配置 | 共用固定框架，企业自定义店铺规则、水印与尾图 | 精确开放配置接口；A/B 企业配置与尾图测试通过，实际迁移及页面验收仍须记录 |
| 平台管理 | 平台人员、企业与授权、共用基础规则、自动任务、监控、AI 设置、提示词库 | 平台超级管理员管理；开发与监控账号同样通过明确授权接入 |

共用汇率、利润规则、物流和取消规则由平台维护。物流管理使用固定的默认企业配置范围，普通企业消费安全的共用费率投影；历史企业物流规则保持原归属，不批量迁移或重分配。本批不修改广泛的定价匹配算法。

矩阵配置的固定风格、主图方案、车型和类目字典可共用。私有尾图新增 `tenant_id`；旧 NULL 归属仅默认企业可见。非默认企业只能上传本企业图片并选择本企业模板。生成、任务、导入、发布和素材删除仍待完整执行链隔离，不随菜单或配置开放。

企业负责人和管理员使用已隔离的 `/finance-center` 财务流程。旧工资、月度账单和利润分析接口尚未完成企业隔离，界面与 API 均继续限定平台授权，默认企业的旧业务 `admin` 岗位不能绕过此边界。

## 人员身份迁移与历史关系修复

本轮完整身份拆分统一使用[平台身份与企业成员迁移](platform-enterprise-identity-migration.md)。先只读盘点，再逐个人员 ID 核对平台授权和迁移后要保留的完整企业关系清单：

```sh
node scripts/migrate-platform-enterprise-identities.mjs
node scripts/migrate-platform-enterprise-identities.mjs --manifest=/absolute/path/reviewed-identities.json
```

默认只读，不建授权表、不补成员、不写授权、不撤销会话。应用模式需要已审查清单、审查人员及原因、明确指定的本机管理员 socket；清单中未列出的人员保持原样，所列人员的完整目标成员列表必须逐项核实。权限发生变化时撤销旧会话，保留业务记录中的人员 ID 和历史引用。生产迁移顺序、清单示例及事务保护见上述专项文档。

历史默认企业成员重叠仍可进行窄范围专项审计：

从配置了目标数据库的工作区执行：

```sh
npm run audit:tenant-default-access
```

默认模式只读取企业和成员关系，不建表、不运行应用初始化、不修改成员或会话；输出候选人员 ID、默认企业角色和其他有效企业 ID，不输出姓名、密码或令牌。候选表示需要复核的跨企业成员，不代表一定是错误授权。该专项修复只处理经确认的默认成员重叠；平台身份和完整企业关系拆分使用上面的清单迁移。

由平台维护人员核实具体名单后，使用本机 MySQL 管理 socket 执行（Linux 示例；ID 和原因须替换成实际已复核值）：

```sh
npm run audit:tenant-default-access -- --apply --mysql-admin-socket=/var/run/mysqld/mysqld.sock --person-ids=101,102 --reason="Reviewed accidental default membership"
```

执行会锁定默认企业及选中成员，保护明确的平台授权，拒绝已变更名单以及没有其他有效企业归属的账号。只停用选中账号的默认企业成员关系，撤销其默认企业及尚未绑定企业的旧会话；保留其他企业成员和会话，并写入 `tenant_membership_repair_log`。审计表在事务前按需创建，成员修改及会话撤销和记录写入在同一事务内完成。修复结果必须记录在发布验收中。

矩阵私有尾图需要单独完成 schema 迁移，默认同样只读；既有 NULL 行保留原值，不推断企业归属：

```sh
npm run db:migrate:tenant-asset-variant-config
npm run db:migrate:tenant-asset-variant-config -- --apply --mysql-admin-socket=/var/run/mysqld/mysqld.sock
```

## 后续试点门槛

1. 人员身份：逐个审查平台/企业归属清单，验证平台专用、企业专用及双身份账号；确认切换与重启不会重新补成员。
2. 订单列表：完成全读链和统计/缓存的租户限定，再开放新企业入口。
3. 库存、采购：覆盖台账、占用、入库出库、关联库存及导出，逐步形成业务闭环。
4. 上架：覆盖提交、批量发布、重试和后台执行的租户身份传递。
5. 用真实 A/B 企业验证列表、详情、修改、删除、导出、后台任务、切换、重启及并发额度。
6. ECS 核验运行版本和迁移，完成人工开户流程、备份恢复验证和试点验收后才能接入收费客户。
7. 自助开通另接原计划切片 2B/3；授权续期审计接切片 4；员工指定店铺权限接切片 6。

## 本地验证方式

- 安全基础、身份拆分、企业人员、导航、矩阵、接口权限及缓存隔离均有合并回归；其中默认成员、身份管理、矩阵与费率投影执行隔离 MySQL SQL。默认企业升级兼容补充旧岗位负责人识别、资料编辑不扩权及业务只读规则/上架消费回归。保留测试范围和失败基线，不把测试通过视为所有业务模块已验收。
- 最新兼容定向回归共 348 项通过，无跳过（合并套件 341 项，SSE 隔离及应用更新事件另 7 项）；前端构建、页面检查、编码、SQL 绑定及 API 文档检查通过。这仍不包含生产实际人员名单逐人验收。
- 矩阵配置常规测试 10 项通过；独立 MySQL fixture 8 项通过，验证 A/B/default 范围、跨企业引用拒绝、默认尾图互不覆盖、文件读取和发布尾图 fallback，以及默认企业运营人员业务读取与配置写入的区别。只创建及删除随机测试库，不访问业务数据库。
- 单元与路由测试使用依赖替身，不连接业务数据库。
- 前端完整 Vite 构建通过；在隔离浏览器中使用模拟 API 验证企业店铺、企业人员及新增弹窗、矩阵配置、平台人员、共用基础资料以及平台专用账号首页跳转。保留现有整体布局；该检查不代替迁移后的真实账号端到端验收。
- 独立 MySQL 测试使用显式提供的 `TENANT_TEST_MYSQL_SOCKET`，创建随机命名的测试库，结束后仅删除自己创建的测试库。默认访问测试覆盖启动不自动入组、显式成员的旧会话绑定、只读审计、名单校验、事务修复及重启；矩阵 fixture 执行真实配置 SQL。
- Windows 临时 MySQL 数据目录应使用本机临时目录下的 ASCII 路径；中文 OneDrive 路径可能触发 InnoDB 文件扫描失败。测试实例关闭 TCP，只使用独立命名管道，不启动 ERP 服务。
- 上架相关保护测试在原始基线已有四个结构断言失败（健康筛选、平面表格更新、媒体首屏及采集 INSERT 路径）；本批不改动对应 UI。相关租户与新增行为回归须单独通过，并保留基线对照。
- 扩展保护回归 156 项中 148 项通过，8 项失败与已确认基线一致：上面 4 项上架断言，另有 2 项采购测试依赖替身与 2 项店铺旧结构断言。未将这些失败计为本批通过。

本地测试通过仅代表本批代码证据。实际人员迁移清单、历史权限清理、ECS 发布、业务闭环及用户验收仍须逐项记录，目前不能认定已具备正式对外售卖条件。

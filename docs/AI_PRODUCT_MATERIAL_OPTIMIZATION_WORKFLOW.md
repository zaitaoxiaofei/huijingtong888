# AI 商品素材优化工作流方案

## 目标

把现有图片优化能力升级成和 AI 裂变实验室一致的工作流体验，用于优化同一个商品的主图、详情图、标题、标签和描述。

核心原则：

- AI 可以优化表达，不能改变商品事实。
- 生成结果先进入候选素材池，用户选择后才进入最终模板。
- Ozon 上架只读取最终图片位，不能读取临时候选池。
- 重新生成不覆盖旧版本，避免丢失用户觉得可用的图片。
- 素材优化属于同一商品的复制优化，保存草稿的开发类型必须是 `copy`，不能按 AI 货号误判为裂变。
- 任一生成节点失败都不能清空其他成功结果；只要已有可用图片，就允许按当前快照保存草稿。

## 模块介绍

AI 商品素材优化用于在不改变 SKU 商品事实的前提下，重新组织商品图片、俄语标题、标签、描述、富文本和视频。它与 AI 裂变的区别是：

- 素材优化不更换商品型号、颜色、数量或适配关系，只提升同一个商品的表达质量。
- AI 裂变用于生成新的目标车型、规格或其他商品变体，开发类型为 `fission`。
- 素材优化保存的草稿开发类型固定为 `copy`。

业务编号规则：

- 新素材优化草稿货号使用 `OPT-A-*`、`OPT-B-*`，不再使用 `AI-OPT-*`。
- 新素材优化流程任务编号使用 `OPTJOB-*`，不再使用 `AIO-*`。
- 编号只表达业务来源和方案，不用于推断开发类型；开发类型读取结构化字段 `development_type`。
- 历史 `AI-OPT-*` 货号保持不变，避免影响已发布商品、订单、映射和外部平台关联。

当前用户流程为四个阶段：

```text
导入素材
  -> AI 识别并确认商品事实
  -> 生成并确认执行计划
  -> 生成结果、独立重试并保存草稿
```

内部生成链路为：

```text
读取商品与模板
  -> 识别精确商品子类和不可变事实
  -> 判断购买决策顺序与视觉品类
  -> 生成文案策略、视觉语言和套图分镜
  -> 生成标题、标签和描述
  -> 文案质量门检查与自动重写
  -> image2 生成两套主图和共用详情图
  -> 每套主图分别生成富文本、视频和视频封面
  -> 逐套保存为 copy 草稿
```

### 商品识别

识别节点输出：

- 精确商品子类，而不是“汽车配件”“家居用品”等宽泛类别。
- 品牌、型号、适配对象、数量、颜色、材质、结构、用途和安装位置。
- 可证明事实、低置信度信息和禁止宣传内容。
- `decision_context`：目标买家或适配关系、购买决策顺序、已验证差异点、视觉品类、价格定位和沟通语气。

所有标题、标签、图片文字和描述都必须以确认后的商品事实为准。低置信度信息不能进入生成文案。

### 文案生成与质量门

标题按以下信息顺序生成：

1. 精确商品名称。
2. 适配型号、使用对象或目标人群。
3. 数量、规格、颜色等已确认信息。
4. 可追溯到商品事实的具体卖点。

标签围绕精确商品子类、适配关系、用途、结构和已验证卖点生成，默认保留 12 到 25 个有效标签。生成后执行独立质量检查：

- 标题是否明确说明商品是什么。
- 是否包含必要的型号、年份、规格、数量或目标人群。
- 是否出现“高品质、耐用材料、时尚设计、实用方案”等可套用到任意商品的空泛表达。
- 标签是否重复、格式化重复、数量异常或包含无搜索区分度的流量词。

第一次不合格时，只调用文本模型重写标题、标签和描述，不重新生成图片。第二次仍不合格时，使用计划中的精确标题兜底，并去重、清理标签。

### 图片文字和视觉风格

图片计划包含 `visual_language`，根据品类、目标买家、材质、价格定位和构图决定文字语气、标题样式、信息层级、字重、强调方式和对齐策略。

每张分镜还包含自己的 `typography_role` 和 `typography_direction_en`。套图保持同一视觉语言，但不能在每张图片重复使用相同的大黑标题、红色横线、等宽图标阵列、固定字幕位置或通用海报模板。

`image2` 直接把已审核的俄语文案设计进最终图片。视觉复检会检查商品真实性、俄语准确性、移动端可读性、信息层级和模板化排版；失败只重做当前图片。

### 双主图与草稿保存

- 默认生成主图方案 A 和方案 B。
- 两套方案共用详情图、基础商品事实、标题、标签和描述。
- 每套方案使用自己的主图生成富文本首屏、视频和视频封面。
- 保存时逐套创建草稿；一套失败不会回滚另一套成功草稿。
- 同一商品允许以不同主图保存两条草稿，不允许同一主图重复保存。
- 视频、富文本、排版审核或部分详情图失败时，仍可保存当前已有结果，并在之后单独重试。

## 工作流

1. 导入素材
   - 支持主图、详情图、标题、标签、描述、模板详情图和参考图。
   - 默认主图进入优化范围。
   - 用户勾选的详情图也进入优化范围。

2. 识别产品
   - 主图做深度识别，锁定产品主体、颜色、结构、材质、品牌、型号、数量和关键配件。
   - 详情图默认做轻量识别，判断图片类型和是否值得优化。
   - 用户选中的详情图再进入更完整的优化计划。

3. 生成优化建议
   - 主图先规划两个受控视觉方向，方向只能改变背景、构图、景深、光线和留白，不能改变商品事实。
   - 图片建议：先生成一份 4 到 5 张的结构化套图分镜，再分别规划主图、材质图、安装图、结构图、卖点图或尺寸图。
   - 每个分镜必须说明图片目标、构图方式和必须展示的已确认事实，整套图共享背景、光线、镜头语言、产品尺度、留白和视觉层级。
   - 生成开始前直接展示完整蓝图，包括主图标题、适配型号/人群、2 到 3 个已验证卖点、两个主视觉方向和全部详情图分镜。
   - 文字建议：标题、标签、描述、卖点提炼、Ozon 表达风格。
   - 输出文本预览，不先生成图片预览。
   - 计划作为独立步骤展示；用户确认主图信息、视觉方向、套图分镜和执行模块后，才允许进入真实生成。

4. 用户补充建议
   - 用户可以填写“不要改产品颜色”“参考模板详情图风格”“增加尺寸图”“突出防水”等建议。
   - 用户建议作为约束和偏好，不允许覆盖商品事实锁定规则。

5. 一键优化
   - 并发生成两个主视觉方向，分别视觉复检并优先选择通过且得分更高的版本；未获选版本保留在候选池供人工切换。
   - 先生成主图，以通过的主图作为详情图的统一视觉锚点，再并发生成各详情图分镜和文字结果。
   - 图片服务只有单参考图能力时，详情图优先使用新主图作为参考，并通过商品事实契约保持产品真实性。
   - 不拆成多个确认步骤。
   - 每张图片生成后由视觉模型检查商品事实、乱码、分镜完成度和套图一致性；存在实质问题时携带短纠偏指令自动重做一次，最多一次。
   - 图片模型直接完成商品视觉和俄语文字设计，服务端固定字体叠字仅作为手动兜底。
   - 主图必须包含精确商品标题、明确适配型号或目标人群，以及 2 到 3 个可追溯到商品事实的卖点。
   - 富文本固定使用最终主图、新标题和新描述；视频封面字段与生成的视频使用同一个可发布媒体 URL。

6. 结果素材池
   - 原始图片、优化图片、新生成图片、失败项和重试版本都进入候选素材池。
   - 每个候选图保留来源、用途、状态和版本。

7. 选择保存
   - 用户从候选素材池选择最终图片。
   - 用户调整图片顺序。
   - 保存为新模板时写入最终图片位和文字字段。

## 图片识别成本策略

图片识别按成本分层：

- 主图：默认深度识别，因为它决定产品主体和不可变事实。
- 详情图：默认轻量识别，判断是场景图、尺寸图、卖点图、包装图、细节图或普通详情图。
- 选中详情图：进入深度优化上下文。
- 图片数量少时可以一起作为素材识别；图片数量多时先分类再让用户选择。

建议默认阈值：

- 1 张主图加 3 到 8 张详情图：可一起作为上下文识别。
- 超过 8 张详情图：先轻量分类，只深度处理用户选中的图片。

## 商品事实锁定

不可改：

- 产品外形
- 产品颜色
- 产品结构
- 材质特征
- Logo、型号、品牌标识
- 关键配件和数量
- 已确认的适配车型、尺寸、认证和安装方式

可优化：

- 背景
- 光影
- 构图
- 清晰度
- 画面质感
- 场景氛围
- 卖点文字排版
- 尺寸标注
- 标题、标签和描述表达

文字优化同样遵守商品事实锁定，不得虚构材质、尺寸、认证、适配范围、数量或功能。

## 候选素材池

候选素材池用于保存所有生成和导入的图片版本，不直接代表 Ozon 上架图片。

候选图建议字段：

```json
{
  "candidate_id": "img_xxx",
  "url": "https://...",
  "kind": "main|detail|scene|size|selling_point|reference",
  "source": "original|optimized|generated|template_reference|retry",
  "source_candidate_id": "img_original_1",
  "status": "ready|generating|failed",
  "version": 1,
  "title": "优化主图 A",
  "prompt_summary": "保留产品主体，优化浅色背景和光影",
  "failure_message": ""
}
```

规则：

- 原图不能被覆盖。
- 每次重新生成都新增一个候选版本。
- 失败只影响当前候选项或当前字段。
- 用户可以对主图、详情图、场景图、尺寸图、卖点图分别重试。

## Ozon 最终图片位

最终图片位是上架和保存模板真正读取的图片列表。

保存新模板时必须写入：

- 第几位图片
- 图片 URL
- 是否主图
- 图片类型
- 来源候选图
- 排序值

建议结构：

```json
{
  "final_image_slots": [
    {
      "slot": 1,
      "role": "main",
      "url": "https://...",
      "candidate_id": "img_optimized_main_v1",
      "source": "optimized",
      "sort_order": 1
    },
    {
      "slot": 2,
      "role": "detail",
      "url": "https://...",
      "candidate_id": "img_scene_v1",
      "source": "generated",
      "sort_order": 2
    }
  ]
}
```

Ozon 上架适配规则：

- 第 1 位必须能映射为 Ozon `primary_image`。
- 后续图片必须能映射为 Ozon `images`。
- 保存模板时同步写入现有 `images` / `editable_payload.images` / SKU 变体 `images`，避免页面显示和发布 payload 不一致。
- 如果 SKU 图片已被用户手动编辑，不能用模板图自动覆盖 SKU 图片。

## 保存新模板

保存新模板时包含两份图片数据：

1. 素材历史
   - 原始素材
   - AI 候选图
   - 重试版本
   - 失败记录

2. 最终图片位
   - 用户最终选择用于模板和上架的图片
   - 顺序稳定
   - 可被发布流程读取

保存规则：

- 生成不等于保存。
- 候选池保留全部版本。
- 模板上架只使用最终图片位。
- 保存前检查主图位不能为空。
- 保存前检查最终图片 URL 可用且能转为公开可访问地址。

## 失败项重试

不需要完整批量任务中心，但每个字段应有独立状态和重试入口。

字段包括：

- 主图
- 选中的详情图
- 新生成场景图
- 新生成尺寸图
- 新生成卖点图
- 标题
- 标签
- 描述

重试规则：

- 失败字段可以单独重试。
- 不满意的成功字段也可以重新生成。
- 重试结果作为新版本加入候选池。
- 用户主动选择后才替换最终图片位或文字字段。
- 每张成功图片必须立即写入候选池、最终图片位和当前任务检查点，后续模块失败不得清空已有素材。
- 两个主视觉方向和每张详情图独立容错；单个生图 502、复检超时、文案失败或视频失败不能拖垮整批。
- 确定性排版图片必须写入静态服务实际读取的 `public/uploads/listing-media`，返回 URL 前保证文件已落盘。

## 与现有系统的连接点

现有基础：

- `src/services/ai-variant-lab.js` 已有优化分析和计划接口：
  - `POST /api/ai-variant-lab/optimize/analyze`
  - `POST /api/ai-variant-lab/optimize/plan`
- `frontend/admin/views/listing/AiVariantLabView.vue` 已有 AI 裂变实验室步骤体验。
- `frontend/admin/views/listing/ListingAutomationView.vue` 已有模板图片、SKU 图片、预览、删除、拖拽排序和模板图片复用。
- `src/services/listing-automation.js` 已有 Ozon 发布前模板标准化、媒体物化和 `primary_image` / `images` 相关链路。

建议开发顺序：

1. 扩展优化工作流前端状态，加入图片候选池和最终图片位。
2. 扩展优化分析和计划接口，让主图和选中详情图一起参与识别。
3. 新增文本预览结构，覆盖图片优化和文字优化。
4. 新增单字段生成和重试接口，结果写入候选池。
5. 保存新模板时把最终图片位同步到现有模板图片结构。
6. 补充测试，保护图片顺序、主图位、手动 SKU 图片和发布 payload。

## 验证重点

- 原图和生成图不会互相覆盖。
- 重新生成会新增版本。
- 用户最终选择的第 1 张图进入 Ozon 主图位。
- 用户最终选择的后续图片进入 Ozon 图片列表。
- 保存新模板后重新打开，图片顺序不变。
- 发布前 payload 不丢图、不乱序。
- 手动编辑过的 SKU 图片不会被模板图覆盖。
- 详情图逐张执行对应分镜，不再按固定的通用提示词轮换。
- 详情图继承新主图的背景体系、光线、镜头语言、产品尺度和视觉层级。
- 用户可以在保留的主图方向间改选，最终采用结果写入评测元数据。
- 草稿保存主图自动优选结果、人工改选状态、生成候选数、采用数、复检通过数、纠偏数和各候选质量分。
- 中文文案和提示词保存为 UTF-8。

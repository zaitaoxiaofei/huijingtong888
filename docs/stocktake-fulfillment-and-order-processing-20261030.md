# 双仓盘点与订单处理

## 库存边界

FBS 待发订单从本地实物分配，FBP/FBO/OGR 订单从官方仓发出，不分配本地现货或采购在途。读取订单履约时除了缓存分类，也识别原始单据显式的 `fulfillment_schema`，避免仅有官方履约字段而没有物流名称的订单误入本地池。

库存账本返回 `fulfillment_summary.fbs/fbp`，分别包含待发单数与当前库存产品折算件数。多个明细属于同一订单时只统计一单；件数按实际 SKU/配件组成展开。盘点只提交本地实物或本地可用数量，FBP 官方实物与可用量独立异步加载，缺失显示待核对，官方可用量不再减一遍待发订单。

`fbp_reserved` 表示已审核、尚未发运的本地备货锁定，不是 FBP 客户订单。已发运、已完成申请不再锁定本地实物。读取锁定时统一按 SKU 配方优先、产品组成其次、直接绑定兜底展开，并校验企业、店铺及产品归属。

## 历史记录与规则

- 采购明细分开显示真实采购历史与当前待到货/待验收批次。最近50条历史展示采购数、验收数、在途数、采购人和时间，累计采购数基于全部有效已采购记录。缺少验收记录显示待核对；金额未补齐时不把零单价当作已确认成本。成本仅采购岗位可读。
- FBP 申请明细包含历史状态，保留原始 SKU 申请数并显示按当前组成折算的实物量；明确历史组成并非不可变快照。当前申请与历史发运不混算。
- 本地保障抽屉可编辑生产周期和运往本地仓周期，沿用库存编辑的取值范围。产品字段、有效规则、规则版本及审计在同一事务保存，校验商品时间戳与规则版本。库存编辑和既有周期规则入口也同步更新，保留人工保障数量。
- 卡片计数标为“项库存”，避免将库存产品数误当成订单数。

## 订单界面

左侧入口、路由标题改为“订单处理”。取消独立的上方模式栏，在订单同步操作旁放置模式菜单。默认显示当前模式，悬浮或键盘聚焦时显示切换模式；菜单分别说明打印/打包/发货和库存缺口/采购/验收的职责。库存模式保留返回打印模式的入口，打印组件在切换时不销毁。

搜索类型及文本框缩短。最近成功同步时间移入“同步当前范围”的提示。打印区域约束在窗口内，订单表格仍保留内部横向滚动。

## 核验及发布

生产只读核对：库存21-4有真实历史采购和652件已批准入库；父商品关联存在已完成及已发运FBP记录，当前没有相应本地锁定不代表历史为零。另一次核对时待发为27单/27件，按原始物流资料判断未混入FBP。本轮未修改生产业务数据。

验证覆盖混合履约、历史记录、配件组成、周期跨入口同步、冲突、撤权、多企业隔离以及实际浏览器的菜单和双仓表单。数量算法更新使需求快照版本升为demand-v3；部署后旧版本快照由既有后台队列重建。本轮开发不代表已部署，发布需另行确认并从合并后的最新release构建。

## 历史SKU改绑的补充边界

上线只读核对发现库存21-4的13条已完成申请中，有5条当前SKU映射已变更。历史申请归属仍以原单据的企业店铺、产品及明细为准，不能因当前映射变化而消失；界面通过binding_status标记绑定已变化，保留原申请SKU数量。进行中的待审核、已确认占用和已提交官方申请仍严格校验当前绑定，失效绑定不新增本地锁定。此补修单独提交和验证，不混入已构建的发布包。

# 按角色操作、按实物统一供货

本次开发基于远端release `dd6b0a65fa0e388c867f6448aebe44fdbe5dd35c`，分支 `codex/inventory-role-workspace`。已进一步合入最新release `f95f142cad4f20e620c894656eccf910341421e9` 的统一库存搜索与交互调整。初始基线的图标流程图已单独部署；本分支的新功能等待用户查看页面后再决定上线。

## 页面与工作流

- 订单列表新增“打印与日常发货 / 库存管理”模式。原OrdersPage不改打印、订单筛选、打包和发货逻辑，首次进入打印模式才加载，切换后用真实DOM容器隐藏并保留组件状态。
- 库存管理按实物商品汇总，支持全部库存需求与当前FBS待发订单关联库存。红色必须处理、黄色建议补货、已采购在途和待核对分别筛选；先筛选再分页。沿用最新统一产品搜索栏，精确编号、SKU、名称与结构化属性保持一致；SKU搜索会展开到对应实物子件。
- 点击库存进入已有完整流程图，直接验货登记入库或打开小盘点弹框；实际合格收货与实物总数盘点仍沿用各自既有事务，未到货和验货未通过不提前入库。
- 采购工作台默认库存需求总览，原采购登记和历史能力保留。必需需求先排序，登记采购默认只填必须采购的数量；没有必须采购时才预填可选建议。实际采购仍要求货款和已有权限，源申请按本次用途关联，不把无关建议带入。
- 运营备货建议保留SKU视角，新增“同库存一起备货”进入统一库存明细。可选择多个关联店铺SKU，分别填套数，并展示换算实物合计、现有待审核申请与锁定。未勾选的关联SKU不自动创建；正式提交不被无现货阻止。
- 草稿没有强制采购义务。新建入口和原备货单状态入口正式提交FBP申请后，缺口直接进入共享库存采购队列，通知在同一FBP事务内落库，通知失败则申请整体回滚；重复待审核状态不重复通知。组合/配方按真实子件发送反馈，虚拟父商品不成为重复采购对象。
- 仓库“反馈缺口”会重新核对货源并通知本企业管理员、采购和运营。盘点保存后自动反馈；反馈失败明确提示库存已经保存，可重试反馈，不能重新盘点。反馈不直接增加一条采购数量，库存队列读最新缺口。
- 在途批次显示实际采购时间和已等待天数，不凭空承诺到货日期。采购和运营收到通知后能直接打开对应库存；来源展开可查看提交人、原申请及最近库存反馈。消息角标与正在查看的库存队列合并实时事件后刷新，后台或已切走页面不持续刷新；原60秒通知轮询继续兜底。

## 统一数量口径

三种需求类型：FBS真实订单、本地安全保障、FBP备货。两个紧迫级别：FBS实际缺口与正式FBP申请未覆盖部分为必须采购；本地保障与未正式申请的FBP安全预测为可暂缓建议。

规划保护现有已确认FBP锁定，保留既有订单现货/在途分配与利润成本路径；未确认的正式FBP需求在采购规划中优先于可选安全目标。现货与在途在同一个物理件数池中只使用一次。同SKU预测与提交申请去重，跨SKU按套装组成展开。盘点发现锁定已无实物支持时，缺失锁定也进入必须处理，不被隐藏。

库存明细、图标流程图、预警和采购总览复用同一supply_plan结果。实物、保障或申请证据缺失保持未知，FBP预测缺失独立标记，不能显示为已核实的零缺口。

## 查询、通知与安全

库存总览不再借用“曾经正数入库”预警名单，读取本企业有效实物商品，包括从未入库的已绑定商品；虚拟组成父商品由子件承接，避免重复。按40个商品批量读取，来源和在途/反馈仅补充当前页，所有查询限定企业。只读页面不调用远程Ozon接口，不生成采购或库存流水。

反馈UUID支持重试幂等，更改同一UUID的商品或说明返回409。岗位、成员和商品归属在事务内重新校验；通知限当前企业的有效接收人，实时刷新信号在提交后发送。FBP回调使用同一连接批量核算，不把可能回滚的事务快照写入共享缓存。SKU配方覆盖父组合，存在跨企业组成时阻止提交并提示修正绑定。

切换企业清空列表与旧弹框，过期响应不能覆盖新上下文；盘点响应跨企业时不把旧商品反馈发送到新企业。无数据库迁移、生产数据校准、利润V1或成本分摊公式变更。

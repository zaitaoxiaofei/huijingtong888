# 订单搜索与无变化观察止增：第一阶段

日期：2026-10-24（北京时间）。本阶段仅本地代码和隔离验收；未查询或修改生产业务数据，未迁移、部署、重启服务，未删除存量。

## 对运营的变化

- 桌面和手机订单页输入完整货件号时请求 `searchMatch=exact`，按本企业店铺的货件号或父订单号精准查找；输入片段、商品名或 SKU 继续原有包含查询。旧客户端不传字段，仍使用包含查询。
- API 支持 `searchMatch=contains|exact|prefix`（兼容 `search_match`）。`prefix` 仅对订单号启用，按字面前缀处理 `%`、`_`、`!`；旧包含查询的通配含义不变。非法匹配方式返回 400。界面没有新增控件或改变样式。
- 只取订单行且不请求统计/物流选项时，OGL/物流识别先限制到当前搜索候选，再使用原分类器判断。统计和物流选项仍按原店铺/日期范围计算，分页总数仍由行查询负责。
- 已申请、实际交运、平台运输和倒计时的含义、状态顺序均未修改。

## 查询结构与索引

精准查询的货件号、父订单号使用独立 UNION 分支，最后按订单主键回读。两个分支都通过店铺归属谓词核验当前企业；默认企业的历史 NULL 店铺仍依照既定权限处理。查询隔离不能依赖唯一键代替。

- 当前新库规范定义 `uk_orders_shop_posting_number(shop_id, posting_number)`；这不表示旧库已完成该结构迁移。2026-10-24 只读发布预检显示，现网仍是 `uk_orders_posting_number(posting_number)` 全局单列唯一键，详见本地 `.verification/priority-release-preflight.json`。本轮查询在两种结构下都保留店铺归属校验，不改写该历史唯一键。
- 新增非唯一辅助索引：`idx_orders_shop_order_number_id(shop_id, order_number, id)`。
- 新库规范结构已包含新索引；旧库不自动执行 DDL，没有该索引时结果仍正确，但父订单查询提速可能不完整。
- `scripts/migrate-order-search-indexes.mjs` 要求显式 `--database`，默认只读；只有 `--apply --mysql-admin-socket=...` 才创建缺失索引。使用在线 InnoDB ALTER，不修改行、自然键或历史关联。已有同名但不同结构的索引会拒绝，不自动替换。生产是否执行由发布审查决定。
- 大批量导入后统计信息过旧仍可能让优化器选择较差计划。隔离性能样本在装载结束后仅对随机测试库执行 `ANALYZE TABLE`；本轮没有对生产执行分析或索引维护。

## OGL 不变观察

`refresh` 和 `official-sync` 在持有当前企业批次行锁时，与该动作最近一条记录比较业务内容。完全相同则不重复追加事件；原有最新检查时间、成员同步时间、错误状态仍更新。

官方状态、货位数、配送方式、收录清单或失败原因变化仍保留事件；A→B→A 会保留三次不同事实。创建、确认、交运、撤回、分袋和关闭从不参与去重。查询及比较也不代替任何鉴权或外部结果核验。

本阶段减少的是重复事件增长，并没有把官方快照整体迁到对象存储，也没有清理旧日志。

## 订单历史报表先消除快照频率偏差

`GET /api/orders/status-history/summary` 保留字段结构，并通过 `summary_basis.version=2` 明确口径：

- `total_history_rows`：真实保存的观察行数，用作存储诊断。
- `customer_coverage`：每订单最新已保存事实，统计一次。
- `by_status.count`：曾经进入对应状态/阶段的不同订单数；不是重复快照条数，也不是进入次数。
- `slow_regions`：每订单最新有效送达事实，平均时长不按重复快照次数加权。
- `latest_observed_at`：最近保存的观察时刻，不能冒充最新同步时刻。
- `dedupe`：企业接口只返回 `mode`。进程累计的候选、比较、重复、跳过、错误计数及全局日指标没有企业归属，均省略，不以零或 null 冒充企业数据；本企业订单统计继续返回。现有前端源文件没有读取这些全局字段，无需改布局或组件。

现有 `ORDER_HISTORY_DEDUPE_MODE=off|shadow|enabled` 的默认仍为 `off`；本阶段不自动启用生产跳写。隔离回放证明上述业务统计不随同义快照数量变化，比较失败仍保留正常历史写入。正式切换前还需核查所有生产报表/外部查询消费者和真实 shadow 指标，尤其是原始行数、观察新鲜度的展示；不能把小样本当成全部历史统计已经验收。

## 隔离证据

全部新 MySQL 验收只在显式指定、关闭 TCP 的命名管道实例创建随机数据库，结束后删除自己创建的测试库。外部 Ozon 使用替身；没有创建、确认或取消真实发运。

1. 六万订单，A/B/默认企业及历史 NULL 店铺，同货件号、父订单号、包含冲突、字面前缀、无结果、非法输入和索引幂等均通过。相同机器的一次 SQL 测量：包含查询约 **34.22ms / 30,006 次顺序读取**，精准查询约 **0.57ms / 9 次顺序读取**。这是不同明确匹配语义下的局部 SQL 测量，不是浏览器端到端或生产提速承诺。
2. 并发及服务实例重建后，重复官方核验只保留一条相同观察；重复物流刷新也只保留一条。货位变化、恢复原值、失败和恢复仍留新记录；跨企业与成员撤权依旧阻断。
3. 同一历史输入分别经真实 off/shadow/enabled 写入器回放，本企业保存 **11/11/5** 行，客户覆盖、状态订单数和 **37 小时**平均送达完全相等；真实客户/物流字段变化被保留。模拟比较失败继续插入原历史。未修改生产配置。

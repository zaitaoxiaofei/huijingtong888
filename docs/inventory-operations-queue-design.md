# 库存管理四队列设计预览

本分支基于最新 release `4ac49d1`，保留已发布的库存销量排行及更早修复。用户确认预览后，接入正式订单库存管理和采购工作台。独立预览仍使用演示数据，不调用生产 API。

## 核实当前逻辑

原筛选允许必须和可选采购交叉出现。本次保障补货要求库存已核实、必须缺口为0且仍有可选缺口。有真实订单但未核实的库存仍在必须处理队列提示先盘点，禁止编造数量。

`inventorySupplyPlan`已把现货和采购在途按优先级分配、去重；本地保障的47件是额外净缺口，并非包含必须26件的总量。因此当前例子建议总采购73件。正式FBP申请未覆盖的数量也计入必须采购；FBP客户订单不进入本地池。未知数据不能被当作0采购。

## 队列划分

|队列|一行代表|进入条件|主要动作|
|---|---|---|---|
|必须采购|库存产品|已核实且必须净缺口大于0|登记采购；同时展示必须、可选保障、建议总量|
|保障补货|库存产品|必须缺口为0，可选保障净缺口大于0|自主决定保障采购|
|采购待到货|采购批次|实际已采购、剩余量未到货|填写物流、确认到货；采购超过48小时标红|
|到货待验收|已到货批次|采购已确认签收、尚有未验收数量|核对实物、按实际数量登记入库|

采购两个队列互斥，避免重复操作。批次队列与采购需求可以同时存在：旧批次未到但新需求造成新的净缺口时允许继续采购。若现货加在途已完整覆盖，则不再出现在采购缺口队列。

原“库存待核对”包含账面异常和FBP预测资料未齐，不能改名冒充“到货待验收”。单独保留异常入口，后续应区分本地盘点异常和FBP资料待补；有真实订单的异常应优先提示仓库。

## 界面与交互

搜索在最上方，最左侧库存范围，接搜索方式/内容、精确搜索、查询/重置；右侧读取/核算时间、刷新、重新核算、模式切换。桌面默认单行，属性筛选收进弹出面板，保留完整精确搜索功能。去掉库存管理标题、副标题和常驻蓝色时间提示条。卡片降低高度，按钮靠左。

采购表提供三类净缺口和“必须＋可选＝建议总量”，登记采购可切换“建议总量”或“只处理必须缺口”。在途和验收使用独立批次表，展示采购人、采购时间、等待/到货时长、数量、物流及当前阶段的主操作。

预览使用现有采购计算函数验证数量。模拟签收不会增加本地实物；实际验收才增加。部分验收的剩余量在预览中继续待验收。正式接入时必须根据差异原因区分“剩余已到待验”“余货未到”“缺件/次品”，沿用库存流水、成本、幂等和审计事务，不能只改页面状态。

## 运行与边界

运行`node scripts/build-inventory-operations-preview.mjs`生成演示预览。正式页面使用 purchase-arrivals 实际批次及 open/arrived 汇总。物流编辑只改物流并审计，确认到货不入库，登记入库沿用既有 receipts 数量、差异和成本事务，自动选中对应批次。库存异常保留单独入口。

## 批量登记采购

采购队列支持分页多选，打开采购表前按每20项刷新真实需求。批量表最多100项，可搜索加入其他库存、移除、分别填写件数、货款、运费、链接和备注。库存详情叠加打开，隐藏跳转完整页面入口；关闭详情返回原表，填写内容保留。登记完成留在当前队列，只重读涉及库存。

沿用 POST /api/procurement/purchases，workspace_batch=true 使用严格数量和金额验证、UUID提交标识。锁定库存后重新检查岗位、成员和订阅；原有需求按实际采购量消费，没有需求的库存创建对应记录。采购单、明细、成本版本和在途批次一次事务提交，失败全部回滚。相同提交重试返回原单据，同一标识修改内容返回409。未收到成功响应时保留原提交重试。

上线验证只读检查版本及数量，不创建生产演示采购。

浏览器验证覆盖：队列独立、总建议73件、在途抵扣后退出采购队列、确认到货不加实物、验收入库流转、窄屏与零API请求。另有四项实际计算模型测试验证在途抵扣和正式FBP需求优先。

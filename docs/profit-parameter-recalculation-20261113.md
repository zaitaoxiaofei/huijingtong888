# 库存参数与订单预估利润重算

本次仅开发和本地验证，不部署、不重启或修改生产配置。任务基于远程发布分支 `release/2026.10.21-task-brand` 的 `adcb484c` 创建。

## 修复和使用方式

- 每日汇率订单的利润详情改用当前生效的预估修订，而非首次预估。即使当前预估不在最近 20 条历史记录中，也按当前修订指针独立读取；首次和历次记录保留在折叠历史明细中。不能证明的历史费用仍显示未知。
- 单笔重算后强制刷新列表及详情。订单内编辑库存后也清理详情缓存。
- 在共用库存编辑窗口修改克重、尺寸、成本、物流规则、费率等计算参数，保存后显示变更及重算范围；从利润差异处理页进入时保留显式重算提示。保存后建草稿同样先处理该提示。
- 重量或成本修正建议重算已有未结算订单；渠道或运价切换建议仅后续订单生效。可按北京时间订单日期、未结算/未发货筛选。
- 重算运价可选每单冻结版本、商品当前选定版本、指定运价版本。保留每单利润公式版本及下单日汇率，不迁移历史公式。缺少原运价、规则不适用、已结算/锁定、结束/售后订单会显示跳过原因。
- 先预览数量、运费及利润差额，再确认写入。预览令牌绑定企业、范围、商品、订单及报价输入；执行前重新计算并校验。在事务内再次检查库存参数、订单数量/费用和结算锁，拒绝过期预览。
- 普通订单状态同步沿用当前预估记录的库存参数，避免将“仅后续生效”变成下一次同步时修改历史订单；显式重算才推进参数版本。并发旧同步不能覆盖较新的手动预估。
- 每次最多处理 1000 个候选商品行，超出时需缩小日期范围。批量按商品行事务提交；部分失败会返回已更新数量及失败原因，不把整批显示为成功。明细快照和不超过 31 天的关联汇总随后刷新。

## 验证

隔离 MySQL 测试只使用指定的本机 socket、TCP 关闭的测试实例和随机数据库，结束后删除自己创建的测试库。未读取或写入生产订单用于本次实现验收。

- 合成复现：重量 0 克按现有最低 10 克逻辑得到 5.04 元；改成 300 克，通过真实单笔重算及商品批量重算得到运费 12.06 元、预估利润 43.77 元，真实详情接口返回相同结果。
- 核对历史修订保留、冻结公式、企业隔离（含跨店错误绑定）、默认企业历史 NULL 归属及 `admin` 汇率键、预览失效、锁定订单跳过。
- 82 项专项单元/回归测试通过，覆盖当前修订读取、零利润及未知值、V1 公式等价、事务写入、范围和版本选择、同步参数保持及并发旧结果拒绝。
- 浏览器使用真实共用库存编辑组件和新重算组件，模拟 API：实际将 0 克改为 300 克保存，自动弹出变更提示，执行预览再确认；确认请求带预览令牌。浏览器组件错误记录为空。截图采用演示数据。
- 前端构建、UTF-8 编码和 SQL 绑定检查通过。

扩展检查共 34 项，29 项通过、5 项失败；在临时目录从干净发布基线 `adcb484c` 导出相同源码后重跑，复现同样 5 项失败。本次没有引入新增失败，也没有修改相关财务回填、风险页文案和路由隔离逻辑。已有失败为：

- `profit reconciliation exposes inventory evidence and component variances`（库存风险页文案断言）。
- `finance backfill sync is windowed and does not apply profit by default`（财务回填源码形态断言）。
- `default ordinary staff and customer staff share only exact verified daily catalog gates`（已有生成路由开放范围断言）。
- `default enterprise uses the same fail-closed order ownership and safe enrichment as other enterprises`（订单归属函数源码断言）。
- `paging, counts, derived coverage, logistics cache and picking all keep an explicit enterprise`（订单分页函数源码断言）。

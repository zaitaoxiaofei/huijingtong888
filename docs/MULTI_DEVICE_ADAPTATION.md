# 爆单 ERP 多端适配方案

## 目标

- 27 寸显示器利用额外空间，但不作为最低设计宽度。
- MacBook 14 寸和 Windows 15.6 寸在系统默认缩放下无需调整浏览器缩放。
- iPhone 竖屏可以完成高频查看、筛选、审批和异常处理任务。
- 平板根据方向使用单栏、双栏或列表详情布局。
- 前端展示可以变化，API、权限、状态和业务逻辑保持共享。

## 窗口等级

| 等级 | CSS 宽度 | 主要环境 | 布局策略 |
| --- | ---: | --- | --- |
| compact | `< 768px` | iPhone 竖屏 | 单列、底部导航、独立详情 |
| medium | `768–1023px` | 平板、手机横屏 | 单列或列表详情切换 |
| compact-desktop | `1024–1279px` | 小窗口、较高系统缩放 | 紧凑密度、收敛次要信息 |
| standard | `1280–1599px` | MacBook、Windows 笔记本 | 主要开发和验收基准 |
| expanded | `≥ 1600px` | 27 寸显示器 | 展示更多信息或辅助面板 |

断点描述窗口能力，不识别具体设备型号。断点之间仍使用 Flex、Grid、`minmax()` 和容器剩余空间弹性变化。

## 组件策略

1. 应用壳层：桌面侧栏、平板抽屉、手机底部导航。
2. 表单和设置：桌面多栏，窄屏单栏，操作区允许换行。
3. 看板：宽屏多列，逐级降为两列和一列。
4. 列表详情：宽屏同屏，手机分别进入列表页和详情页。
5. 数据表格：优先级列、列显隐、详情抽屉和横向滚动组合使用。
6. 资源列表：订单、商品、采购等在手机上使用卡片，数字对比仍可使用精简表格。
7. 复杂工作台：桌面保留完整编辑；手机先支持查看状态、校验、审批、重试和关键异常处理。

禁止通过 `transform: scale()` 或全局 `zoom` 缩放应用画布。固定像素可以用于触控目标、图标、缩略图和间距，不应用作页面主内容的最低宽度。

## 界面密度

- 自动：`compact-desktop` 使用紧凑密度，其余桌面使用标准密度。
- 舒适：增加表格和页面留白，适合大屏查看。
- 标准：笔记本默认模式。
- 紧凑：压缩间距和表格行高，不把正文压缩到不可读尺寸。

用户选择保存在浏览器本地；密度只改变尺寸变量和组件间距，不改变业务字段和页面功能。

## 验收矩阵

- 桌面：2560×1440、1920×1080、1536×864、1440×900、1280×800。
- 平板：1024×768、834×1194、768×1024。
- 手机：430×932、402×874、390×844，另测横屏和安全区域。
- 每个尺寸检查导航、筛选、主操作、弹窗、抽屉、表格滚动和键盘输入。

## 迁移顺序

1. 公共壳层、窗口等级、密度、弹窗和测试基线。
2. 经营首页、设置表单、库存列表、订单列表、订单详情五类样板。
3. 批量迁移普通业务页面。
4. 商品上架、选品和 AI 工作台逐页设计移动任务流。

## 可行性结论

当前 Vue 3、Pinia、Element Plus、移动路由和响应式 CSS 足以支持方案，不需要更换框架。已有手机订单和采购页面可以作为专用移动任务流继续扩展；桌面页面通过共享状态、CSS 变量和局部响应式组件渐进迁移。主要风险来自大型固定宽度表格和受保护工作台，应逐页处理，不能用全局 CSS 强制压缩。

## 当前实施基线

截至 2026-08-26，前端页面盘点包含 81 个 Vue 页面，其中约 50 个页面包含数据表格。全站适配采用两层保障：

1. 全站安全层统一处理内容边界、工具栏换行、筛选表单、标签页、分页、摘要网格、弹窗和宽表触控滚动。
2. 页面规则负责复杂工作台的列优先级、面板重排、卡片化和手机专用任务流，不能依赖全局规则压缩业务界面。

已建立的手机专用任务流包括：首页、订单、订单详情、采购、库存、库存预警和在线商品。其余桌面页面在手机“电脑版”模式下由全站安全层保证可访问，再按业务优先级继续优化交互效率。

普通业务页面的最低验收要求：

- 页面根节点不得产生不可控的整页横向溢出。
- 筛选控件在 767px 以下变为单列且宽度不超过视口。
- 三列以上摘要区域在手机下降为两列，420px 以下下降为一列。
- 宽表保留字段和排序语义，通过局部横向滚动查看，不缩放字体。
- 固定列在手机上不得覆盖主体内容。
- 弹窗、消息框和抽屉不能超过可视宽度。
- 复杂编辑页允许保留桌面画布，但必须提供清晰的局部滚动和返回入口。

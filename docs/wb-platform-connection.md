# WB 中国主体接入

当前验收阶段：在现有 ERP 配置 WB 店铺并读取真实平台数据。没有独立 Demo 页面。Ozon 的原有在线商品和上架页面保持独立；订单沿用现有表格，平台标识用于区分记录；平台活动使用 Ozon / WB 页签。

## 首次配置与验收

1. 在“企业店铺 → 新增店铺”选择 WB（中国主体），填写本企业负责人、店铺名称和 API Token。现有店铺不能转换平台，正式环境和沙箱分别建店。
2. Token 类别包括 Content、Marketplace、Prices and Discounts。先做拉数验证时可以使用只读授权；POST 形式的查询也不会因此成为平台业务写操作。
3. 点击“检查授权”。正式店铺核对各服务连接及 `common-api.wildberries.cn/api/v1/seller-info` 返回的卖家身份。换 Token 后必须重新检查；不能用另一卖家的 Token 替换已有店铺身份，也不能在同一企业重复绑定同一 WB 卖家。
4. “绑定 WB 仓库”读取此店铺的卖家仓目录。这个仓库是自有仓 FBS 的销售库存入口，不是 WB 平台托管仓。
5. “运营 → WB 在线商品 → 同步商品”读取真实商品卡及规格。没有授权或尚未同步时显示明确空状态，不注入示例数据。
6. 在原有订单页面选择 WB 店铺，使用现有的拉取／同步按钮。首轮读取新订单、所选日期范围的订单及已知未完结订单状态。WB 订单和 Ozon 订单在同一个列表中展示。

合肥揽收点的承运商、线路和交接要求暂不预填，不影响授权和拉数。WB 平台业务写操作由 `src/shared/wb-capabilities.js` 的验收阶段开关关闭，包括上架、图片、改价、发布库存、备货、面单及交接；库存绑定也暂不开放。Ozon 操作不受该开关控制。真实店铺拉数验收后，再分别验证并开放这些能力。

## 数据与库存

- `shops.platform` 默认为 `ozon`。WB Token 位于 `wb_shop_credentials`，不返回客户端；客户端仅接收是否配置和检查时间。
- Ozon 的既有店铺字典和同步任务继续只读取 Ozon；WB 店铺使用明确的 WB 路由。所有 WB 路由采用会话中的企业，并重新验证成员、订阅和权限，不接受请求中的企业 ID。
- WB 商品卡独立存入 `wb_product_cards`。规格通过店铺、平台商品编号和规格编号关联内部 SKU，后续绑定仍使用共同的基础商品及组件库存。
- WB 订单进入现有 `orders` / `order_items`；`wb_order_details` 保留平台原始单号、状态和供货批次。WB SKU 在兼容的旧字段中使用 `WB-<chrtId>`，不会当成 Ozon 商品编号。
- WB 原币金额保留在原始数据中显示，不能写进既有 CNY 利润金额。WB 尚未接入利润核算，禁止套用 Ozon 公式。
- 已实现但未开放的库存适配复用既有组件展开和库存流水；重复同步不重复扣货。交接前取消只释放一次；交接后取消不能自动认定实物退回。
- 自有仓与未来 WB 平台仓不是同一个库存位置。本轮只接 FBS 卖家仓，未来平台备货需要独立的调拨、在途及收货接口。

## 物流研究结论

已核对的官方文档：

- [WB 中国区商品、卖家仓和库存](https://dev.wildberries.cn/docs/openapi/item-management)
- [WB 中国区 FBS 订单、面单和供货批次](https://dev.wildberries.cn/docs/openapi/orders-fbs)
- [WB 中国区促销日历](https://dev.wildberries.cn/docs/openapi/promotion)
- [WB 测试环境及 FBS / DBS 状态模拟](https://dev.wildberries.cn/docs/openapi-other/sandbox-environment)

FBS 的 `supplierStatus` 和 `wbStatus` 分开保存：`new` 对应待备货；`confirm` 对应待交接；`complete + waiting` 只说明交接已提交，不能认定承运商已揽收。`accepted_by_carrier` / `sorted` 说明实际物流推进，`ready_for_pickup` 仍是待买家取件，`sold` 才是已签收。未知状态保留为待核对。

官方 FBS 文档中，向特定交货点送货涉及运输箱、箱标签和供货批次二维码；订单面单、箱标签和批次二维码不是同一个东西。中国跨境揽收点不能仅凭名称就套用俄罗斯交货自提点要求。因此揽收点交接方式保留“尚未核对”，不影响读取订单。

自有物流属于 DBS / Express DBS 等独立履约模型。官方沙箱文档列出 `dbs`、`dbsPickupPoint`、`edbs`；这不能证明某一中国主体账号已开通正式业务资格。需要从实际店铺权限、仓库类型和 WB 卖家后台继续确认。本次没有开放 DBS，也不把它映射成 FBS 发运。

## 发布与后续扩展

上线前运行兼容数据库初始化：新增平台字段及 WB 表，不重写历史 Ozon 记录。遵循现有发布分支、准确合并提交和 ECS 明确批准规则。回退代码时保留新增表及数据，不做破坏性回滚。

Yandex 后续需要自己的授权、商品、活动及履约适配器；当前未知平台会拒绝执行 Ozon 履约，不能默认当成 Ozon。共享的是商品、实物库存与订单展示习惯，不共享平台原始状态和 API。

## WB 模板与草稿审核

WB 使用独立的 `wb_listing_templates` 和 `wb_listing_drafts`，不修改 Ozon 的模板表、草稿内容、上架服务或利润公式。入口为“运营 → WB 商品上架”，沿用 Ozon 上架工作台的主要信息、商品表格、属性、图片和顶部操作区。先选择 WB 一级/产品类目，系统自动获取字段并匹配或生成类目模板；填写资料、人民币价格和图片后，再选择目标店铺保存、校验和预览。无需手动导入模板。

模板从 WB 中国区类目和属性接口动态取得完整结构；父类目、搜索分页和属性结构按企业及正式/沙箱环境独立缓存在 wb_catalog_cache，有效期 6 小时，过期会回源并可手动刷新。接口失败时展示带明确过期提示的旧缓存。更换类目时清空旧类目属性，保留标题、图片、包装和价格。模板保留属性编号、数据类型、必填标记和单位。模板默认属性只作用于新套用的草稿；修改模板不会覆盖已经保存的商品草稿。商品草稿保存模板版本和属性快照，校验时再读取 WB 最新要求。

引用现有商品草稿通过原有、受企业权限约束的草稿读取服务取得 `effective_images`。不回写原草稿，不继承 Ozon 类目 ID、字典 ID、售价、运费和利润公式。已手工清空的草稿图片不会回退到历史采集图。图片支持上传、直链、预览、删除和拖动排序。

中国主体 WB 草稿明确记录人民币 `CNY`。WB 中国卖家官方商品录入说明注明价格以人民币设定：https://seller.wildberries.ru/instructions/ch/ch/material/how-to-add-item-cards-china 。平台面向买家的卢布展示和转换不由本次模板适配计算。

本轮只开放 ERP 内部模板及商品草稿的保存、校验和预览。`WB_REMOTE_WRITES_ENABLED` 继续关闭；没有开放创建商品卡、生成条码、上传 WB 图片、改价、发布库存或订单履约写入。缺少条码可保存草稿，但会在发布资料校验中明确提示。用户审核前不调用发布接口。

本次钥匙套审核资料单独保存在任务工作区，包含货号 WF-24244810-1、候选类目 3373、用户指定的 258 CNY、8 张当前有效图片；不会将真实商品资料提交到公开代码仓库。正式商品内容需用户审核，原 Ozon 草稿中的车型文案冲突不会自动回写修复。

WB 目录缓存和模板/草稿基础表由 migrate-wb-listing-catalog.mjs 纳入发布前只读检查及兼容迁移，不依赖线上手工初始化。

WB 工作台采用紧凑双栏布局。图片和视频集中在独立素材区，支持多图顺序上传、拖动排序、选择删除、单个视频上传或链接、视频预览和草稿保存；视频使用独立 video_url，不混入图片顺序。上传复用现有 ERP 素材服务，实际存储仍要求 OSS 配置完整。类目字段数量及缓存来源只写服务端日志，用户页面只保留必要的失败及恢复提示。

WB 上架表格沿用现有上架操作习惯：顶部店铺与变体策略、每行一个款式/颜色变体、按行编辑素材和尺码、显式“同首行”、下方共用属性。WB 独立实现，未改 Ozon 受保护页面。旧单商品草稿兼容读取为单行，多变体保存到同一草稿 payload.variants；首行 card/images 保留旧读取契约。货号按 WB 长度限制生成，保存时以店铺锁序列化检查全部变体与其他草稿、在线商品的货号冲突。合并策略不允许非 isVariable 属性出现差异，变体、尺码条码不得重复。

颜色、性别、生产国、季节、税率和 FEACN 使用 WB 官方专用目录；不将普通文本属性误判为字典。目录按企业、正式/沙箱环境、语言、类目适用范围缓存；客户端仅提交选中值，预览及校验再次核对目录。2026-11-13 用已配置中国主体店铺做只读核对，colors/countries/vat/tnved 接口可用。首图视频复用现有 generateAiVideo 服务，保留每行 video_url/video_source_image，未执行真实视频生成或 WB 发布；后续人工验收确认生成结果和素材存储。

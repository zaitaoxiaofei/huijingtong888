# 库存编辑分区与入口统一

## 入口与权限

- 手机商品库存卡片、只读库存明细及已绑定本地库存的 FBP 预警卡片增加“编辑库存”和“历史版本”，沿用同一套库存资料编辑器与历史窗口。
- 手机采购待到货、到货待验收及库存页的核验收货共用现有批次入口；元数据操作始终使用 `row.product_id`，不用采购批次 ID。
- 电脑端商品库存、库存明细、采购及收货中的库存身份区，以及已绑定实际库存的 FBP、SKU 和备货库存行提供相同入口。未绑定实际商品的行不推测商品 ID；已删除商品保留历史入口，沿用原恢复流程后再编辑。
- 编辑仍要求 `inventory.write`，历史查看仍要求 `inventory.read`。新增按钮不扩大岗位权限，沿用既有库存计算、验收、SKU 绑定及编号规则。

## 手机编辑分区

原库存表单保留，手机通过分区直接定位：

| 分区 | 内容 |
| --- | --- |
| 名称规格 | 核心品名、品牌车型、颜色、款式、材质、工艺及主图 |
| 计量包装 | 产品规格数量、单位、包装及重量长宽高 |
| 组成配件 | 已选组成件、赠品、添加和查找子产品 |
| 采购物流 | 负责人、供应商、采购链接、成本、周期与物流配置 |
| 定价预估 | 已有价格参数及预估模型 |

顶部显示名称摘要和分区导航，底部保留历史、取消与保存。数量与单位、适合短值的规格和包装尺寸采用并排布局；组成分区优先显示已选配件，查找添加区按需展开。手机审批管理和主图等次要区域可展开查看；不删除审批、图片、规格或组成操作。切换分区只改变显示，所有表单值和组件引用保留，保存仍提交原完整结构。校验失败时显示对应必填字段所在分区；切区不表示保存成功。电脑端保留既有横向表单布局。

## 保存与刷新边界

- `PUT /api/products/:id` 实际回执为 `{ok:true, product: DTO}`。编辑器的 `saved.product` 必须是商品 DTO，兼容旧调用返回的裸 DTO，不能把整个回执嵌套成商品对象。浏览器验证使用真实回执结构，避免只用裸 DTO 模拟而漏掉跨入口刷新问题。
- 手机商品库存保存资料后刷新当前筛选、页码和数量展示；只读明细独立发送 `metadata-saved`。这个事件不得冒充盘点的 `saved` 回执或生成 `physical_after`，避免采购队列将资料修改当作实物调整。
- 手机 FBP 预警保存资料后，按已应用的查询条件重读已加载的全部页，更新本地库存名称和编号；保留线上 SKU 标题及原 FBP 指标语义。未点击查询的新输入不改变正在浏览的筛选。
- 历史窗口沿用已有只读接口及旧号、旧名称、资料版本展示；历史留存范围见 [库存编号与历史版本](../inventory-numbering-v2.md)。
- 本轮不修改后端合同、编号触发器、数据库结构、库存计算或采购验收事务。手机相机、键盘与设备操作仍需真机验收；浏览器手机视口验证不冒充真机测试。

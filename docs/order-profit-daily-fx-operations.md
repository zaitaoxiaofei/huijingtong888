# 订单每日汇率归档运行验收

每日参考档案使用俄罗斯央行官方历史 XML 的 CNY 报价，方向为 **1 人民币 = N 卢布**。这是每日官方参考值，不是银行实时成交价。北京业务日期和央行实际生效日期分别保存；休市时可以是较早的真实生效日，但不能提前使用未来报价。

## 启用顺序

1. 先运行 `scripts/migrate-order-profit-daily-fx.mjs --database=目标库 --mysql-admin-socket=本机管理员套接字` 只读审计，确认连接目标；增加 `--apply` 才创建公共日档表。
2. 对 `scripts/migrate-order-profit-fx-policy.mjs` 使用相同明确连接参数。默认只读；`--apply` 只创建订单汇率伴表。另加 `--activate` 才首次记录实际启用 UTC 时间及当时最大订单 ID。重复启用保持原边界。
3. 服务正常启用现有定时任务系统后，任务 `order_profit_daily_fx_archive` 每 15 分钟检查北京昨日、今日两天，重启后也只补这两天。已有日档直接回读，不重新请求或覆写，不扫描旧订单历史。

这些脚本不读取应用默认数据库配置，不改旧 `exchange_rates`、旧订单或历史利润。订单是否使用新规则还受首次启用时间和旧订单 ID 双重边界约束。归档本身不会触发利润重算。

启用 V2 之前必须确认生产主服务和所有候选／后台写入进程都已运行支持 V2 的同一版本。先建伴表和部署代码，再明确激活；不要在旧写入进程仍运行时提前激活。激活后不支持删除该启用设置作为回滚手段，已有 V2 订单必须继续由支持 V2 的版本处理。

## 订单核算口径

- 已存在订单、晚同步的旧订单及已经固定为 V1 的明细均不升级；即使后来补齐下单时间，也不能给 V1 订单换算价格或混入 V2 新明细。
- 新规则订单把卖家原币金额、币种与下单北京日存入企业所属订单伴表。预估引用该日档案，首次有效预估的全部费用与总利润留在修订中；后续重算不覆盖首次基线。
- 签收依据官方实际签收时间（含 `fact_delivery_date`），冻结签收北京日及对应档案。没有真实签收时间时不采用同步时间、预计到达日或今天代替。费用后来补齐仍使用原冻结汇率；实际利润可随真实账单增加产生新修订。
- 未签收的取消／拒收没有虚构签收日，使用下单日档案并明确 `no_delivery_order_day` 依据。签收后退货继续沿用冻结的签收日；V1 的取消与售后处理不变。
- 纯汇差用同一份实际原币净额按下单／签收日各折算一次比较；人民币采购、包材及其他成本不重复换汇。成本与实际费用变化单列业务差额，分位尾差单列。签收日汇率不用于重选下单时的物流计价版本及佣金档位。
- 缺少币种、下单价、日档、签收证据、有效预估或必需账单项目时明确等待核对，不以 0 元假称实际利润。旧财务表的历史换算列保持原样，V2 从可核实的原币重新换算；详情及缓存使用已提交的 V2 投影，不能按历史换算列再次重算。

## 已核对的币种与剩余账单同步问题

2026-10-26 只读抽查最近 200 条原始财务 JSON，没有币种字段。随后用户核对已签收订单在 Ozon 官方财务页面的收入、佣金和物流费，确认原币为卢布；另明确 ERP 的财务统一采用人民币核算、展示，费用核算规则为平台公共规则。该人工审核依据由下方显式脚本留档，仅适用明确的 Ozon 财务接口；原始接口已有明确币种时仍优先采用原币证据。

只读排查另发现生产财务流水最新业务日期仍为 2026-09-08，近期六个店铺的财务同步均在旧 `/v3/finance/transaction/list` 返回 `404 page not found`。随后对官方新 `/v1/finance/accrual/types` 和 `/v1/finance/accrual/by-day` 做只读请求，均返回 HTTP 200；得到 135 项费用类型与新日期账单，原币金额明确，抽样净额均对平。新读取、归一化、事务写入和 V2 签收核算已接线；生产恢复结果仍须在部署后核验。见 [新接口验证记录](ozon/finance-accruals.md)。

新源仅在 V2 全局启用后接入，按店铺避开旧接口已保存的最后业务日，避免两种编号体系重复记账。旧来源最后一天可能未齐，单独待核对，不能以 `MAX(date)` 证明该日完整。新计提在店铺锁内发现同日旧来源时拒绝混入；不会删除旧流水。新增晚到账单即使关联 V1 订单，也不自动改写旧订单利润。其他已确认的新来源事实可保存；未知金额/类型明确待核对，不用推测凑出实际利润。

本轮已通过 221 项聚焦测试、41 项发布流程回归以及前端生产构建、UTF-8、SQL 绑定和 API 文档校验。实库管道覆盖分页、原币入账、幂等、凭证引用保护、晚到费用及企业隔离。模拟数据验证下单率 10、签收率 12.5、真实净卢布 800、人民币成本 25 时，实际利润 39、纯汇差 -16；晚到费用按原签收率重核，不覆盖初始预估及冻结 ID。ECS 只读取价成功返回北京 2026-10-26 对应汇率 12.0557、央行生效日 2026-10-24；网络失败明确待补并重试。本机访问央行超时，未往生产写入测试记录。上线迁移、每日实际落库与定时任务验收仍须单独执行，不能将本地通过写成已部署。

## 核查方式

- 平台超级管理员可读取 `GET /api/exchange-rates/daily-archive?from=2026-10-25&to=2026-10-26&page=1&pageSize=30`。此接口只查数据库，不取价、不写入；普通企业员工和企业管理员无此平台审计权限。
- 记录应包含业务日、央行生效日、固定 12 位小数的汇率、原始名义数量/报价精度、官方请求 URL、XML 摘要以及抓取和入档 UTC 时间。用户界面或导出应统一转换为北京时间。
- 定时任务历史应显示成功或失败。某天抓取失败仍检查另一日，已成功入档的记录保留；错误摘要说明缺哪一天，后续重试只抓缺日。失败不写假汇率、不使用 11.32 或今日值冒充历史。
- 多个进程同时归档同一天，只保留首次成功入档值；供应商后续修正也不覆写已保存档案。只读历史查询支持日期范围及最多 100 条分页。

## 本地验证边界

聚焦测试使用 `TENANT_TEST_MYSQL_SOCKET=\\.\pipe\OzonSaasLaunchTest`，先断言 MySQL 已关闭 TCP，再创建随机前缀测试库；结束时只删除该测试库。使用模拟官方响应验证并发、休市日、失败重试和日期精度，不调用生产业务接口或更改生产数据。源码验证完成不代表已部署或已启用。

## 公共规则与原币明细

用户确认各企业共用费用核算规则，ERP 财务统一以人民币计算、展示，Ozon 账单和真实订单原币明细可展示卢布。公共规则不包含企业业务数据，各企业订单及成本仍隔离。

新按日接口已经逐金额返回明确 `currency`；读取同一金额对象的币种进行折算，不再为旧失效接口部署人工默认币种，也无需逐店手工配置。CNY 金额保持原值，RUB 按已归档日期汇率换算；其他或缺失币种保持待核对，不猜测成 RUB。原始卢布记录保留用于对账，用户界面利润和成本仍为 CNY。

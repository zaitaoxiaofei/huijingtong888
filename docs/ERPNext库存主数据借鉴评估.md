# ERPNext 库存主数据借鉴评估

## 结论

不建议用 ERPNext 整体替换现有系统。建议保留现有 Ozon、多店铺、订单和库存业务链路，借鉴 ERPNext 的物料主数据、规格变体、产品套装、仓库和替代品模型，在现有系统内建立统一库存主数据中心。

ERPNext 能提供成熟的库存建模思路，但“多人用不同叫法重复创建同一产品”属于主数据治理问题，不能只靠更换 ERP 系统或模糊搜索解决。

## 当前数据观察

本次对现有 MySQL 数据进行了只读统计：

| 指标 | 结果 | 含义 |
| --- | ---: | --- |
| 有效 SKU 绑定 | 1,020 | SKU 与库存品的映射规模已经较大 |
| 被 SKU 引用的库存品 | 391 | 统计口径包含当前映射引用的库存品 |
| 绑定多个 SKU 的库存品 | 167 | 约 42.7%，多 SKU 共用库存是核心业务形态 |
| 跨多个店铺使用的库存品 | 130 | 约 33.2%，库存主数据必须是全局共享的 |
| 单个库存品最多绑定 SKU | 87 | 不能让 SKU 名称承担库存品身份 |
| 单个库存品最多覆盖店铺 | 5 | 店铺应绑定统一库存品，不能各自创建库存品 |
| 当前有效主/库存产品 | 346 | 当前库存主数据统计口径 |
| 已结构化产品 | 40 | 约 11.6% |
| 未结构化产品 | 306 | 约 88.4%，是同物异名和搜索困难的主要风险 |
| 组件关系 | 36 | 涉及 17 个父产品和 25 个可复用组件 |
| 已启用 SKU 配方 | 0 | 配方模型存在，但尚未成为实际主流程 |
| 规范化名称重复组 | 3 | 仅能发现标点、空格、大小写层面的重复，语义重复会更多 |

以上结果说明：多 SKU、多店铺、通用配件并不是异常，而是系统必须原生支持的业务模型。当前最明显的问题是结构化覆盖率不足，而不是搜索框本身。

## 建议的数据模型

### 1. 全局库存品

每个真实可计库存的物品只创建一次，并分配不可变的系统编码。显示名称可以调整，但库存流水、采购、盘点、绑定关系全部引用系统编码。

建议唯一身份由以下结构字段生成指纹：

- 核心品名
- 品牌
- 车型或适配范围
- 规格、材质、颜色
- 包装数量和库存单位
- 制造商料号或条码

数据库对完整指纹增加唯一约束，避免并发或绕过前端造成重复建档。

### 2. 店铺 SKU 只是销售别名

建立 `店铺 + SKU/Offer ID -> 库存履约定义` 的映射。不同店铺、不同标题、不同语言和不同 SKU 可以映射到同一个全局库存品，不能因为叫法不同复制库存品。

### 3. 原子配件和虚拟套装

真正入库、盘点和扣减的是原子库存品。一个销售 SKU 如果由多个通用配件组成，应保存为套装/配方：

`销售 SKU -> 组件 A × 数量 + 组件 B × 数量 + ...`

套装本身通常不存库存，订单出库时按配方扣减组件。这样同一个通用配件可被多个产品和店铺复用，不需要复制库存。

### 4. 别名与替代品分离

- 别名：同一个库存品的不同叫法，用于搜索命中，不产生新库存。
- 替代品：两个不同库存品在业务上允许互换，必须由有权限的人维护。

不能把别名当成替代品，也不能用模糊搜索结果自动判断两个库存品相同。

### 5. 仓库与货位

库存余额应落在 `库存品 × 仓库/货位`，店铺和用户只拥有映射、权限或业务归属，不分别拥有同一物品的库存主档。

## 建档和合并治理

普通操作员不应直接自由创建正式库存品。推荐流程：

1. 先按核心品名、品牌、车型、规格等结构条件搜索。
2. 系统展示精确匹配和疑似重复候选。
3. 找到已有库存品时，只新增 SKU/店铺别名绑定。
4. 确实不存在时，提交“新库存品申请”。
5. 主数据管理员审核后生成正式编码。

重复品合并时应保留审计记录，并迁移 SKU 映射、组件关系、采购关联和库存流水；不能简单删除旧产品。合并前必须校验库存单位、组件配方和库存属性是否兼容。

## 分阶段落地

### 第一阶段：堵住新增重复

- 建立统一编码和结构化唯一指纹。
- 创建时强制先搜索，展示疑似同品。
- 普通用户以“绑定已有品”和“申请新品”为主。
- 核心品名保持 7 个字以内，但不把短名称当唯一身份。

### 第二阶段：治理历史数据

- 为 306 个未结构化产品补齐关键字段。
- 建立别名词库和疑似重复审核队列。
- 优先治理 SKU 多、跨店铺多、库存余额高的产品。
- 合并时保留旧名称作为搜索别名。

### 第三阶段：统一组件和配方

- 明确原子库存品、套装和成品的边界。
- 将通用配件统一为共享组件。
- 把现有组件关系和 SKU 配方收敛为一套履约模型。
- 订单、分拣、打包都读取同一份版本化配方。

### 第四阶段：仓位与运营治理

- 建立仓库、库区、货位层级。
- 增加条码、制造商料号和替代品管理。
- 监控新品重复率、结构化覆盖率、无效 SKU 映射和待合并数量。

## 建议验收指标

- 新建库存品结构化字段覆盖率达到 100%。
- 历史有效产品结构化覆盖率逐步达到 95% 以上。
- 新增疑似重复品率低于 1%。
- 所有有效店铺 SKU 都能解析到一个库存品或一个完整组件配方。
- 通用组件只保留一个全局库存身份。
- 合并前后库存总量和库存流水可核对、可追溯。

## 数据口径说明

上述统计来自当前数据库的只读聚合查询。`391 个被 SKU 引用的库存品` 与 `346 个有效主/库存产品` 使用的筛选口径不同，不应直接作为同一总体比较。规范化名称重复仅处理大小写、空格和标点差异，因此是保守下限，不能识别近义词和业务语义上的同物异名。

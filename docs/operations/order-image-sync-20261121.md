# 订单信息同步与主图补齐

用户要求保留每十分钟的自动订单同步，只停止订单主图的批量更新。状态、数量、物流等订单信息仍按既有同步入口更新；本次不调整调度频率、利润计算或库存规则。

## 图片写入边界

- 批量同步、定时同步和按货件号同步都不主动查询商品图片、不下载图片正文，也不触发订单图片的 OSS 归档或完整读回校验。
- 已有订单商品保留已保存的 `ozon_image_url`，同步也不覆盖已有在线商品的主图。缺图不会在下一轮同步中自动补齐。
- 新订单商品可以保存订单接口直接附带的图片地址或同店已保存的在线商品图片，不为找图额外调用商品接口。
- 主图缺失或加载失败时，由有订单管理权限的用户点击“补同步主图”。图片加载错误只改变显示状态，不会自动提交补图请求。

## 单订单接口

`POST /api/orders/:id/sync-images` 只接收一个订单 ID；可用 `{ "item_id": 123 }` 进一步限定该单的一个商品。接口不接受客户端图片地址、跨订单商品、订单数组或批量补图参数。

服务核对当前有效会话、企业、店铺和订单商品归属，优先按该单的 SKU 查询官方商品图片地址，只更新指定订单的图片字段并清理订单读取缓存。补图只读取图片地址，不下载正文或重新归档 OSS。它不调用整单业务同步，不修改其他订单、共享商品主图、利润或库存。

响应结构为 `{ ok, order_id, updated_count, failed_count, items }`，每个 `items` 结果包含 `{ id, ozon_sku, image_url, updated, error? }`。`ozon_sku` 来自已核对归属的订单商品，供旧版列表缺少商品 ID 映射时局部更新。部分失败保留原图，界面给出失败反馈；重新请求只由用户点击触发。地址未变化时也只重新加载用户点击的那张图片。

## 费用与发布边界

这项修改消除订单同步触发的批量图片归档和公网读回路径。正常查看图片及其他业务的 OSS 使用仍可能产生流量，不能承诺整个账号公网流量归零。

生产发布需要在本地行为、企业隔离和桌面／手机操作验证后，另行取得本次 ECS 发布批准。本文档不授权生产配置修改或重启。

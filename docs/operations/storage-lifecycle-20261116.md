# 自动存储生命周期（待批准发布）

任务基线为远端 `release/2026.10.21-task-brand` 的 `0da62d256c2d29768fc6fc3f509b78ee5697c940`。已兼容后续远端发布 `9193a08658ac60a9df06e464597fa356c758f306`。最终版本、合并 SHA 与部署包 SHA256 以本轮发布验证记录为准。此文档不授权生产部署、重启或配置变更。

## 本轮交付

1. **binlog**：每十分钟限量处理，默认每批最多4个文件、512MiB；先验证 MySQL 事件校验和，再私有归档、完整读回SHA256比对，归档恢复清单。PURGE 前再次核验本地和远程字节、数据库UUID、连续前缀和复制连接。只通过MySQL PURGE删除已核验的关闭日志，保留最近两个关闭日志和活动日志，不直接unlink数据库文件。
2. **媒体缓存**：替换已停用的旧自动清理入口。只回收有完整OSS持久副本的本地复制品；不删除OSS原件、业务引用、任务记录、水印及尾图模板。新读写器以跨进程租约保护裁切、生成、预览和流式下载。临界区仅核对映射、文件及unlink，网络上传和读回在临界区之外完成。未升级的Node读者、活动媒体子进程、变更文件、无有效映射、校验/恢复清单失败均阻止删除。
3. **统一写入**：图片、视频及文件的内容寻址上传/复用/服务器复制共用完整读回校验；私有JSON与日志归档使用同一私有对象写入器。修复带首尾空白的data URI绕过。大JSON标准入口先接入库存需求读模型，256KiB以上只在DB保存企业范围引用；OSS故障不提交新引用。库存数量、成本、订单等原始事务记录不迁出MySQL。本轮不自动迁移其他历史大JSON。

缓存目标为1GiB（软目标），常规保留24小时；超过目标时可回收至少闲置1小时的已验证复制品。每批最多20个、128MiB，校验工作预算约15秒。活跃任务、容量不足或未验证文件可导致本轮无法降到目标，结果明确记录over_budget，不以删除不明数据强制达标。媒体任务及缓存下载预留3GiB空间；单进程最多同时恢复两个文件。恢复映射先私有归档，回收后仍按原路径从OSS校验恢复。访问标记随缓存回收，永久素材保留由另一套离线工具处理。

新入口默认关闭，受保护本地备份、swap和财务审计历史保持不变。没有新增运行依赖。高权限binlog进程使用从root拥有的发布压缩包提取的只读代码及现有root只读依赖缓存，避免执行应用用户可改写的脚本；媒体清理在取得发布锁后降权到ozon-erp运行。

## 必须列入批准的生产配置

- 确认当前MySQL无待追赶的离线副本/CDC；运行时检测到复制连接会拒绝PURGE。新增复制消费者前须停用自动清理并重新评估保留窗口。
- 首次启用前，建立一次全业务数据库的私有OSS一致性基线，记录源binlog位置/GTID并在隔离实例实际恢复核对。压缩SQL只使用受限临时空间，完成后不新增长期本地全库副本；现有受保护备份不动。将恢复验真清单的私有对象键设为`BINLOG_ARCHIVE_BASELINE_MANIFEST_KEY`。缺少验真基线或衔接日志已不在本地时拒绝首次激活PURGE；不能用旧本地备份文件存在替代此步骤。
- 绑定`BINLOG_ARCHIVE_EXPECTED_UUID`为本机已复核UUID。其他实例或重建后UUID变化会拒绝运行。
- 将MySQL的时间自动过期交接为“归档验证后清理”：明确批准后设置持久化`binlog_expire_logs_seconds=0`及`binlog_expire_logs_auto_purge=OFF`。归档服务不自行修改这些全局设置；未交接时拒绝执行PURGE。归档失败保留原日志、返回失败，不能用缩短保留期绕过。
- 首次发布保持`LARGE_OBJECT_STORAGE_ENABLED=0`，主备新读取器均ready且功能检查通过后，再启用大对象写入并滚动重启。媒体租约及验证上传开关同样只在批准范围内启用。
- 拟启用：`BINLOG_ARCHIVE_ENABLED=1`、`MEDIA_CACHE_LIFECYCLE_ENABLED=1`、`STORAGE_VERIFIED_WRITES_ENABLED=1`；协调目录固定为`/opt/ozon-erp/shared/storage-maintenance/media-leases`。其他预算值见env.example。

只读代码安装与两个timer的替换在新主备ready之后进行。不能仅凭timer active判定健康；须检查service的Result、last-result的completed_at、实际归档/清理数量与over_budget。连续失败、执行时间陈旧或剩余空间低于3GiB均需处置，不能补删未核验数据。日常空间快照继续使用既有storage collector。

## 验证与发布检查

- 本地独立MySQL禁用TCP：生成真实日志，实际PURGE旧日志，删除测试数据库，再从归档日志重放，完整核对中文长文本、更新/删除结果及二进制列。
- 两个独立读者进程共用真实MySQL协调锁：任何读者未退出时禁止回收；回收进程被杀后，新读者可自动恢复协调状态。
- 故障注入：错误SHA、公开ACL、归档中断、恢复映射失败、复制消费者、UUID变化、未归档日志缺失、磁盘预算和读写竞态均不能授权未验证删除。
- 默认/A/B企业的真实文件与ZIP权限测试，在新保护与上传验证开关打开时执行；外企业ID/路径不得读到私有媒体。
- 大JSON：旧格式读取、原文恢复、企业边界、失败保留上次成功、正文去重及回滚验证。只改变刷新时间时复用同一个OSS正文。
- 上线后先验证真实OSS私有写/读及媒体恢复，再启动小批回收。主备均复查预览、视频、ZIP和库存需求读模型，最后检查磁盘曲线与两个后台服务实际结果。

## 停用与回滚

先停止两个timer及正在执行的对应service，关闭四个写入开关并完成滚动重启；保留本版本读取器即可停止新行为，不必回退数据格式。若必须退到不支持OSS读模型的旧程序，先在批准的离线窗口停止主备及worker，`LARGE_OBJECT_STORAGE_ENABLED=0`后用以下显式工具逐企业恢复内联JSON：

```
node scripts/restore-demand-json.mjs --database=ozon_erp --socket=/var/run/mysqld/mysqld.sock --tenant=企业数字ID --write --offline-maintenance
```

工具先验证原文与企业范围、私有归档原引用，采用字节精确CAS恢复且保留calculated_at；有其他写者、源已变化或OSS校验失败就拒绝覆盖。不删除恢复对象。停用期间binlog仍增长，应保留已验证的手工归档通道并尽快恢复自动任务，不擅自改回按时间删除。binlog归档和永久媒体对象保留；不得通过RESET MASTER、rm binlog、清空历史表或删除受保护备份回退。

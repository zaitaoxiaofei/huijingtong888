## 已实现的修复

- 通知、首页、WB 刊登记录在页面隐藏或 KeepAlive 停用时暂停展示读取、取消在途 GET；恢复后补查。业务 POST 与服务器任务继续执行。主接口 401/403 后暂停，身份复核成功后恢复；首页可选面板自己的 403 仅暂停该资源，不能冻结合法首页。
- 全局更新检查也暂停隐藏轮询和重连；已有低流量 SSE 保留，权限失效后关闭。首次检查沿用延迟，恢复检查合并，旧请求不能重新安装重复定时器。插件身份检查的资源级拒绝不会不断重试。
- 通知抽屉关闭使用 `summaryOnly=1`，不读取正文；展开可用 `sinceRevision` 跳过不变正文。默认旧契约保持。每次仍验证当前企业成员与接收人，正文 revision 不缓存权限。
- 首页增加 `statusOnly=1` 与权限过滤后的 snapshot revision。轮询只传状态，变化后再读完整数据，保留构建过程逐段出现的指标。使用普通 200 JSON，不把客户端不能处理的 304 引入原契约。
- 公开、内容寻址的本桶图片可用 `/api/image-thumbnail` 派生列表 WebP；只接受固定尺寸，内网读取有字节、像素、时间、并发与缓存上限，并校验原图内容摘要。该路由保留会话、企业与订阅校验；拒绝响应 no-store，成功只缓存公开派生内容。私有对象、签名、外链和任意变换不进入凭证读取。失败可回原图，显式重试可绕过坏缓存。预览、保存、AI 与刊登继续原图。
- WB 列表沿用原 el-image、预览数组及 64×84 样式，只替换展示 src 并提供失败回退。共享商品组件沿用原有 63×84 全局样式。本轮涉及的 WB 视频播放器使用 `preload=none`，其 HLS 分片等用户播放后才开始加载。
- 在线商品、库存快照在原自然键的排他锁下比较 TEXT 字段，未变的 JSON 不再进入 UPDATE 赋值列表。所有观察时间保留原语义；库存确认零、前置删除、别名清理与人工 product_id 绑定保留。权限复核复用事务连接，并在行锁等待后才建立权限读取快照，防止连接池耗尽与旧权限快照。
- 订单原始物流合并继续在原事务锁下执行。数据无实质变化时仅刷新 fetched_at，不重复赋值大 JSON；变更、补充合并、跨店隔离、失败回滚及历史业务副作用保持。

财务统计刷新与同步新鲜度是业务契约。此轮选择锁内差异写入，没有为了减少日志取消观察时间、改变利润口径或删除业务历史。

## MySQL 配置待审批项

只读核实 ECS 为 MySQL `8.0.46-0ubuntu0.24.04.5`，`binlog_format=ROW`、`binlog_row_image=FULL`，未发现复制源/副本。另有一张历史一致性备份表没有主键，不修改它的结构或内容。NOBLOB 对定位记录仍需要的 TEXT 会保留完整字段，不等同于关闭日志。

独立本机 MySQL 8.4.9、禁用 TCP 的命名管道实例，使用原生 mysqldump 基线、mysqlbinlog 重放到另一库，验证未变观察、TEXT 变更、主键变化、NULL、新增、删除及无主键重复行。恢复结果逐字段相等。100 KB 订单样本中，FULL 观察更新约 200,655 字节，NOBLOB 约 442 字节；这只是合成样本，不是生产日节费预测，也不是生产 8.0 恢复演练。

MySQL 官方解释：[行镜像选项](https://dev.mysql.com/doc/refman/8.0/en/replication-options-binary-log.html)。仅更改格式但继续 SET 大字段为原值，仍可能写入大字段，因此必须与差异 SQL 配合。

工具 `scripts/audit-mysql-binlog-row-image.mjs` 严格只读，不含配置应用模式，不加载应用 .env。要求显式数据库、管理员本机 socket 与独立绝对报告路径：

```sh
node scripts/audit-mysql-binlog-row-image.mjs --database=ozon_erp --mysql-admin-socket=/var/run/mysqld/mysqld.sock --output=/private-review/binlog-row-image-before.json
```

审核身份、版本、格式、拓扑、历史备份表及现有恢复链后，需依 AGENTS.md 获得针对本轮代码发布及下列数据库配置的明确批准，才可执行：

```sql
SET PERSIST binlog_row_image = 'NOBLOB';
```

变更前保存原全局值与 persisted_variables 状态，变更后独立核验二者，并通过正常发布重建应用连接。已有连接不会自动继承新全局值；不需要重启 MySQL，不扩大应用数据库账号权限。发生回包丢失时先重新连接核查，不能当作未执行。回退需恢复原全局值及原持久状态，并重建受影响应用连接；若原来不存在持久覆盖，应 RESET PERSIST 后 SET GLOBAL FULL。配置变更和应用重启属于生产批准范围。

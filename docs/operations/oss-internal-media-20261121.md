# OSS 公网下载治理（2026-11-21）

## 目标与范围

保留每 10 分钟订单业务信息同步；订单主图缺失时按单手动补同步，沿用已发布的订单图片修复。本次补充处理服务器自身访问 OSS 和归档重复读回，不改变浏览器、Ozon 使用的公网图片 URL，不修改前端页面。

在线商品只由有权限的人工 POST 同步请求启动。构造路由、打开列表、读取状态、刷新查询和任务完成后轮询均不得启动同步；同企业正在执行的重复请求复用同一后台任务。关闭页面不等于取消已经人工启动的后台任务。该行为原已存在，本次增加实际路由和后台任务测试固定边界，不添加定时同步。

## 优先级与实现

1. **服务器正文读取使用内网。** 共享 `oss-client.js` 读取现有 `OSS_INTERNAL_READ`；值为 `true` 或 `1` 时 SDK 固定访问同地域内网 endpoint，网络失败不得偷偷切回公网。未设置或为 `false` 时仍支持本地环境的公网 SDK。覆盖媒体存储、缓存恢复、私有 JSON、发票、归档维护脚本和 AI/视频图片输入。
2. **同一次归档只完整验真一次。** 内容寻址写入完成完整 SHA-256/字节数读回校验后，可将原始结果在 60 秒内交给使用同一客户端的下一层归档一次。证明仅保存在进程 WeakMap 中；复制、序列化、改字段、换客户端或过期均不能代替验真。底层未开启验真时，归档层仍完整读回；私有 ACL 校验保持执行。
3. **先保存生成结果，再持久归档。** AI 工作流的生成适配器延后归档，由工作流保存生成结果检查点后统一归档，避免同一张图在适配器与工作流各归档一次。直接调用适配器仍保留原有默认持久化行为。
4. **合并并缩小缓存恢复。** 本地文件存在时直接复用；同一规范化路径的并发恢复共享一个下载。裁切工具按选中的输入文件或实际打包的目录恢复，避免先恢复整任务的其他批次。损坏或失败不登记成功，清理临时文件，后续请求可以重试。恢复后文件继续保留到现有缓存回收策略触发，不因再次预览重复下载。

本地缓存已经回收后，预览或打包必须从持久存储取回所需文件，这是保留磁盘空间与可恢复性的正常取舍。此时服务器应走内网。完整图片和打包原文件仍需要完整正文；不以跳过哈希、仅信任对象名或放宽回收保护来节省流量。本次不修改生产缓存配额、回收周期或 OSS 生命周期规则。

## 权限及公网访问边界

- 通用图片输入只允许本桶已知的公开内容寻址空间 `listing-media`、`product-media`、`collector-media`、`ai-unused`、`video-source` 使用 SDK。私有任务媒体、附件和未知本桶路径不得通过通用图片 URL 获得服务器读权限；仍由原公网读取边界决定 URL 是否可读，原有验证归属的文件路由保持不变。
- 非内容寻址旧链接、签名链接和图片变换参数继续使用原公网请求，避免丢失参数语义或破坏历史公开链接。这是预先确定的请求路径，不是内网失败后的公网回退。
- 外部图片保持原有 DNS、重定向、大小及权限检查。
- 用于证明 Ozon 可访问的公网图片检查、私有对象匿名访问拒绝检查仍有意使用公网，不能替换成有凭证的内网读取。
- 本次不关闭 OSS 公网访问，不改变对象公开/私有属性，不删除 OSS 对象或业务数据。

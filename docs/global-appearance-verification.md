# 全局主题与页面验收

全局外观支持亮色、暗夜两种模式，每种模式分别保存蓝、青、紫配色偏好。色板由 `frontend/admin/utils/theme-presets.js` 管理，`erp-theme.css` 提供页面、状态和控件的语义颜色；页面切换和传送到 body 的弹窗使用同一套变量。

## 配色约定

- 页面、卡片、次级区域、边框和正文使用 `--erp-*` 或对应的 `--erp-detail-*` 变量。详情变量在深浅两种模式均映射全局主题，不能只在暗夜模式生效。
- 主色实底必须搭配 `--erp-primary-fill` 与 `--erp-primary-contrast`。浅色提示底搭配对应的状态文字，不能直接拿装饰性的亮红、亮绿、亮黄当小字颜色。
- 图像画布、透明棋盘格、二维码白色底和视频黑底可保留用途明确的固定颜色；不能把这些例外扩散到表单、说明文字或操作栏。
- 外观修复不修改 API、人员权限、数据库、利润算法、AI 路由或任务执行。订单模块的样式还位于 `frontend/orders/`，不能只扫描 admin 目录。
- 页面标题说明的选择器不能影响其内部按钮文字。不要通过无范围的 `header span` 等选择器覆盖控件的文字与背景配对。

对现有路由进行六套配色的只读浏览器遍历；对有数据、无数据、二层弹窗和受保护操作使用隔离 API 夹具验证。正式回归 `test/theme-controls.browser.test.js` 使用真实 Element Plus 和源码样式，检查所有六套配色中的按钮普通/悬停/禁用状态、混合 ERP class、单选/复选/分段选项、下拉、日期/月选择、提示条、步骤、标签和空状态。启用文字按 4.5:1 检查；禁用控件保留禁用语义。

```powershell
$env:RUN_THEME_BROWSER_TESTS = '1'
node --test test/theme-controls.browser.test.js
npm run check:encoding
npm run check:frontend-safety
npm run build:frontend
```

本轮 Vue 脚本和模板与发布基线保持一致。组合商品弹窗单独做了最小 CSS 排版修复：长名称获得可用宽度，用量与库存分行，窄屏可滚动访问保存操作；已验证长名称、宽屏和 390px 窄屏。

订单普通单元格在深浅模式都显式绘制背景，避免 Chromium 连续切换主题后透明单元格保留旧的绘制内容。亏损行及其固定列、悬停状态使用同一套危险提示色；连续两轮亮暗切换同时检查计算样式和截图像素。

指定上架保护测试的四个旧结构断言、旧 AI proxy 工作台的六个源码断言，以及订单版本测试中缺少 `ensureOrdersViewScope` 依赖的两个旧提取夹具，已与未修改的 HEAD 对照确认同样失败，不计为本轮通过，不为消除失败而改动业务或断言。其余主题、标签页、快捷工具及本轮相关功能回归分别记录。

发布必须通过正常构建流程合并到最新 `release/*`，再使用仓库 ECS 发布脚本。生产验收核对实际 commit、分支、就绪状态、登录、订单 OGL 筛选、库存可用量和企业私信只读接口；检查账号、成员关系与订阅摘要保持一致。不在生产验收中向真实人员发送测试私信或执行 AI 生成。

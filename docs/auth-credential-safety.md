# 登录凭据、限流与盘点撤权

## 密码与手机记住登录

手机记住凭据保留 30 天，但只在当前密码版本仍匹配时有效。密码版本由服务端当前 `people.password_hash` 生成指纹，只存在服务端内存，不进入 cookie、用户 DTO 或接口结果。自助改密码、平台重设密码及企业人员允许的改密路径都会使旧版本失效，不依赖某一个密码入口额外清理手机 Map。

待桌面消费的已确认二维码也保存该版本。`GET /api/auth/qr/status` 消费前重新读取当前密码、账号和实际数据库会话；密码已变、账号停用、会话被撤销、企业成员关系或平台授权已失效时不返回旧 token，并删除待确认会话。消费成功使用当前角色与企业 DTO，不复用手机记住的历史授权。二维码仍只能消费一次，手机 cookie 不能通过请求体指定另一个账号或企业。

## 独立限流与可信代理

密码登录和二维码密码确认共用两个独立窗口：IP 桶和账号桶。已找到账号时按真实人员 ID 分桶，登录名大小写、数据库接受的其他等价写法不能另开账号桶。成功登录只清该账号的失败次数，IP 只退回本次成功请求预占的一次，其他失败保留；正常成功登录不会累计成失败封禁。预占退回必须匹配原窗口，不能减少较新窗口的请求。

`AUTH_RATE_LIMIT_MAX_ATTEMPTS` 默认 8，`AUTH_RATE_LIMIT_WINDOW_MINUTES` 默认 15。窗口仍由当前服务进程保存；重启或多实例部署需要另行规划共享限流存储，不能把进程内保护描述成分布式全局限流。

应用只信任 loopback 或 `AUTH_TRUSTED_PROXY_IPS` 中明确列出的代理 socket 地址，并只读取该代理覆盖的、格式合法的 `X-Real-IP`。不直接信任 `CF-Connecting-IP` 或客户端可保留的 `X-Forwarded-For` 首项。ECS nginx 使用 `proxy_set_header X-Real-IP $remote_addr`，与该默认配置兼容。增加 CDN 或多级代理时应先在可信入口正确解析真实地址，不能为了获取客户端 IP 而无条件信任公网请求头。

## 库存与采购台账

库存盘点入口只允许 `inventory.write`。采购台账要求 `procurement`，转换、替代、损耗、盘点及优先级等库存操作额外检查 `inventory.write`。这些权限来自当前企业的成员岗位，不以平台超级管理员身份替代企业成员关系。

台账在等待所有目标产品行锁后，通过 `FOR SHARE` 当前读取重新校验企业状态、订阅状态与期限、成员、登录身份和岗位。该读取不使用事务早期的重复读快照，授权共享锁保留到事务完成。撤权发生在产品锁等待期间时整笔台账回滚，不能留下流水、成本、库存余额或幂等操作记录；已经取得授权共享锁的操作与后续撤权按数据库锁顺序完成。

相关行为回归：`auth-rate-limit-boundaries.test.js`、`auth-remembered-credentials-mysql.test.js`、`tenant-procurement-ledger-revocation-mysql.test.js`。实际 SQL 测试只使用显式提供的隔离 MySQL socket 和随机数据库，不访问生产或外部服务。

# AI 裂变与批量刊登图片一致性

## AI 裂变草稿

AI 裂变保存会将目标变体的新主图同步到该变体富内容的首图、普通属性 `11254`、动态属性及字段别名。最终模板快照合并后再次同步，避免旧动态属性把母图带回。只修改目标变体，保留富内容的布局、文字、非主图以及其他变体；不重建人工富内容为系统默认布局，也不改变手动图片集合的权威规则。

## 批量素材清单

浏览器为每张水印结果附带原始 `source_url`，按草稿、店铺和图片序号保留顺序。后台使用处理时读取的草稿权威图片集合比较来源、数量和顺序。图片被增删、替换、重排，或者旧页面没有来源清单时，返回 `LISTING_PREPARED_MEDIA_CHANGED`，提示刷新草稿列表后重新准备；不能截取多出来的素材继续发布。相同源图被多个变体共享时按来源映射复用。

不同源图产生相同水印结果时，浏览器先清除当前草稿、店铺中受影响条目的指纹缓存，仅一次通过既有串行服务端水印通道重做原图。恢复后重新核对完整结果；仍相同则明确停止，提示检查原图内容是否重复。正常路径不会多发请求。后台仍独立校验并可返回 `LISTING_PREPARED_MEDIA_DUPLICATED`，最终同一 SKU 有重复 URL 时也阻断，包括服务端素材准备路径。浏览器缓存升级为 `v2`，避免继续复用旧错误产物。没有浏览器准备结果的请求继续使用服务端准备流程。

图片展示代理原先在上游失败时返回 HTTP 200 的 SVG 占位图；浏览器画布会把该图当作成功原图，多个失败图片叠加同一水印后可能产生相同内容地址。画布专用请求现在附带 `require_original=1`，包括已有的相对、同源代理 URL；上游失败、失败缓存和占位分支均返回非成功状态，触发原图服务端回退或明确失败，不能把占位图上传为商品素材。普通页面的图片展示仍保留占位行为。

## 发布前完整读取

发布时检查本次实际主图、详情图、受管理 OSS 素材及原有公开刊登素材，图片不能因旧预热数量上限而跳过。图片需要两次连续完整读取成功，任何一张失败均阻断整个 SKU；图片顺序与请求快照保持不变。带宽读取仍使用有大小、超时、公共 DNS 和逐次权限检查的安全媒体读取器；视频保留原有 HEAD/Range 语义。

## 已确认与未确认的边界

只读抽查发现过提交请求有 9 个图片条目但仅 5 个不同 URL、Ozon 实际返回 4 张的样本，也有 8 个不同 URL 完整保留为 8 张的样本。因此已经确认重复素材与预热漏选风险，但没有据此认定所有偶发缺图都来自同一个原因。历史发布不会自动重发；修改后的真实发布结果仍需正常业务操作验证。

回归包括 `listing-ai-fission-rich-content-sync.test.js`、`listing-batch-media-integrity.test.js`，以及既有实际 MySQL 批量发布、水印、企业发布和公共媒体安全测试。外部 Ozon、AI、OSS 写入均由替身承担，不使用真实发布作为自动测试。

# 共用库存履约入口（2026-10-29）

库存明细沿用原流程图与账本，新增采购申请节点、三类需求判断及明确操作入口。订单、商品库存、库存预警与采购工作台复用同一物理件数政策。大屏弹窗约80vw，小屏96vw，可展开为商品详情页面。

## 数量和业务边界

优先级为FBS真实订单、本地安全保障、已提交FBP备货申请。安全保障使用已有本地实际消耗计算器（日均消耗乘保障天数，向上取整），不含已出单数量。确认FBP占用只扣一次可用；发出才扣实物。在途不当现货，晚于交付时间的到货须人工核对。

真实订单缺口继续自动生成。安全保障与FBP备货机会仅为建议，人员明确提交后才有采购申请；草稿不产生正式采购需求。申请、实际采购、收货分开。来源人和来源订单保留，但不新增第四种采购类型。相同商品用途的多人提醒不累加成多倍缺口；实际订单与已提交FBP申请按真实需求汇总。

申请支持当前企业有效成员提交，管理员和采购岗位收到事务性通知；通知落库失败时申请一起回滚。重试沿用UUID，同一标识的变更内容拒绝。企业、岗位、订阅在写入前重新核实，库存缓存包含企业和商品，并在原库存分配失效链中一起失效。

## 收货和FBP

登记入库只列本企业已采购待收批次，不给仓库暴露金额；部分收货只增加合格件数，其余保持待处理。若已有盘点或历史出库，须填写当前实物总数，通过原收货与盘点事务校准，避免重复增加。仓库只获得限定的到货登记路径，不获得通用库存调整或财务权限。

FBP表单使用共用预测的分级、周期和建议，复用原备货写入；保存草稿不占用，提交进入待审核，仓库确认仍沿用原锁定/发运流程。原有批量备货、官方库存、标签、PDF导入、发仓核对与财务对账保留；专业工作台继续独立办理批量和历史任务，未删除数据或历史接口。

## 导航

左侧保留商品库存、收货入库、FBP、库存管理等父入口，各自的现有子页面以页面内横向Tab切换，保留旧URL与权限过滤。采购核对内含平台订单和支付对账。官方FBP库存默认只看有库存，支持切换断货和全部。

## 验证和发布

重点验证物理分配、未知数量、三类优先级、重复提交、通知回滚、企业隔离、岗位撤销、普通及历史部分收货，以及FBP草稿/提交不占库存。浏览器验证1920/1366深浅色、手机宽度、节点明细定位、多商品订单各自操作、本地数据先显示及异步FBP不关闭申请表。构建、编码、SQL参数、API文档同步纳入检查。

本地模拟和A/B测试不代表真实客户验收。发布只使用合并后release的精确提交和现有候选预热流程，不执行历史清理、不调整生产实物、不调用收费AI、不手动覆盖线上文件。

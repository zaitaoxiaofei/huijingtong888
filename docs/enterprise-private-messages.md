# 企业一对一私信

私信仅在当前企业的启用账号和启用成员之间使用。平台超级管理员必须有当前企业成员关系，且只能查看自己的会话；没有全平台聊天查看入口。每次查询和写入均从数据库重新检查企业状态、订阅和成员，不依赖旧会话中的岗位快照。

`enterprise_direct_messages` 是本功能唯一新增表。收件箱、双方游标查询及发送重试均有企业前缀索引。发送端为每条草稿生成并保留 `client_message_id`；网络失败后重用相同标识与内容，服务端返回同一消息。相同标识改发其他内容或其他收件人会返回 409。文本限 1 至 4000 字，不解释 HTML，不支持附件、群聊或后台代读。

发送事务按人员 ID 升序直接取得双方的排他锁，查询取得共享锁，保留至事务提交。因此同一会话不会出现高 ID 已提交、低 ID 尚未提交而增量游标永久越过消息的情况，也不通过先共享再升级来制造死锁。新增消息和已读时间显式使用 `UTC_TIMESTAMP(3)`，不依赖数据库会话时区。

接口契约由 `src/server/api-docs.js` 维护，生成到 [后端接口文档](BACKEND_API_REFERENCE.md)。读取最近一页、历史页和增量页都不会自动已读；客户端仅向 `read` 提交确已显示的收到消息 ID，不能用最大 ID 一次标记所有旧消息。使用轻量轮询；响应设置 `Cache-Control: no-store`，前端切换账号或企业时须关闭旧请求并清空会话与草稿视图。

订单引用按订单所属店铺限制企业，默认企业兼容旧 NULL 店铺归属。采购引用对应 `procurement_requests.id`，按需求自身和来源订单店铺校验企业；不把缺少归属的 `purchase_orders` 当作企业采购记录。标签和站内链接由服务端生成，忽略客户端传入的标签及网址。读取消息时重新检查引用权限和归属；无权访问时只显示“记录暂不可访问”。采购需求可以通过单条 `reference` 接口读取安全摘要，包括已完成需求，不依赖工作台待处理聚合。

## 数据库迁移与部署

应用账号不负责建表或修改 schema。先使用有目标数据库配置的工作区只读检查：

```sh
node scripts/migrate-enterprise-messages.mjs
```

应用模式必须显式指定本机管理员 socket；只创建本功能新表和索引，不修改现有业务表：

```sh
node scripts/migrate-enterprise-messages.mjs --apply --mysql-admin-socket=/var/run/mysqld/mysqld.sock
```

官方 ECS 发布流程已将此脚本加入常规数据库维护清单，在完整数据库备份成功后、候选启动前执行。若显式跳过数据库维护，须先确认表已经迁移；不能依靠应用启动补表。旧版本不使用此表，代码回滚保留已存消息。

迁移会检查 InnoDB、列类型及可空性、重试标识的二进制排序规则，以及索引唯一性和列顺序；同名但不兼容的表会拒绝应用，不静默修改或覆盖现有数据。

## 隔离验证

`test/enterprise-messages-mysql.test.js` 使用明确的 `TENANT_TEST_MYSQL_SOCKET`，只创建和删除自己随机命名的 `ozon_messages_test_*` 库；不读取应用业务库。覆盖双方及第三方、双企业账号、平台账号、成员停用、账号停用、企业停用、并发重试、游标、显式已读、跨企业及伪造引用，并以真实官方脚本验证管理员迁移可重复执行。未指定隔离实例时仅 MySQL 部分跳过，精确路由及授权测试仍运行。

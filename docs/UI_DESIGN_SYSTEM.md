# Ozon ERP UI Design System

产品和开发进度统一记录在 `docs/DEVELOPMENT_TRACKER.md`。本文件定义当前 Vue 管理端必须遵守的 UI 规范。

## 1. 当前前端栈

- 框架: Vue 3
- 组件库: Element Plus
- 构建工具: Vite
- 宿主页: `public/admin.html`
- 源码目录: `frontend/admin`
- 运行时产物目录: `public/vue-apps`

说明:

- 新系统不再维护旧版静态页面体系
- 新页面必须直接落在 Vue 管理端
- 公共布局、分页、表格、搜索区优先复用现有管理端组件和样式

## 2. 目标风格

- ERP 优先: 紧凑、稳定、可连续操作
- 统一优先: 相同类型页面使用相同的搜索区、表格区、分页区结构
- 粘性优先: 搜索区和关键工具条置顶，不因滚动丢失
- 数据优先: 不使用夸张总览卡、装饰型 hero、大面积无业务价值模块

## 3. 布局规则

- 页面主体使用卡片化分区，但避免层级过深
- 搜索区固定在页面顶部，和内容区分离
- 表格区单独滚动，不让分页被内容无限向下撑开
- 分页固定在表格区底部，样式与订单中心分页保持一致
- 弹窗头部固定，弹窗内容区滚动

## 4. 采购模块规则

- 采购中心页只承担“创建采购请求”和“请求列表管理”
- 不再保留采购总览页
- 采购页面顶部不展示采购汇总、待入库等概览块
- 非必要的旧采购表单字段不在采购请求页渲染
- 采购清单页面才承担汇总视角

## 5. 组件优先级

- 优先使用 Element Plus 原生组件
- 公共分页统一使用 [frontend/admin/components/PageFooterPagination.vue](/C:/Users/DIZAI/OneDrive/文档/ozon-erp/ozon-system/frontend/admin/components/PageFooterPagination.vue)
- 共享布局和全局色板统一来自 [frontend/admin/styles/index.css](/C:/Users/DIZAI/OneDrive/文档/ozon-erp/ozon-system/frontend/admin/styles/index.css)
- 页面级结构优先对齐订单中心、库存、采购当前实现

## 6. 视觉规则

- 主色使用当前管理端蓝色体系
- 背景跟随当前浅色或深色主题，保持低噪音
- 卡片圆角、边框、阴影使用统一系统值
- 不新增随机色、不引入旧页面残留配色
- 危险和警告只标记在标签、文字、边框上，不整块高饱和铺底

## 7. 开发规则

- 新页面放在 `frontend/admin/views`
- 共享组件放在 `frontend/admin/components`
- 不新增旧静态页面入口
- 不重新引入 iframe 挂载旧业务页
- 如果已有新页面能承接业务，不再保留旧页面并行实现

## 8. 验收重点

- 页面滚动时搜索区保持可见
- 分页始终位于可预期的底部区域
- 同类页面的筛选器、按钮、间距、分页交互一致
- 旧版利润页、异常页、采购旧页不在新系统出现

## 9. 深色主题

- 全局色板由 `frontend/admin/styles/erp-theme.css` 的主题变量维护，页面不能用固定白底或深灰字覆盖深色主题。
- 普通背景、浮层、文字、边框分别使用 `--erp-surface` / `--erp-surface-alt`、`--erp-text-*`、`--erp-border-*`；成功、警告和危险状态分别使用对应的 `--erp-*-bg` / `--erp-*-text` / `--erp-*-border`。
- 实色主按钮使用 `--erp-primary-fill` 与 `--erp-primary-contrast` 配对，避免只改背景或只改文字。禁用态、悬停、键盘焦点和选中态必须能辨认。
- 页面私有色板应映射共享变量；主要交互的强调色在亮色、暗夜两种模式都必须跟随全局方案。主题修复不改变布局尺寸、业务行为或接口。
- 下拉菜单、日期选择器、弹窗等传送到 `body` 的浮层也必须跟随主题，不能仅依赖页面容器内的变量。
- 验收需实际切换浅色 → 深色 → 浅色，并检查跨页导航、状态标签、按钮、输入框及浮层。抽查普通文字对比度至少 4.5:1，不能只检查页面背景。

## 10. 外观与全局快捷工具

- 右上角“外观设置”分别提供亮色、暗夜模式，每种模式可选择蓝、青、紫三套配色；每种模式独立记忆方案，浏览器重新打开后恢复。预设位于 `frontend/admin/utils/theme-presets.js`，通过共享 ERP / Element Plus 变量应用到全站及浮层。
- 本地外观配置只保存显示偏好，不保存账号、企业业务数据或计算表单；无效或不可用的浏览器存储不能阻止界面打开。
- 密度、下载、通知、外观以及利润计算器、定价工具统一使用图标入口，并保留提示和可访问名称。桌面、手机均需验证顶栏不溢出。
- 两个快捷计算器复用原页面的组件和计算逻辑，按原页面权限显示。首次打开时加载，弹窗内部滚动，支持叉号和 ESC；有嵌套浮层时先关闭最上层。
- 关闭弹窗或切换工具可以保留当前登录上下文中的输入；账号、企业、权限或会话范围变化时必须关闭并卸载缓存，包括用户对象未改变的纯 token 变化。
- 侧栏和登录页共享 `BrandLogo.vue` 的“爆单 ERP”标识，折叠侧栏只显示图标，不再使用多层描边和错位贴纸字样。

主题结构参考 [Ant Design 全局主题设计](https://ant.design/docs/react/customize-theme/)、[深色模式规范](https://ant.design/docs/spec/dark/)和 [Element Plus 主题变量](https://element-plus.org/en-US/guide/theming)。本项目继续使用现有 Vue / Element Plus 前端。

## 11. 工作区、快捷计算与私信

- KeepAlive 缓存键必须由当前已确认的路由产生，不能使用提前切换的标签选中状态；关闭标签不应把离开的组件存进另一个页面的缓存，也不应靠强制刷新清空用户表单。
- 简易计算器位于利润/定价工具左侧，支持键盘输入、括号、百分比和四则运算，使用受限解析器，不执行表达式代码。与其他快捷工具一致按账号/企业范围清空，仅保留当前会话中的输入。
- 企业私信入口放在通知旁；未读数与系统通知分别统计。对话限当前企业有效成员之间的一对一纯文本消息，草稿不写浏览器持久存储；切换账号、企业或 token 范围后关闭浮层并清空旧状态。
- 发送失败保留输入和重试标识；已读只提交实际渲染的收到消息 ID。引用标签、权限及链接以服务器为准，订单进入原详情，采购需求通过只读详情查看，包括已完成或取消的需求。内容用文本渲染，不执行 HTML。
- 任务矩阵、详情卡、嵌套弹窗、日历和选择器继续使用全局主题变量；深色细节变量不能依赖未传送的页面祖先。验收保留亮色原布局并实际检查深色蓝/紫主题及移动端工具入口。

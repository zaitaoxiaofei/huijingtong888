# 采购开票助手 · 拼多多 v0.1.1

供 Chrome 120 及以上版本使用的本地浏览器扩展，支持三个采购账号的订单分组、企业普通发票申请、状态刷新、票据下载和 CSV 台账。

## 安装

1. 将 `pdd-invoice-assistant-0.1.1.zip` 解压到固定位置，之后不要删除或移动文件夹。
2. 在 Chrome 地址栏输入 `chrome://extensions`，打开右上角「开发者模式」。
3. 点击「加载已解压的扩展程序」，选择直接包含 `manifest.json` 的文件夹。
4. 将「采购开票助手 · 拼多多」固定到工具栏，点击图标打开工作台。

标题与已读取、待申请、待核对统计在顶部同一行显示，记录区独立滚动。右上角设置按钮管理发票抬头和读取配置，时间、汇总和导出分别收在顶部菜单中。

这不是 Chrome 应用商店发布版本，不要把 ZIP 直接拖到浏览器安装。

## 开始处理

1. 点击「打开拼多多订单」，手动扫码登录自己的采购账号。
2. 返回助手，点击「绑定当前登录账号」，填写账号备注并确认身份。
3. 填写完整公司名称和纳税人识别号，保存抬头。收票邮箱是备查信息；平台表单没有邮箱字段时，不会随申请提交。
4. 刷新页面列表，选择拼多多订单页，点击「读取订单」。勾选滚动读取可加载更多订单；一次最多滚动 18 次，再次点击可继续读取。读取范围以平台实际加载的数据为准，不代表所有历史订单已经齐全。
5. 按日期、店铺、商品或订单号筛选，选择订单，点击「批量申请发票」。核对账号、公司名称和税号后确认开始。
6. 在任务卡片查看进度。申请后由商家开具，可稍后选择订单点击「刷新开票状态」。
7. 对已开票订单选择「下载已开票票据」，文件保存在 Chrome 下载目录的 `采购发票/账号备注/` 下。台账可导出 CSV，Excel/WPS 可打开。

## 两到三个账号如何使用

同一 Chrome 用户配置内，拼多多只有一套当前登录状态。助手的账号卡片用于分别保存订单、抬头和任务，不会复制 Cookie 或自动替你切换账号。

- 顺序处理：结束或暂停并结束当前批次，在拼多多页面手动退出并登录另一个账号，再绑定或重新绑定对应账号卡片。
- 重新登录后，登录指纹可能变化。插件会暂停处理，需要核对身份后重新绑定。若旧批次仍有待处理订单，先结束旧批次，再重新绑定。
- 如要三个账号保持同时登录，可用 Chrome 的三个独立用户配置，分别安装本插件。各配置的数据彼此独立。

## 结果和异常

- 待发货、待付款、退款及关闭等订单会在读取时跳过；已申请、已开票或待核对订单不会自动重复申请。
- 插件通过官方页面的实际订单号、加载状态、抬头字段、提交确认和申请状态来核对结果。没有明确结果时暂停并标为「待核对」，不会反复点击。
- 点击「查看处理窗口」或订单行的「发票详情」，核对平台结果，再点击「编辑台账 / 历史」保存实际状态。只有确定未申请时才恢复为「待申请」。
- 暂停阻止后续提交；已被平台接受的申请不会撤销。当前步骤结束后可继续或结束本批。发生验证码、登录变化、页面不兼容或访问限制时需人工处理。
- 关闭工作台后可继续处理，但 Chrome 必须运行。浏览器重启或后台中断后任务会暂停；中断时正在处理的订单标为「待核对」，需要核对后再继续。
- 失败订单也需先人工核对状态，再决定是否恢复为待申请。未确认的申请不会自动重试。

## PDF 原件与发票图片

当前验证的官方发票详情页展示 PNG 图片，并通过「发送至邮箱」提供 PDF 原件。本版可保存平台提供的直接文件链接和发票图片，图片文件名带「平台图片」，不把图片或网页截图冒充 PDF 原件。

需要 PDF 原件时，在订单行打开「发票详情」，使用拼多多页面的「发送至邮箱」领取。本版不自动发送邮件。只有按钮、临时 blob 文件或未知格式的入口保留为人工处理，不猜测下载地址。

下载记录以 Chrome 的实际完成/中断事件为准。已有下载记录不会自动重复下载；如下载被浏览器拦截或中断，请打开 Chrome 下载页面处理。

## 数据与权限

所有订单、抬头、任务和下载记录保存在本机 Chrome 存储。没有自建服务器、订阅、统计脚本或第三方数据上传。订单号按字符串保存，CSV 中防止长数字截断和公式执行。

- `storage`：本地保存账号分组、抬头和任务。
- `unlimitedStorage`：支持长期积累采购台账和变更历史，避免默认存储额度影响记录保存。
- `tabs`：打开、读取和复用拼多多处理窗口。
- `cookies`：只读取当前拼多多登录标记以计算 SHA-256 指纹，检测切号或退出。不保存明文 Cookie、不写入 Cookie、不收集支付密码。
- `scripting`：在拼多多页面读取已加载组件中经过白名单筛选的订单、发票状态字段，不调用内部业务接口或组件方法。
- `downloads`：将平台票据保存到 Chrome 下载目录并跟踪完成状态。
- `alarms`：检查后台任务是否需要恢复。

页面权限仅限 `https://mobile.pinduoduo.com/`。清除扩展数据、移除扩展或删除 Chrome 用户配置会丢失本地记录，请先导出台账。卸载不会删除已经下载的发票文件。

## 当前验证范围

当前为本地试用功能，已在用户登录的真实页面验证订单读取、日期/实付金额、官方发票详情与申请表单字段。批量队列、二次确认、重复提交和账号隔离由自动测试与隔离页面验证。开发验证未向商家提交真实申请，未发送邮件；真实申请与下载仍需安装后先用少量订单验收。

平台页面变化可能需要更新适配。无入口、专用发票、红冲重开、政府补贴身份资料、人工客服沟通等情况交由人工处理。本扩展为独立自用工具，与拼多多及「多多开」等第三方产品没有隶属关系。

## 发票台账、日期与金额汇总

- 点击「同步已有发票台账」，读取当前账号官方列表中的已申请、开票成功和开票失败记录及平台金额。再选择记录点击「刷新开票状态」，补齐申请日期、开票日期和失败原因。
- 台账可按状态、账号、店铺、商品、订单号筛选，并可切换申请时间、开票时间、下单日期三个时间口径。所选时间缺失的订单不参与日期筛选，并单独提示。
- 「全部账号汇总」可合计这台浏览器中保存的三个账号并导出。该视图不执行批量申请，处理任务需回到对应账号且登录匹配。
- 成功票面金额、申请中订单金额、失败申请金额分列显示，不将失败金额算入成功开票。金额按整数分计算。成功发票票面金额缺失时留空并提示，不用采购订单金额替代。申请中和失败金额优先使用平台申请金额，没有时按订单实付金额统计。
- 官方发票列表的金额是元字符串，采购订单组件的实付金额是分，两种来源分别转换。平台仅提供日期时保留日期，不推造时分秒；可在「编辑台账」中按原件核对补充。
- 可再次编辑状态、申请时间、开票时间、票面金额、发票号码、开票失败原因与备注。平台刷新、申请结果和人工修改都会保留变更历史；金额或状态修正后，筛选汇总即时更新。
- 可分别导出明细 CSV、汇总 CSV、变更记录 CSV，便于 Excel/WPS 对账和二次分析。明细保留原始空值，汇总明确给出金额缺失未计入的订单数量。

开发时已只读参考用户提供的 `duoduokai-offline-v4.5.6.zip` 的状态判定和队列思路。未运行该安装包、未复制其中账号或服务端配置，未把其程序打包到本插件。

## 分页与工作区

默认每页 50 条，可选 20/50/100 条。顶部工具栏、上下分页固定在可视区域，中间表格独立滚动，表头固定。上下的每页条数、页码和翻页按钮同步，切换分页后返回表格顶部，状态刷新不打断当前滚动位置。汇总、全选和导出仍包含全部筛选结果，不只限当前页。

## 0.2.0 / 统一插件 1.5.12

- 主入口「同步采购订单」支持按下单日期范围和全部历史；先读取订单补齐日期、实付和图片，再进入官方待申请列表的「选择订单并联系商家」弹层，持续滚动加载。每批读取即时保存，支持停止；重新同步会按订单号去重合并。
- 官方发票弹层目前提示仅展示近 6 个月，插件明确显示此限制。全部历史表示尝试读取平台可加载的所有记录，不承诺平台未提供的历史。达到时间上限、加载停滞或验证限制时不会冒称全部完成。
- 平台没有提供下单日期的记录保留供核对并单独提示，不伪造日期；日期范围读取不会删除此前已同步的其他记录。表格日期筛选用于查看当前范围。
- 待申请卡片保存官方商家申请链接、商品缩略图与申请金额。批量申请会展示抬头、数量和已知金额，经确认后逐单核对身份与抬头再发送；无法确认结果时暂停，禁止自动重复提交。
- 「更新开票进度」优先处理勾选记录，无勾选时更新已申请等记录；空台账先同步官方开票记录。异常显示具体原因，可单独重试读取状态。
- 界面改为白底深色文字、蓝色操作，默认 50 条，固定上下分页。查看发票进入官方详情，图片预览不能当作官方 PDF 原件。

## 0.2.1 / 统一插件 1.5.14

采购历史使用官方采购列表的只读游标分页，不限制年份，不受发票助手近六个月展示范围影响。空列表才确认读完；游标停滞、登录过期、网络失败均保留已读记录并明确提示。账号设置显示数量、实际最早日期和完成状态。

真实商家申请会跳转至聊天页并销毁原页面回执。提交已获授权但消息通道中断时，仅打开发票详情只读核对状态，确认已申请后继续队列；无法确认则暂停，不重复发送。

本版保留 1.5.13 的 Ozon 财务原件同步入系统功能。
